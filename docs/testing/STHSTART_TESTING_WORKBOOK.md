# 在 SthStart 里学测试：先试一件事

假设你写了一章小说。有人读完后，建议把结尾改成“午夜出发”。你还没接受这个建议，自己先把结尾改成了“天亮再出发”，并保存了。

**这时，如果你去接受那份旧建议，刚保存的“天亮再出发”会不会被覆盖？**

你今天就写一条测试来回答这个问题。先用 Python 直接请求项目后端，相当于把页面上的“保存”和“接受”交给代码去做。暂时不用打开浏览器，也不用调用 AI。

## 第一步：打开你已经写过的测试

在 VS Code 打开 [test_story_proposals.py](../../tests/python/story/test_story_proposals.py)，找到 `test_story_proposals`。先看这段代码里三件事怎么做：

1. **建章节**：创建成功后，从返回的数据里拿到章节 ID 和版本号。
2. **提建议**：拿这个章节 ID 和版本号创建一份建议。项目代码把建议叫作 `proposal`。
3. **接受建议**：拿建议自己的 ID，发送 `{"decision": "accepted"}`。

不用一口气读懂整个文件。找到这三段，就有了新测试需要的大部分写法。你已有的 [直接保存冲突测试](../../tests/python/story/test_story_api.py) 里，`test_story_revision_conflict` 展示了怎么保存正文，以及怎么保存之后重新读取。

## 第二步：先写下这次要做的事

在原文件里新增一个测试函数，原来的测试先留着。让新函数按下面的顺序做：

| 顺序 | 做什么 | 看到什么才能往下走 |
| --- | --- | --- |
| 1 | 建一章，写“等钟响再出发” | 建成了，记下章节 ID 和版本号 |
| 2 | 建一份建议，写“午夜出发” | 建成了，记下建议 ID；它还在等作者决定 |
| 3 | 作者自己保存“天亮再出发” | 保存成功，记下新的版本号 |
| 4 | 尝试接受第 2 步的旧建议 | 后端拒绝，说明建议已经过期 |
| 5 | 重新读取章节和那份建议 | 正文仍是“天亮再出发”，建议仍在等作者决定 |

第 2 步一定要在第 3 步之前。我们想测的是**本来有效的建议，后来变旧了**。反过来做，建议可能在创建时就被拒绝，根本没有测到“接受旧建议”。

为什么还要做第 5 步？因为后端说“我拒绝了”，和它确实没把正文改掉，是两回事。你要再读一次，亲眼核对保存下来的结果。也不要把三份正文都写成同一句话，否则写错了可能也看不出来。

## 第三步：分两次写代码

**第一次只写到创建建议。** 参考你现有代码，创建项目、章节、会话和建议。这里的“会话”只是这个接口要求关联的一条记录，建它不用发聊天消息。检查建议确实建成，而且是 `pending`，意思是还没决定。先跑一次，确认前半段没写错。

**第二次再写作者保存、尝试接受和重新读取。** 先检查作者保存成功；保存没成功，建议就还没变旧。最后检查三件事：

- 接受旧建议返回 `409`，错误字段是 `story_proposal_stale`。这表示拒绝的原因是建议过期。
- 重新读取章节，正文仍是“天亮再出发”，版本号仍是作者保存后的那个。
- 重新读取建议，找到刚才那份，状态仍是 `pending`。

| --- | --- | --- |

| 接受建议 | POST `/proposals/{建议ID}/decision` | `{"decision": "accepted"}` |
| 重新查看 | GET `/documents` 和 GET `/proposals` | 从各自的 `items` 里按 ID 找到目标 |

版本号（`revision`）可以理解为“这是正文的第几版”。`baseRevision` 记录建议是看着哪一版写的；`expectedRevision` 告诉后端，作者这次要改的是哪一版。这两处都用创建章节时实际拿到的版本号，不写死为 1。作者保存以后，旧建议里的版本号不要跟着改。

## 这件事做完以后

你已经练到了一个通用方法：**先把事情按顺序发生，再到系统里核对结果。** 后面还是用这一章正文，每次只多学一件事：

1. **浏览器**：真正在页面输入、保存、刷新。学怎么找到输入框，怎么知道“这一次”已经保存完。
2. **失败处理**：让页面收到一次保存失败。看看没保存的字还在不在，服务器上的旧正文有没有被改。
3. **MCP**：让外部工具读到同一章，再交一份建议。检查工具只提交了建议，正文仍要等作者同意才变。
4. **Skill**：给模型相同的故事资料，分别有、没有写作指导，看看它找出的矛盾有没有证据。

接口和环境的完整说明见 [Story 实战指南](STORY_VERTICAL_TESTING_GUIDE.md)。想查“为什么这样测”，看 [软件测试基础](SOFTWARE_TESTING_FOUNDATIONS.md)；卡在语法，查 [Python 教材](TESTING_FOUNDATIONS.md)。
