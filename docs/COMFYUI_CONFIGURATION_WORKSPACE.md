# ComfyUI 配置工作台使用说明

本文对应 2026-09-13《ComfyUI 配置工作台改造》计划的落地实现，说明从导入到生成的完整操作路径，以及每个能力背后的执行语义。

入口：`/settings/generation`（生成配置工作台），共三个标签：**工作流**、**连接**、**预设与用途**。

## 1. 连接

- 新建连接默认方式为 **ComfyUI 直连**（浏览器 → SthStart Service → Windows 上的 ComfyUI）；已有 Windows Worker 连接继续可用，配置归入连接编辑器的高级区。
- 普通用户只需填名称与地址；「内部 ID」自动生成（高级区可自定义）。可选凭据写入系统凭据库，编辑留空表示保持原值。
- **测试连接**由后端发起：ComfyUI 走 `/system_stats`（404 时回退探测根路径），Worker 走 `/health`。连接成功只代表可达，不代表所有工作流可运行。
- **模型/节点发现**为只读接口：ComfyUI 直连读取 `/object_info` 的加载节点枚举；Worker 走受鉴权的 `/v1/worker/discovery/*`。结果有 60 秒内存缓存，手动「刷新库存」绕过缓存；失败时保留最后成功结果并标记「可能过期」。旧版 Worker 不支持时会明确提示升级，不伪造空列表。
- 删除连接时若仍被预设引用会被拒绝，需要先处理这些预设；历史版本中的引擎引用随删除脱钩，任务数据不受影响。
- 部署边界：Service 与 ComfyUI 不同机时，地址必须从后端所在机器可达；Docker 部署中 `127.0.0.1` 不是宿主。Service 不会修改防火墙或跨域配置。

## 2. 工作流工作区

布局：≥1440px 三栏（列表 / 编辑区 / 试运行）；1024–1439px 试运行走抽屉；<1024px 单列。

### 2.1 导入

1. 点击「导入」，粘贴或选择 JSON 文件。支持两种格式：
   - **原生 ComfyUI API JSON**（节点 ID 为对象键）：先分析，再确认字段与连接；
   - **本项目配置包**（`sthstart-generation-config@1`）：恢复定义、映射与编辑器配置，连接引用需重新确认。
   - 含 `nodes` 数组的画布 GUI 导出会被明确拒绝，不做未经验证的自动转换。
2. 分析结果列出候选输入：已知节点（KSampler、CheckpointLoaderSimple、CLIPTextEncode、EmptyLatentImage、LoraLoader 等）给出语义猜测；未知节点只作为技术字段展示，确认后才映射为业务字段。连线数组永远不会变成参数。
3. 工作流 ID 由系统生成；同名可改用「复制为新工作流」。导入先创建工作流外壳与草稿，**只有保存版本后才可试运行或建预设**。

### 2.2 编辑（四个页签）

- **模型**：主模型/组件模型的默认值来自目标连接的真实库存；「允许选择的模型」由配置者圈定（默认仅允许导入图中原有模型）。多组件工作流建议「通过预设成套切换」。LoRA 槽位来自工作流已有加载节点，不动态插入。
- **参数**：显示名称、常用/高级/固定层级、排序、默认值、min/max/step 与枚举。默认值与范围唯一存于 inputSchema；界面配置只引用字段键。未映射的节点输入保留在高级区，可确认后映射，不会通过可视化保存丢失。
- **输入与输出**：媒体槽位（MIME、必填、语义）与节点绑定；输出节点候选与输出 MIME。
- **高级**：API JSON、节点绑定、复制工作流、导出配置包。

### 2.3 草稿与版本

- 草稿自动保存（约 1 秒防抖），带 `revision` 乐观锁；其他窗口修改后保存会返回 409 并给出服务端草稿，可选择「采用服务器草稿」或「以我的内容覆盖」，绝不静默覆盖。
- **保存版本**把当前草稿固化为不可变的新版本（含编辑器配置时记为 V2）；旧配置保持 V1 投影，首次在编辑器保存后升级为 V2。
- 保存版本不会自动开放到创作中心；业务开放由预设/用途绑定控制。

## 3. 试运行

右侧「试运行」面板（窄屏经抽屉打开）：

1. 填写提示词与所需媒体（媒体仍走系统上传链路，客户端只提交引用 ID）。
2. **保存并试生成**：草稿有变化时先保存版本，再创建真实任务；内容未变化时复用已对应版本。
3. 任务复用既有队列、快照与媒体仓库，归属 `creative-center` 的固定 `configuration-test` 用途。页面关闭不会取消后端任务，重新打开可从「历史测试」找回。
4. 结果展示真实工作流版本、实际 seed、耗时与「实际使用参数」（来自任务快照，不从表单推算）；支持下载产物与**另存为预设**。连接失败、参数非法都会如实显示，不伪造成功。
5. 暂不支持远端取消的连接明确显示「停止跟踪」语义（Worker 任务远端可能仍在运行）。

## 4. 预设与用途

- 预设 = 确切工作流版本 + 连接 + 一组覆盖值 + 开放用途；不复制工作流定义或模型库存。支持新建、编辑（`revision` 校验）、复制、禁用、删除与**设为默认**。
- 「设为默认」在同一事务里同步用途绑定与 `default_preset_id`；编辑默认预设的工作流/连接引用需显式确认（`clearDefault`），确认后服务端同步用途绑定，避免两种客户端执行出不同结果。
- 显式选择非默认预设不会修改全站默认；切换预设只替换它明确包含的值，会覆盖已编辑值时创作中心先展示差异并确认。
- 预设引用固定版本，不自动追随 latest；工作流出新版本时用「复制预设」指定新版本。

## 5. 创作中心

- 第一行为**工作流选择 → 预设选择**，来源是「至少有一个对当前用途启用的预设」的工作流；没有预设的旧配置继续使用固定表单与用途绑定。
- 模型仅在配置允许单独调整且有库存缓存时显示下拉框，否则显示「模型组合」摘要（随预设成套切换）。
- 表单字段、默认值与范围来自服务端契约（`/api/v1/admin/creative/options`），客户端不自行决定可编辑字段。
- 提交带 `presetId / presetRevision / parameters`；服务端验证预设归属、启用状态、版本与连接后解析内部工作流，最终参数优先级为：**工作流默认 → 预设 → 本次输入**，随后统一校验（未知参数、固定字段覆盖、越界、非有限数字都会被拒绝，不做静默钳制）。
- 请求哈希覆盖预设/连接/合并值：同一幂等键但配置变化会返回 409 冲突，需重新确认。

## 6. 兼容性

- 旧客户端不传 `presetId` 时沿用既有用途绑定；若该用途设置了默认预设，其模型选择与参数会参与合并（客户端显式发送的字段仍然优先）。
- 活动配图、角色头像等消费者继续走各自应用/用途的绑定与默认预设；参数校验位于共享生成入口，无法绕过。
- 旧版 Worker 保持可用；发现功能缺失时界面明确降级提示。
