# 故事世界架构标准

版本：1.5（2026-11-15）。适用于故事世界、公共图片队列及其与写作项目的集成。

本文件是后续开发与审查标准。[产品计划](STORY_WORLDS_PLAN.md)定义范围，[实施记录](STORY_WORLDS_IMPLEMENTATION.md)保留协作接口，[验收记录](reviews/2026-11-11-story-worlds-delivery.md)记录实际证据。标准存在不代表功能已完成验收；当前仍在集成验收中。

## 2. 数据语义与历史

- 时间 tick 是从世界起点计算的非负整数分钟；显示标签与实际数值分离。
- 可选startMinuteOfDay是世界起点的日内分钟（0–1439）。个人上下文只接收由它和tick计算的day/minuteOfDay，不接收自由timeLabel；未定义时不能猜测昼夜。
- 分支 mode 的实际枚举为 canon-gap、adaptation、alternate，分别显示原作留白、原作改编、平行世界。原作留白仍是同人创作。
- 来源 nature 为 canon、author、ai、unverified，保存引用、版本、采集时间和内容快照。内容缺口必须显示，不能将 AI 输出标为官方证据。
- 角色基础资料与分支当前状态分离；加入世界不会覆盖全局角色卡。提升主角、加入角色库必须是明确操作。
- 事件只保存一份事实，多人物视角和故事线引用同一事件。布局坐标不得改变事件时间。
- 更新世界资料不会静默改写分支；显式刷新来源会增加分支定义历史。从历史时刻分叉，只继承当时已经结束（tick + duration <= forkTick）的完整事件及其记忆和状态。事件是原子结果；分叉落在持续事件中间时不复制该事件的最终结果。图片任务和采纳记录不复制到新分支。
- 配图以 definitionAtTick 读取历史定义，禁止 images 服务绕开 Store 自行拼装历史 SQL。

持久化使用 ServiceDatabase 和既有迁移器。迁移55新增故事世界与图片队列；迁移56新增待通知步骤的部分索引；迁移57新增人物计划、每步意图和个人记忆摘要表。已经应用的迁移不可重写。

迁移62新增 `sw_world_setups`，保存仅有名称或部分设定的待配置世界；待配置记录不进入 `sw_worlds` 或运行接口。创建请求通过 `creation_key` 幂等，部分保存使用 `revision` 比较交换。完成配置在同一事务内保留原 ID 写入主定义、建立初始分支并标记已完成；分支写入失败时全部回滚。精确重放完成请求返回原世界和原分支。完成记录保留哈希与分支 ID 用于重试，不再保存一份完整草稿。

### 独立配置与候选写入

- `/apps/story-worlds/new`、`/apps/story-worlds/:worldId/edit` 是自然滚动的普通配置页，不使用工作台锁高。日常为世界简介、登场人物、开场地点与故事方向；详细人物档案、时间、视觉参考与运行模型按需展开。
- `POST /story-worlds/create-bundle` 以同一个事务创建世界、名为“主线”的初始根分支与人物状态。主线不是 `sw_story_lines` 或项目大纲，创建后不自动运行。迁移 59 保存幂等请求；同一键同一内容重放，不重复创建。
- 世界公共设定和分支方向分别写入。`PUT /story-worlds/:worldId/branches/:branchId` 要求独立修订基准，活动运行拒绝方向更新。世界公共设定仍通过比较、确认后显式刷新到分支。
- 本机编辑信封沿用 `sthstart:story-worlds:draft:create`、`edit:<worldId>`。世界/分支基准与内容独立，后台刷新和切分支不抬高脏草稿的世界基准；无基准的旧草稿必须比较后确认。切走的分支字段按分支保留。提交标识在请求前同步落盘，成功与部分保存只清理实际保存的一侧。
- `POST /story-worlds/suggestions` 允许创建前调用，使用 `story-worlds / authoring` 模型用途，未单独绑定时继承应用文本模型。沿用 AI 调用审计，不创建运行任务，不自动重试付费调用。
- 生成时冻结草稿与来源快照，候选默认不选。只有明确采纳才写草稿，保存另行确认。旧候选的目标或来源变化后重新核对，确认凭据绑定具体字段与来源值；AI 不能替换角色库身份或媒体引用。撤销只回退仍等于 AI 写入值的字段。
- Tavily 搜索只发送用户编辑的关键词，默认 basic、最多 10 条、关闭综合答案。勾选后再 Extract，读取成功和失败清单；摘要、失败、截断与待核实性质保留在快照中。公共资料库另存是独立动作，搜索不会自动入库。密钥由既有凭据库或环境变量提供，仅服务端读取。
- 采纳独立分页分支事件，每页 200、可继续读取全部历史，每次最多 100 个事件；不能复用画布的时间窗与人物筛选。预览与服务端按同一规则限制标题 120、正文 100000，超长拒绝而不截断。采纳标识跨刷新与修订重试保持稳定，成功后主动新采纳才换标识。
- 项目绑定带 `expectedBinding` 做事务比较；旧调用可绑定空项目或同分支，不可无确认覆盖不同分支。绑定时修订不等于分支当前修订。项目、章节编辑、制作和图片引用入口保留明确操作。

## 3. 模拟、事实与个人知识

一次步骤的实际顺序如下。叙事完成前不发布半成品事件。

取得步骤租约并固定输入快照
	→ 各人物提出个人意图
	→ 环境裁定事件、转述、状态及配角
	→ 程序校验并执行一致性审查
	→ 按人物已知事实生成正文并审查
	→ 原子提交事件、记忆、状态、时间、运行进度
	→ 提交后通知配图服务

个人行动输入只包含当时可知的资料。环境裁定可以看全局；个人正文只能看到属于该人物的事实。事实 knownBy 是知识约束，participantIds 不是“知道现场所有秘密”的授权。

记忆 kind 实际枚举为 experienced、heard、inferred、mistaken。每条保留 sourceEventId、learnedAt、fromActorId；听说需有可追溯的传播事件。未知事实、未来事实、跨分支信息及无来源关系变化必须被拒绝。重复出现的精确同文事实不能把人物更早已知的记忆误判为未来泄漏；这不允许新增或扩写秘密。

正文不得增加影响后续的事实。程序校验事实引用、时序、位置、前提与来源，模型辅助审查动机与原作一致性；后者不是绝对正确性保证。每阶段最多一次输出修正，修正同样计入调用额度。

事件裁定审查保留全局原作、导演约束和锁定事实；个人叙事审查仅接收与正文作者相同的本人资料、ownIntent及显式摘取的事件id/tick/locationId/knownBy事实，不接收全局概要、其他人物状态/正文、来源或导演私有方向。裁定通过的事实是叙事依据，不能在审查意见中为人物补足未知信息。审查拒绝时把该个人范围内的具体issues带回唯一修正，最多8项/6000字符，原输入和审计保留。复用旧运行前按持久化JSON比较实际审查输入与当前个人输入；旧全局或不同范围意见只返回通用理由，不转述未知细节，不重置修正次数或新增派发。程序校验结构与事实引用，语义仍需模型及实际阅读核对。

日常行动应允许人物在已知情境内合理主动推进；未描述许可不能自行变成审批障碍，已有明确限制、拒绝和物品归属仍须遵守。裁定记录实际动作、观察、言语及结果，正文可以用等义对白和自然语序呈现，不应机械重复校验否定句。未明确性别时使用姓名或你我，不按外貌、姓名或职业猜测代词。此类提示词改进必须另做真实内容阅读，不能用提示词字符串测试代替效果验收。

日常计划只复用意图。工作/日常留在原地点，旅行须有目标地点；跨步多人互动不可复用，计划最多720分钟。裁定显式引用本步事件并允许继续、且事件事务提交成功后才激活。新知识、个人状态、目标、位置、同行人物、相关事件、世界定义或导演干预变化均会使计划失效。远处没有主角在场、没有干预或新情况的配角可以走背景意图；仍由环境裁定实际结果。

裁定可用planOutcomes.routineProgressFactIds指明既定活动的纯进度，避免每次记录继续睡眠或独立工作就必然使计划失效。仅允许continue、本人单独参与、原地点、正时长、本人独知且没有状态变化、传播、猜测和新因果的本步事实；缺失、重复或外来引用拒绝。普通进度和新发现必须分开记录，未列出的新事实仍会使计划失效。分类同时经过正常一致性审查：发现、消息、危险、新判断或需要重新选择的结果不得冒充进度，不确定时去掉分类并重新决策。程序只证明结构及来源合法，不证明自由文本语义。成功提交后仅更新仍有效计划的知识指纹；其他失效基线保留。旧记录缺少该可选字段时仍按原有保守规则处理，不需要新迁移。

同地点旁人的事件只有在该次裁定attempt对应的一致性审查明确通过、整个事件均是合法独知纯进度且无状态/传播/信念/因果变化时，才不打断本人计划；本人不得参与、获知其中事实或收到相关记忆。不是根据“睡觉”等文字猜测是否可忽略。旁人新增风险、未分类事实、互动、状态变化及进出地点仍使计划失效；途中离开又返回也须检测，不能仅比较步末同行名单。旧审查缺失、错轮次或未通过时仍按保守规则打断。

个人叙事输入包含本人的ownIntent，不传入其他人物的私下意图。本人意图只是尝试，不能代替已裁定事实；叙事可依性格和目标选择不同关注点，无须逐段复述同一场对白。吃饭、休息、睡眠及次日活动必须有地点条件、时间和事件依据；安静空白不等于已经完成这些活动。真实内容验收须记录样本条件，不能把新增生活场所和作者目标造成的变化全部归因于提示词优化。

当前行动契约每人每步只有一个targetLocationId。可在起点行动、移动到该目标并继续当地活动；action文字中的第二目的地不能授权另一段移动，须留下一轮决策。生效外部事件仍按现有规则处理。位置错误反馈须列出事件、人物、当前地点、事件地点、新状态位置及声明目标，使唯一修正能处理实际问题；不能只改事件地点掩盖不合法状态变化。修正失败后保留失败运行，不能清空阶段记录获得无限重试。

移动后的日常不能在出发地附work/routine计划；可不附计划或只为未完成的旅程附travel，到达后下一轮再选择当地活动计划。validUntil按本人准备重新选择的时刻设定，可跨多个模拟步，不能机械截短为当前untilTick，仍不得超过720分钟或以意图代替实际结果。

纯睡眠等无意识时段的个人正文用简短有限第三人称概述，不让人物在第一人称中自我报时或声明“尚未醒来”。精确分钟与时段留给时间轴；有意义的对话和时间判断才在正文保留精确数字。人物语气可不同，不能为了文采添加未裁定的天气、香气、目光或内心经历。短小的普通活动不强行展开成多人日志；这些表达规则仍需真实正文阅读验证。

正文优先当前实际动作、关键回应或结果，省略不影响理解的“计划尚未结束”、旧工作未重开和旁项未变化的重复列账；明确拒绝、营业/空房未知等会影响结果的不确定性必须保留。省略事实不是改变事实，不得将未知去处写成确定推荐或已经抵达。不为制造个性添加未经裁定的心理或环境。固定事件重写只能证明该组事实的表达变化，不能当成新的行动、长期作息或原作还原验收。

个人摘要采用可追溯的原文摘录，不调用另一个模型捏造总结；最多24事实、12记忆、8信念，合计10000字符，有效期120分钟。复用前再次校验分支、人物、时刻、输入指纹和来源。省略内容不表示世界中不存在，模型不得据此补造历史。完整历史仍供程序校验，历史查询缓存按新增行更新；不能宣称任意规模恒定成本。新分支重建自己的摘要与计划，不复制父分支缓存。

commitStep 将事件、记忆、人物状态、消耗干预、分支时刻/修订及运行进度放入同一事务。可重入写入使用 SAVEPOINT，不嵌套 BEGIN。模型调用在事务之外；规则验证可在 SAVEPOINT 内试提交并回滚，不能在等待网络时持有 SQLite 写锁。

## 4. 后台生命周期与恢复

运行由服务端调度，关闭页面不停止。单分支活动状态包含 queued、running、paused、uncertain；结束或完成后才允许另起运行。

步骤租约位于 sw_run_steps，执行期间每15秒续期至60秒。写入前再次确认租约及输入修订。sw_run_calls 在派发前持久化请求并扣额度，成功响应持久化后才进入下一阶段。

超时或中断但结果不明时进入 uncertain，停止后续派发。恢复接口支持“确认未执行”和“取得原始结果”；两者都要求明确核对说明。后者仍经过原阶段校验，不能直接注入事件。不得把超时当成安全重试依据。

明确拒绝（例如已核实的HTTP 429）只在显式恢复时授权新的派发。成功阶段复用原结果，旧失败请求/响应和授权审计保留，新派发继续扣额度；传输重试不得重置结构修正的attempt=1。failed状态本身不是未执行的证据。

提交后回调的步骤由 committed 变为 notified。调度仅扫描部分索引中的待通知步骤，使用租约和心跳排除并发回调；失败留待后续恢复，成功不反复扫描整个历史。回调必须幂等，因为进程可能在外部动作成功而状态尚未写回时退出。

关闭服务时等待活动步骤、调度及通知收尾后再关闭数据库。不得以吞掉 database is not open 异常代替生命周期修复。

默认运行1440分钟、120次文本调用、12幅配图；这些是默认设置，可在契约范围内调整。到达时间目标为 completed；文本额度不足会暂停。图片额度独立，未配图不能阻塞阅读或文本推进。只有配置价格才能展示费用估计。

## 5. 公共图片队列与视觉一致性

所有图片任务使用既有 Generation 服务，同一数据库内跨连接、跨模块共享名额：ComfyUI 1、云端图片组1、Worker图片组1，总计2。当前 cloud 引擎统一归 gpt-image 组；不能添加第二个 API 地址绕过限制。每个任务只能生成一幅图。

领取名额必须在 SQLite 事务中完成，提交中和运行中均计占用。已标 failed、cancelled 或 abandoned 但 upstream_may_continue=1 的任务仍占用名额。只有明确完成、失败或确认取消才释放；本地取消 HTTP 跟踪不证明云端已停止。恢复使用 confirmGenerationTaskUncertainOutcome 及管理恢复接口，必须保留核对说明。启动调度先完成历史任务核对再派发。

配图围绕 establishing、action、result 三阶段，固定人物外观、服饰、地点、事件摘要及事实，不能凭阶段名称强加冲突或道具。工作流输入依据实际字段声明映射；配方默认值与用户覆盖按现有生成协议合并。参考图和 LoRA 只在工作流支持时使用；纯文生图明确提示一致性限制。

任务成功只证明通道可用。验收必须查看图片，核对人物、道具、地点及动作顺序，并与正文相互检查。

图片请求尺寸与实际返回尺寸分别记录；供应商可能调整画幅，不能把请求1024×1024写成已验证输出为正方形。以文件真实尺寸和实际画面作为验收依据。

Cloud图片工作流按实际请求字段声明prompt/positivePrompt/negativePrompt，不伪造Comfy节点路径；GPT Image以service-finalized-v1处理最终文本。inputCapabilities是媒体输入控件映射，无媒体输入时为{}，不能写acceptsTextPrompt等布尔对象。云端负面词作为明确排除段合入prompt，JSON生成与multipart编辑保持一致；仅配置或准备成功不能证明供应商采纳了排除要求。

云端image-to-image工作流从媒体能力声明识别参考图，不要求Comfy节点路径；text-to-image不得仅因媒体能力存在就声称支持图生图。故事图片的size/quality只发送schema明确声明的默认值，未声明则沿用recipe或节点默认值，不能强行覆盖成1024×1024/standard。

世界可配置visualReferences场景和重要道具参考，按事件历史快照和地点/明确提及筛选；视觉备注不能写成模拟事实。绑定顺序为场景、道具、人物。当前路径实际只发送首张参考图，其余未发送数量须明示。不能把配置了多张素材说成上游已接收多图。

## 6. 前端与项目集成

服务器数据使用 React Query，选择/筛选在页面适配层管理。useStoredDraft 只保存有修改的草稿；关闭的干净表单不持久化陈旧基线。后台修订变化时干净表单自动更新，脏表单显示冲突并要求显式处理。

来源更新先预览人物、来源、地点和世界字段差异、受影响分支及角色库新版本。确认请求同时携带预览时的世界和分支修订，服务事务内复核；预览后世界再次变化必须拒绝，不能纳入未展示内容。既有事件、正文、记忆和状态不重写。无稳定原文链接的摘录只标本库快照版本与采集时间，不声称已同步原文。

重新比较必须同步更新预览及父级世界/分支查询，不能让新预览与旧修订长期冲突。位于transform侧栏内的全屏弹窗须挂到不受该变换影响的容器；来源预览使用body Portal，并验1440/390视口几何、滚动、确认与关闭操作。

桌面时间长卷、筛选与事件详情分区滚动。移动端优先阅读、人物筛选、事件详情和暂停。沿用语义 token 和主题，不另建外框；不使用 emoji 图标。

故事阅读默认每个事件只展示客观叙述，个人正文通过视角按钮显式选择，避免自动叠加多人重复段落。人物筛选的默认正文保持该人物视角；缺少正文时明确提示未记录并提供切换客观叙述，不能以全局概要或其他人物正文填充个人视角。已有个人记录（包括非在场列表内记录）均保留显式入口；个人记录可能采用有限第三人称，界面不声称必然是人物的内心独白。导演仍可主动展开全局事实、状态或事件档案；此处是叙述归属规则，不将阅读控件冒充访问权限边界。事实与状态默认折叠，首次操作即展开，并通过aria-expanded表达状态；局部展开和视角选择按分支/事件隔离。

事件查询限定世界、分支、时间窗口，单页最多200条。画布按窗口及聚合控制节点数量，聚合可展开、共享事件唯一、人物基线稳定。只有全部数据加载且无人物/故事线过滤时 dataComplete 才可为真；长事件仍在持续时不得折叠为无事发生。卡片碰撞布局只调整显示位置，不改事件 tick。字号、可见节点和实际截图均须检查，不能仅凭 DOM 数量判定可用。

采纳为新章节，保留来源分支、版本、事件及幂等信息，不覆盖既有正文。指定个人视角时必须参与事件且拥有该视角正文；缺少时明确拒绝，不回退全知 summary。正文后续编辑不反写历史世界。
