# SthStart 全站 Mantine 升级计划

交付状态（2026-11-14）：Mantine 9.8.0 已验收并部署到本地 9320。最终修订、验证结果、性能对比和回退版本见[迁移验收记录](reviews/2026-11-14-mantine-ui-maintenance.md)。

目标：把门户的基础控件、交互反馈、导航和弹层收敛到 Mantine，用同一套规则改造创作、查找和设置流程。最终要验收全站路由、编辑数据安全、四套主题和桌面／窄屏体验。安装依赖、角色库样板和全量迁移是三个不同的完成节点。

现行规则见 [前端架构规范](../FRONTEND_ARCHITECTURE.md) 和 [前端工作约定](../../app/AGENTS.md)。问题基线来自 2026-11-13 全站评估：29 个路由入口，81 次浏览器观测；发现角色筛选抽屉位置与功能缺失、抽屉打开时命令面板无法聚焦、窄屏页签截断、两个暗色主题日历对比度不足，以及媒体页首屏的素材路径异常。媒体问题单独验证来源与显示状态，避免把存储缺失当成样式缺陷。

## 方案和兼容范围

- React、Vinext、Tailwind、Lucide 和现有路由保留。Mantine 是通用组件的唯一来源；其 `core/hooks` 及按需验证的 `dates/spotlight/notifications` 官方扩展属于同一套。业务画布、Markdown、视频播放器、渲染器与邻舍 iframe 继续做专用工作，外壳和普通操作用共用组件。保留语义 HTML；适合原生选择器的简单选项不用改成交互复杂的 Combobox。
- 单一主题来源是 `app/styles/theme.css`。用 Mantine 样式层和主题变量映射四套主题、强调色、模块识别色、表面、边框、焦点、字号和间距；Mantine 的 light/dark 从现有主题派生，避免独立存储或竞争首屏颜色。保留暖纸视觉、Lucide、长文排版、窄屏触控和系统减少动画偏好。Tailwind 继续做布局及少量业务表现。检查 portal 浮层里的主题继承和 SSR 首屏，不把路由全部改为客户端组件。
- 共享适配器归 `app/components/ui` 和 `app/components/shared`。在保留有意义的公开接口前提下迁移按钮、表单、组合选择、页签、菜单、工具提示、对话框、抽屉、通知、分页、卡片及加载／空／错状态。新页面复用这些接口。原有兼容层逐批清理；完成时按入口清点残留并记录有明确用途的语义 HTML 或业务专用控件。表格排序与筛选、日历事件、编辑器草稿属于业务层。
- 继续使用 URL 筛选／分页、现有查询键、服务接口、草稿键、修订及历史恢复。保留中文输入法组合事件、原生表单提交语义、链接与浏览器历史。通用 UI 不引入业务请求、付费调用或存储变更。
- 浮层统一规则：抽屉在窄屏贴底，短视口可滚动并露出完成操作；桌面维持侧栏或对话框语义。弹层内菜单必须可点击与键盘操作，Esc 每次只关闭一层，关闭归还焦点，正文滚动隔离。全局命令仅在没有阻塞性模态时打开；禁止时不挂载，也不抢占输入法事件。旧原生 `<dialog>` 与新 portal 并存时遵守原生 top layer 边界，不靠增大 z-index 绕过。不同类型的浮层需要门户层明确协调。

参考：[Mantine 与 Next.js](https://mantine.dev/guides/next/)、[样式层](https://mantine.dev/styles/mantine-styles/)、[主题样式 API](https://mantine.dev/styles/styles-api/)、[抽屉和焦点](https://mantine.dev/core/drawer/)、[Spotlight](https://mantine.dev/x/spotlight/)。Next.js 文档不能代替在本项目 Vinext 生产构建中的验证。

## 分派与顺序

实施与补修子任务仅以 `magpie/auto-deepseek-v4.1-flash`（用户简称 `auto-deepseek`）/ `max` 执行。记录实际任务 ID 或进程、返回状态、改动与验证证据。主代理维护计划、分派边界、隔离基线、合并、独立验收及本地交付。每位子代理只写自己负责的文件；冲突文件通过主代理排期，交付补丁或明确变更清单。保留既有工作区改动；依赖锁文件、全局样式入口和公共适配器不并行写。子任务不部署、不改线上数据、不调用真实付费服务。

| 阶段 | 子任务与写入归属 | 交付门槛 |
| --- | --- | --- |
| A1 | **主题与运行时**：`package.json` / 锁文件、`app/layout.tsx`、现有客户端 Provider、`app/globals.css` 和主题桥接样式。确定同一版本的官方包，确认 Vinext 构建、层叠顺序、首屏及 portal 主题。 | 四主题及自定义强调色切换无错色；直接加载和客户端导航无新增水合错误；记录入口 CSS/JS 基线与改后差异。 |
| A2 | **共享控件与反馈**：`app/components/ui` 和公共布局；单一写入者收敛按钮、表单、页签、菜单、反馈、分页；保留必要的 CJK 和语义原生适配。 | 共享组件行为和架构通过；链接、提交、禁用、键盘、错误、空态、触控在代表页可用。 |
| A3 | **弹层和外壳**：A2 合入后接管其弹层文件；独占 `app/shell` 和外壳样式，统一全局导航、搜索、任务抽屉和叠层策略；清理旧叠层冲突。 | 窄屏抽屉贴底；焦点、下拉、Esc、`Ctrl/Cmd+K`、滚动隔离和回焦均通过；普通页与工作台的外框不重复标题。 |
| B1 | **角色样板**：`app/apps/characters` 及 `app/features/characters`。角色库、详情和新建；共享筛选模型贯通桌面和手机。 | 手机可达作品、标签、分组和仅收藏；链接状态能恢复；末尾页签可见可选；中文选词不误触。样板通过后铺开。 |
| B2 | **项目与 Story 样板**：`app/apps/{projects,story}`、`app/workspaces/{projects,story}` 及同名功能层。列表、项目详情、Story 工作台、章节和发布弹窗。 | 从项目继续创作、切章、退回、重开；中文草稿、自动保存、离线／冲突恢复、发布预览和危险操作有隔离证据。 |
| B3 | **活动制作样板**：`app/apps/activities`、`app/features/activities` 与活动专属样式。列表、新建、Studio、分镜、预览及导出反馈。 | 活动创建→编辑→分镜→预览走通；拖动分栏、时间轴、草稿、错误及预览状态可达；使用假任务验证导出和失败重试。 |
| C1 | **世界、叙事与日历**：`app/apps/{story-worlds,narrative,calendar}`、`app/workspaces/narrative` 和对应功能层。 | 世界的空／运行／阅读状态、叙事过滤与详情、日历事件及日期切换可用；四主题选中文字实测合格。 |
| C2 | **笔记与资料**：`app/apps/{notebook,resources}`、`app/workspaces/resources`、对应功能层及专属样式。 | 笔记列表、新建、详情、离线入口、搜选资料与采用；验证草稿不丢，移动页签与返回路径可达。 |
| C3 | **媒体、灵感与自由生成**：`app/apps/{media,inspiration,creative}`、`app/workspaces/{media,generation}` 和对应功能层；其他模块的嵌入入口由其归属者验收。 | 媒体列表、详情、筛选、导入入口和素材缺失可区分；有图样本可预览；空／错／等待／失败以固定数据覆盖，不调用真实生成。 |
| C4 | **首页、设置及邻舍边界**：`app/page.tsx`、`app/workspaces/home`、`app/settings`、`app/apps/linshe` 和对应功能层。外壳修改先交 A3。 | 首页继续创作及导航；配置分组、公共服务、模型／生成、诊断、日志、备份界面；邻舍桥接、返回和 iframe 错误状态。备份／恢复只在隔离环境。 |
| D | **收敛与补修**：各归属者按最终矩阵修复问题，架构文档记录组件归属和升级方式；主代理审核残留、独立验证和部署。 | 达到以下完成条件才关闭全站计划。 |

A1 是基础。A2→A3→B1 作为首条验证链；主代理同时准备夹具与基线。A2 接口稳定后，B2、B3 可以并行；B1 与两个工作台的接口验收后，C1–C4 按不重叠的归属并行。跨模块样式或组件的变更由原归属者集中处理。各批记录行为证据和未覆盖边界，验收失败回分对应任务。

## 全站验收与交付

1. **覆盖与视觉**：完整核对 29 个入口（含重定向及实际数据详情）。每个路由族覆盖 1440×900 与 390×844；代表性普通页、设置和工作台补测 1024×768、1920×1080、短视口及四主题。逐页记录加载／有数据／空或错误状态中实际可出现的状态。窄屏尾部页签可达，页面不整体横溢，工作台独立滚动。捕获手机角色抽屉、编辑与预览、媒体可用与缺图、暗色日期的真实页面截图。
2. **交互和可访问性**：键盘顺序与可见焦点；CJK 组合不触发提交、关闭或快捷键；Esc 只关栈顶；退回触发点；链接和浏览器历史保留；普通文字对比度至少 4.5:1（大字 3:1），要求可辨识的控件边界和状态至少 3:1。测实际绘制颜色和真实点击；不能只据 axe 无违规或截图认定通过。浏览器自动化覆盖 Chromium 及可用的 WebKit，报告未实测的真实设备／输入法边界。
3. **业务与数据**：在 Playwright 隔离数据库、媒体和端口下执行编辑、自动保存、刷新恢复、冲突和导航；保留笔记和 Story 的离线及同步；验证角色 URL 筛选、项目详情、日历、Studio 回放、预览和模拟导出、资源采用、设置出错与边界。生产服务仅进行健康和只读页面抽查。
4. **工程与性能**：运行 `npm run ci:core`，必要时 `npm run lint`；执行定向 E2E 后扩大到全站流程与浏览器矩阵，不能因快照失败盲目覆盖。测同一基线、同样夹具下普通页和工作台的首屏 CSS/JS、加载、长任务及水合；若首次交互或页面开销明显回退，先定位并补修。核查依赖与最终导入，确认不再有第二套通用 UI 体系，说明剩余原生控件与业务组件用途。
5. **整合与回滚**：以当前项目状态创建私有隔离基线和可审查的批次差异。保留用户现有工作，把产品补丁与无关变更区分；合入前检查可应用性及是否覆盖并发修改。主代理在最终候选上重新独立运行验收，记录修订、依赖版本、测试／截图、已知限制和上一可用本地版本。候选通过后更新现有本地 `9320`，检查健康及真实改动页，异常则按已有可用版本恢复门户与服务。数据格式不变；不推送远端。

完成条件：各阶段的实现、回归记录、全站矩阵、残留清单和本地验证均具备同一最终版本的证据。任一尚未验收或仅有样板证据，计划保持进行中。
