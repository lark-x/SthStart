# AI 驱动创作系统：已批准实施范围

批准日期：2026-11-17。用户授权按本计划灵活实施；当前模型与 auto/deepseek-v4.1-flash 分别最多3个子代理，后者max。不使用computer use。保留已有脏工作树。主代理负责契约、集成、验收及备份后的本地9320部署，不推送Git。

## 产品决定

- 全站AI入口，兼容Codex等外部Agent；可启动站内团队，也可直接提交作品产物进入同一审核流程。
- 人物自主＋导演引导；总管/制片、创作导演、总编三个核心岗位，按任务增加受控模板岗位；不同岗位可选不同模型。
- 支持同一时间线多线交织和历史隔离的平行版本。正式事实、人物知情范围、状态、来源与摘要分别保存。
- 完整场景/小节作为交付单元：正文、事件、状态变化、新设定、伏笔、审核共同确认；用户最终采用前不改变正式历史。
- 等待确认最多预写1个后续场景，标记依赖；重大不可逆变化先确认。旧事实改变时依赖产物失效但保留历史。
- 场景描写与可延续视觉细节充分；设定与镜头表现分开，图片不反写事实。
- 插图优先：任务单→提示词模型→生图→独立视觉模型→定向返修；初次＋最多2轮返修且受额度限制。普通图可自动采用，定妆/地点基准/关键剧情和无法判断的重要性人工确认。
- 视频先审核分镜/用途/额度，按真实通道能力开放，不能把配音图文冒称动态视频。
- 首期有可视化编排：类型化输入输出、并行汇合、条件、有限返修、子流程、人工门、正式采用；模板/自然语言/画布共同编辑同一草稿。运行固定版本，工具权限不由节点图提升。
- 运行持久、租约/CAS、明确失败与未知分开、调用审计、额度硬限制、不会因网络超时重投。正式内容与已采用媒体不自动清除。
- 单人，1–3活跃作品，每时间线5–10核心角色。页面阅读优先，技术细节按需展开。

## 2026-11-18 项目计划重评估与三阶段收敛路线

基于阶段 C/F 的真实模型试跑经验（详见[创作系统评估](reviews/2026-11-17-creative-system-evaluation.md)），对既有实施范围进行重评估与收敛：放弃高耦合重型流水线对日常写作的强绑定，聚焦“作品统一工作台 + MCP 原文精读闭环 + 轻量化章节副驾”。以下既保留 2026-11-17 历史实施与验收证据，同时明确新的收敛方案：

### 核心收敛决定

1. **统一创作入口收口至作品工作台 (`/apps/story-worlds`)**
   - 主侧栏仅保留“作品”（`/apps/story-worlds`）作为创作领域主入口，承载世界观设定、正史章节脉络、MCP 原文检索与沉浸式正文创作。
   - 原 `创作项目`（`/apps/projects`）与 `AI 创作工作台`（`/apps/ai-studio`）在主侧栏设为隐藏（`hiddenFromSidebar: true`），继续保留命令面板（`Ctrl/Cmd+K`）索引与直达 URL 兼容；旧正文编辑页顶部链接同步收敛至 `/apps/story-worlds?...&view=chapters`。

2. **以轻量化章节副驾替代多节点巨型 JSON 双阻断审核流**
   - 阶段 C/F 实测表明，将导演规划、整场巨型结构化 JSON（正文 + 事件 + 状态 + 新设定 + 伏笔）及双路阻断式独立审核强串联，容易出现输出截断、JSON 解析脆弱及供应商客户端拒审导致流程卡死。
   - 收敛为交互式三步轻量协同链路：**`场纲节拍 -> 纯文本写正文 -> 事后非阻断一致性体检`**。
   - 作者以章节纯文本正文（即时新建与带版本校验的保存）为核心产物；AI 副驾按需提供节拍拆解（`beats`）、正文起草/润色（`draft` / `polish`）与事后非阻断体检（`check`，输出结构化 `canon` / `tom` / `voice` / `style` 问题提示与事实摘录），不阻断作者编辑与保存。

3. **打通 MCP `检索 -> 原文精读 (akasha_read) -> 参考篮引用` 闭环**
   - 在作品工作台内打通针对原作/资料 MCP 源的完整参考链路：先通过检索获得命中片段与定位符（`locator`），再经原文精读接口（`akasha_read`，支持按 `offset` / `limit` 分段读取原文内容）核实上下文，随后将选定片段收入“参考篮”，作为章节副驾写作与体检时的直接依据。

### 邻舍故事模式对照（2026-11-18）

核验基线为邻舍 `v4.4.0`（`4562ca0a`）以及从 `v3.9.0`（`686a2a5b`）引入的 SthStart 集成代码。4.4.0 发布提交主要更新照相馆相框与滤镜、关系图样式、字体资源和排期视图，未见故事推进主链的重大重构。故事模式相关实现可分为两条：

1. **Galgame 沉浸对话**：从角色私聊切换到沉浸式呈现，仍沿用普通私聊的角色、上下文、历史记录和流式对话生命周期。它改变的是交互呈现与代入感，不会单独创建章节、场景版本或正史状态。
2. **小镇奇遇**：由角色/小镇事件开启情境，事件保存 `choice_history`、当前分支和新选项。玩家可选给定行动或提交自由行动，模型根据事件摘要、此前选择、角色人格和世界规则续写；支持撤回上一步、事件到期收束及历史归档。对话也会读取活动事件的最新摘要，形成事件线与角色私聊之间的上下文衔接。

2026-11-19 已完成 `upstream/linshe` 工作树的 4.4.0 集成：以本地 `e4d524ef`（含 SthStart 角色、图库和图片托管补丁）为基线合入 `4562ca0a`，保留 4.4 的照相馆批次、相框滤镜、关系图、语音依赖和工作流元数据，同时恢复公共 LLM、图片 Artifact、向量与角色权威接入；ComfyUI 仍默认使用邻舍自身配置。冲突后的前端 bundle 已重建为 `index-DsbyjgSi.js` / `index-Bq3zHuZ2.css`。完整邻舍后端回归为 400 通过、1 跳过、0 失败，父项目邻舍角色契约 2 项通过，公共角色权威 UI 3 项通过。邻舍旧 UI 测试仍有 22 项按 3.9 的串行批次行为断言，与 4.4 的服务端批次模型不一致；生产构建通过，但这组旧测试尚未改写为 4.4 语义。该结果目前位于子模块工作树，底层提交仍为 3.9 集成基线，父项目指针只有在后续明确提交子模块后才可推进。

这套交互把“下一步做什么”交还给玩家，角色人格和处境约束续写，回合历史承载连续性。它适合即兴扮演和短事件线，但其完成态属于邻舍事件/对话历史，不能直接等同于作者作品中的章节正史。AI 可提供情境和候选行动，作者仍须决定哪些内容进入正式作品。

SthStart 当前新增的 `turn` 章节副驾沿用“作者行动 → 模型续写一幕 → 返回下一步选项”的逐回合节奏，并把推演记录暂存在当前面板。作者明确汇入已有章节或新建章节后，结果才进入手稿。它应成为作者尚无完整故事构想时的探索入口，而不是代替作者决定主题、角色价值和最终取舍。作者可从一个角色、关系、地点、困境或一句话起步，逐回合接受、修改或忽略模型选项；推演正文与手稿继续保持可辨认的边界。

当前 `turn` 已具备逐回合请求和显式汇入路径，作者提交下一步行动时会把此前手稿和本面板内推演正文继续传给模型。与邻舍事件模式相比，尚不持久化推演会话、分支/撤回状态和结束归档，刷新页面会丢失尚未汇入的推演。后续是否补这些能力，按实际作者使用反馈决定，且应优先保存可恢复会话，再考虑复杂事件类型或自动长篇结构。
