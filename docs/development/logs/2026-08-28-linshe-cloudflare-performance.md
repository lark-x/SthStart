# 2026-08-28：邻舍 Cloudflare 远程访问性能收口

状态：阶段 1～4 已实现，真实手机验收延后  
关联事项：VAL-013  
关联提交：待提交

## 本轮目标

- 降低邻舍经 Cloudflare Tunnel 访问时的首屏体积、重复请求和角色切换等待。
- 保持 API、用户图片和聊天内容的私有缓存边界。
- 提供不记录内容与密钥的浏览器端性能诊断，为手机线路与 Tunnel 协议选择提供依据。

## 已完成

- 移除约 8.7 MB 的 HarmonyOS WebFont，改用系统中文字体；除聊天外的页面改为路由懒加载，并只在浏览器空闲时预取常用页面。
- 邻舍核心为带哈希的 `/assets/` 返回一年不可变缓存，HTML 返回 `no-cache`；`/api`、`/images`、`/avatars` 不进入公共静态缓存。
- 为角色、配置、日程、群聊和信箱的读取请求增加短时请求合并与 TTL；写操作完成后强制失效，失败结果不缓存。
- 聊天历史默认只返回最近 50 条，支持游标向上加载；保留旧客户端无分页参数时的完整响应兼容。
- 角色切换保留各自的内存消息会话，已访问角色可以立即显示；并发初始加载会复用同一个请求。
- 设置页增加“远程访问诊断”，显示首字节、页面可交互、API P50/P95、静态传输量及统一 SSE 重连次数，不采集正文或凭据。
- 远程检测脚本支持 `--target linshe`；部署文档明确生产 Tunnel 使用 3099 的已构建同源页面，5173 仅用于本机开发。

## 关键指标

- 优化前生产静态资源约 10 MB，其中字体约 8.7 MB。
- 优化后入口 JS gzip 约 195 KB、入口 CSS gzip 约 26 KB，首屏不再下载字体文件；其余页面按需加载。
- 聊天初始历史从全量改为最多 50 条，单页上限 100 条。

## 已知限制与后续决策

- Cloudflare Access 登录、跨境链路和手机代理线路仍可能贡献主要延迟，应用代码不能消除这部分 RTT。
- 只有真实 iPhone 记录显示暖导航或 API P95 仍持续超过 1.5 秒时，才进入下一阶段持久化本地读取缓存；当前不提前复制聊天数据库到浏览器。
- 3099 只能保持回环监听并经 Cloudflare Tunnel + Access 暴露，禁止路由器端口映射。
- 真实手机、不同代理线路以及 QUIC/HTTP2 的长期 A/B 验收继续登记在 VAL-013。
