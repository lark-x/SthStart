## 一、总体结论

三轮功能均已实现，服务端与前端形成完整数据流：资料元数据与来源可保存 → 资料可被企划检索引用 → 引用内容在生成时冻结成快照 → 搜集任务与待整理可形成资料 → 推荐/补查/更新检查/批量导入/活动回流接入。

- 自动化：契约 16 项、服务端 273 项、门户 10 项全部通过；`npm run typecheck` 与 `npm run build` 通过。
- 手动浏览器走查：34 项断言全部通过，0 个页面错误，含一次窄屏检查。

**真实外部 MCP 未联调**：本轮浏览器验证与自动化测试均使用本地模拟资料源与模拟模型（HTTP JSON-RPC + /chat/completions mock）。真实虚空终端/Akasha 与真实模型的输出质量未在本轮验证。

## 三、第一轮：资料可用于企划

### 服务端

- `knowledge/store.ts`：元数据归一化（三条轴 + 作品/角色/地点/分类/来源/来历）、`noteReferenceText`（只取文本/链接/原文摘录/图片说明，图片像素不会被模型读取）、内容 hash、来源身份与版本（同源同内容只更新检查时间，内容变化保留新旧版本）、引用记录。
- `knowledge/search.ts`：资料与叙事分别查询再汇总（不跨库 JOIN）；短中文词走 LIKE 回退；叙事结果行号标为本地行号（`lineKind: 'local'`），不冒充远端真实行号；推荐按「关联角色 > 同作品/同地点 > 标题摘要 > 正文」打分，同名角色不跨作品合并。
- `knowledge/references.ts`：引用解析、快照编译（单条 2400 / 总计 16000 字符预算，超限标记 `truncated`）、更新检查（hash 比较，区分 updated/missing/unchanged）、提示词分块（原作背景 / 未确认解释与个人设定 / 本次要求分开列出，并声明资料里的指令不能改变用户要求）。
- `knowledge/routes.ts`：`knowledge/search`、`knowledge/notes`、`references/preview`、`references/check`、`notes/:id/knowledge`、`notes/:id/references`、`source-versions/:id`。
- `notebook.ts`：服务端筛选（作品/角色/分类/参考状态/性质/收藏）与分页 + 分面；未带分页参数时保持旧的 300 条上限以兼容离线缓存；**元数据缺省表示不改动，显式 null 才清空**，旧客户端整篇 PUT 不会清掉来源与参考状态。
- `activities/planning.ts`：引用选择写入会话，生成时编译并冻结快照（写回会话，版本冲突不阻塞生成）；`validatePlanningOutput` 只接受本次真实存在的 `referenceIds`；候选 `planningInput` 与 `planningBasis` 携带快照。

### 前端

- 资料库改名与入口：侧栏「资料库」、页面「创作资料库」、`/apps/notebook` 深链接与内部 ID 保持不变。
- 资料属性面板（默认收起）：三条轴、分类、作品/角色/地点标签编辑、手工来源与摘录、引用记录。
- 元数据筛选行（作品/参考状态/内容性质/资料类型）走服务端筛选。
- 参考资料选择器：资料/叙事切换、出处预览、空态说明「资料库中暂未找到」。
- 企划向导：参考资料区（添加/移除/用途切换/查看本次引用）、方案卡展示「主要依据」。

## 四、第二轮：搜集进入资料库

### 服务端

- `knowledge/collections.ts`：任务定义（名称/目标/作品/角色/模式/时间范围/资料源绑定/频率/时区/下次时间/启停）与执行记录分离；待整理（同一任务同一来源版本只入一次）；整理草稿与采用。专题模式不使用「新梗/近七天」等热点词；近期模式默认最近七天。
- 执行流程：搜索 → **先保存来源与版本** → 模型整理 → 生成待整理；整理失败仍交付原始来源并标记 partial；重试整理复用已保存版本，不重新访问资料源；每轮 12 次工具调用、180 秒、同时 2 个来源。
- `knowledge/scheduler.ts`：每分钟检查到期定义，**先顺延下次时间再执行**（每个定义最多补跑一次）；暂停的定义不调度；手动与定时共用占用检查，同一任务不并发。
- 取消与重启：取消后迟到的返回不覆盖状态；重启把未完成记录标记为 interrupted。
- 话题收藏：重复点击返回已有资料，保留话题来源快照，默认「仅记录」。
- 任务中心：新增 `knowledge_collection` 域，只暴露已实现的取消能力。

### 前端

- 资料库顶栏三视图：资料 / 搜集任务 / 待整理；支持 `?view=collections` 深链（任务中心跳转指向它）。
- 搜集任务：任务卡（状态、模式、频率、下次时间、最近一次结果）、执行记录展开、执行详情（新增/有变化/重复发现、仅读取部分内容标记、重试整理）、新建/编辑弹层（保存任务 ≠ 联网，另设「保存并立即搜集」）、无资料源时保存为暂停任务并说明原因。
- 待整理：分组计数、批量保留/忽略/整理/用于企划、详情侧栏含历史版本；「保留」不生成笔记，「整理为资料」才生成正文。
- 整理草稿：左「原资料」右「建议整理」，可新建或追加；追加前校验目标 revision 与内容 hash，生成期间目标被编辑时拒绝静默覆盖并保留草稿；可添加叙事档案原文片段作为来源。
- 话题卡片新增「收藏到资料库」。

## 五、第三轮：推荐、补查、更新与批量维护

- `knowledge/gaps.ts`：按本次范围给出缺口问题，统一用「是否有……」提问（资料库没找到 ≠ 原作没有）；引用齐全时不重复提示已有分类；来源时间较旧或未知时提示检查近期动态，但不自动联网。
- 本地推荐：只查本地资料库，展示「关联主角/同作品/包含地点资料/标题匹配主题」等可读原因，不展示虚假概率；「仅记录」的资料默认不进入推荐。
- 补充搜集：先列缺口问题（可自行填写），按专题建一次性任务并执行，结果进入待整理并可直接回填到参考资料；失败时仍可「仅用已有资料生成」。
- 更新检查：只比较本地 hash/revision；**收藏星标变化不算内容更新**；显示旧摘要与新摘要，可选择「继续用旧内容」（以 `excerptOverride` 固定）或下次生成使用最新内容；不改写旧候选与已创建活动。
- 批量导入：从资料库提供入口跳到现有叙事档案导入流程；原文片段可直接参与整理草稿。
- 角色详情「相关资料」：按角色与作品查询，可从该角色发起专题搜集，不要求先建人设卡。
- 活动回流「整理为个人设定」：选择活动片段保存为资料，默认「仅记录」+ `nature: personal`，注明来自哪个活动与当时版本，不自动成为其他活动的背景。

2. 服务端筛选与分页不受首批条数限制；中文短词回退可用。

6. 推荐不跨作品混用同名角色；仅记录不进入推荐。

8. 一次性专题任务不绑定企划、不限最近七天。
9. 重复运行不重复入待整理；内容变化可辨认；多任务发现同一来源各留关联不复制原文。
10. 来源失败仍可使用成功结果；重试整理不重新搜索。
11. 取消与重启中断不留永久运行中记录；调度器每个定义最多补跑一次。
12. 整理草稿目标被编辑时拒绝静默覆盖并保留草稿。
13. 收藏同一话题两次只得到一份关联资料。
14. 活动回流默认个人设定且不自动进入推荐。
15. 引用更新检查区分内容更新与元数据变化。
16. **工程导出→导入保留引用快照**：快照正文、内容 hash 与证据链逐字保留；导入后删除源资料，历史快照仍可读，更新检查标记为「源资料已不可用」。导入不写入指向本地资料的绑定，跨环境不会误绑同名或同 ID 对象。
17. **叙事重复导入与原文变化**：同一份规范化 JSON 导入两次只保留一份原文且不自动生成资料；上游按稳定 externalId 改文后重新导入仍只有一份，引用更新检查能发现变化并保留旧摘要。

## 七、真实限制与剩余项

1. **真实外部 MCP 与真实模型未联调**；模拟源验证与真实来源验证必须分开看待。
2. 场景 A（普通记笔记 + 离线）与场景 C（两次活动完整对照）的端到端人工走查未做；工程导出导入的引用快照已由回归测试覆盖（见验证记录第 16 项）。
3. 批量导入只保证「叙事档案规范化 JSON」这一条路径；未适配任意原始数据仓库。
4. Akasha 原文行号仍是导入时重新编号的本地行号；界面已标注 `lineKind: 'local'`，但未保存远端真实行号。
5. 整理草稿的「替换指定内容」未实现，只提供新建与追加（计划中该能力为「仅在明确展示差异后进行」，本轮未纳入）。
6. 资料库列表仍是传统列表 + 详情页，没有为资料做块级定位跳转；跳转到资料只到资料本身。
7. 搜集执行预算为固定默认值（12 次调用 / 180 秒 / 2 个来源并发），未做界面可调。
8. 未实现语义检索、知识图谱或资料关系可视化（计划已明确不作为必做项）。
9. 邻舍与 ComfyUI 未改动；视频渲染未涉及。

## 八、使用说明

1. **写资料**：`/apps/notebook` → 新建资料；只要求标题和正文，其余可后补。
2. **开启参考**：资料属性 → 使用状态改为「可参考」，并按需填内容性质、形成方式、作品/角色/地点、来源摘录。
3. **搜集与整理**：资料库顶栏「搜集任务」→ 新建任务（专题不限时间 / 近期可选天数；一次或每天每周）→ 保存并立即搜集 → 到「待整理」保留、忽略或整理为资料。
4. **企划引用**：新建活动向导第一步 → 参考资料区「添加资料」或「推荐资料」；可在方案卡查看「主要依据」。
5. **补查缺口**：「补充搜集」勾选问题并执行；结果进入待整理，也可直接加入参考资料。
6. **更新依据**：「检查资料更新」查看新旧摘要；需要锁旧内容时点「继续用旧内容」，否则下次生成使用最新内容。
7. **活动回流**：活动「设定」页 →「整理为个人设定」，选择片段保存；默认仅记录，可在资料属性里改为可参考。
8. **备份**：沿用既有便携备份/工程导出；引用快照随活动依据一起保存。

## 九、可重复演示步骤（小样本）

1. 在公共服务里配置一个可检索的 MCP 资料源并测试连接。
2. 新建一篇资料：标题「钟离的人物关系」，正文写一句关系描述；资料属性里填作品「原神」、角色「钟离」、来源摘录一句，参考状态改为「可参考」。
3. 「搜集任务」新建专题任务（目标：整理钟离的人物关系；资料源选上面那个），保存并立即搜集；在「待整理」看到结果后点「整理为资料」，生成草稿并保存为新资料。
4. 新建活动 → 选主角 → 参考资料区点「推荐资料」加入第 2 步的资料；点「补充搜集」看到缺口问题，可只选一两个执行或直接关闭。
5. 生成方案后在方案卡查看「主要依据」；点「检查资料更新」确认没有内容更新（只改收藏不应触发更新）。
6. 活动「设定」页点「整理为个人设定」，保存后在资料库看到一篇仅记录的资料，来源注明来自这场活动。
