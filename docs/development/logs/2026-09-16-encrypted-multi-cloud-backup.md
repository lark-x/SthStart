## 一、总体结论

三阶段的功能都已实现并串成闭环：一致的加密快照 → 文件级增量 → 多目标独立上传与校验 →
按版本恢复（活动副本 / 资料导入 / 完整工作区）→ 定时与保留清理 → 换机只凭远端仓库找回版本。
页面位于「设置 → 云备份」（`/settings/backups`），沿用现有设置布局与组件。

验证严格分档，不把未验证的部分算作完成：

1. **自动化测试（已通过）**：新增 11 项（加密 4 项 + 备份链路 7 项）。本轮结束时服务端 289 项、
   契约 16 项、门户 10 项、windows-worker 4 项全部通过；`npm run typecheck` 与 `npm run build` 通过。
2. **本地端到端（已通过，使用 `local_test` 适配器与真实文件系统）**：备份 → 只新增一张图时复用未变化媒体 →
   一个目标失败时部分完成 → 只重试失败目标 → 把同一版本补传到新目标 → 保留清理不删除其它目标需要的对象 →
   换机导入远端仓库并找回版本 → 资料导入（含重复跳过）→ 完整工作区恢复准备（含恢复前备份）。
3. **真实网盘联调（未做）**：Google Drive 与 OneDrive 适配器按官方接口实现，但本轮**没有**真实账号与授权，
   没有做过真实上传/下载/续传的端到端验证。夸克网盘按计划只做能力核实，**明确未支持**。

同时说明：`local_test` 适配器是测试与模拟验证用的适配器，不能当作三个网盘都可用。

## 三、实现内容

### 契约（`packages/contracts/src/index.ts`）

仓库/目标/计划/运行/版本/对象/恢复/清单的完整类型，含 `BACKUP_FORMAT_VERSION=1`、
`BACKUP_SCRYPT_PARAMS`、`BACKUP_UPLOAD_CONCURRENCY=2`，以及各请求体、恢复预览、清理预览。

### 加密（`apps/service/src/backup/crypto.ts`）

AES-256-GCM + scrypt + HKDF，版本化文件封装 `STHBAK01`：

- 仓库随机 256 位主密钥；密码与恢复密钥分别经 scrypt（独立前缀）派生包裹密钥，只用于包裹主密钥；AAD 绑定用途。
- 主密钥经 HKDF 派生 `object-encryption` 与 `object-naming` 子密钥，不复用同一密钥做不同用途。
- 每个对象独立随机文件密钥与唯一随机 nonce；**不固定 nonce、不复用 nonce**；续传始终复用已冻结的同一份密文字节。
- 单遍流式封装（`.part` 临时名 + 原子改名），输出 hash 覆盖「头部 + 正文 + 标签」，可直接用于上传后校验。
- 解密先写临时文件，认证标签通过后才改名；截断、密码错误、身份错配、篡改都不产生部分明文。
- 头部身份可被新设备读取（身份由 AAD 认证保护），因此换机不需要旧设备的本地索引。

### 仓库与解锁（`apps/service/src/backup/vault.ts`）

创建仓库只返回一次恢复密钥；密码/恢复密钥二选一解锁；「记住本机」写入 `SecretStore`（无可用后端时不静默写明文）；
修改密码只重新包裹主密钥（不重传媒体），并逐目标报告仓库头更新结果。

### 对象仓库（`apps/service/src/backup/objects.ts`）

以明文 SHA-256 判定变化；同一内容在仓库内复用一个密文对象；密文缓存仍在时直接复用，不重新随机加密；
缓存丢失时从有效远端副本取回（`restoreCipherFromRemote` 先校验密文 hash 再认证解密），
**绝不重新加密覆盖**，避免旧清单里的密文 hash 失效。

### 一致捕获（`apps/service/src/backup/capture.ts`）

- 维护窗口：捕获期间标记「维护中」，写入型业务请求得到可重试的 503（备份自身接口不拦截）；
  用 `try/finally` 结束，异常与重启都不会让项目停在维护模式。
- 两个数据库各自 `VACUUM INTO` 事务一致快照；跨库一致性由维护窗口 + 长任务收敛等待保证，
  等不到预算就如实记录「仍有长任务未收敛」，不假装是空闲拍的。
- 三种范围：完整工作区（数据库 + 媒体 + 笔记附件）、指定活动（复用工程导出规则，元数据合并为一个对象、
  媒体各自入对象仓库，不把整个工程 ZIP 当唯一对象反复重传）、创作资料（版本化逻辑包 + 附件，
  **只导出所选资料及依赖，不夹带完整业务数据库**）。
- 排除备份自身、日志目录与暂存目录；源文件缺失逐条记录，本版本不标「完整」。

### 清单（`apps/service/src/backup/manifest.ts`）

解密后的完整清单列出恢复所需全部对象（逻辑相对路径、资源种类、明文/密文 hash 与大小、远端不透明对象键、
引用来源），不是「比上次多了什么」；解析时校验格式版本与相对路径安全（拒绝绝对路径与 `..`）；
格式版本高于应用支持版本时明确拒绝。

### 适配器（`apps/service/src/backup/providers/`）

统一接口覆盖连接状态、定位仓库、列举、检查、可恢复上传、下载、删除能力与配额；能力用结构化结果表达。

- `local-test.ts`：本地目录适配器，按远端语义实现（对象不可变、最后发布清单、SHA-256 远端校验），用于测试与模拟验证。
- `google-drive.ts`：官方 Drive API v3 + 用户 OAuth（PKCE），默认写在 `appDataFolder`，
  可恢复上传会话、256 KiB 分片对齐、会话过期重建，上传后核对大小并在小对象上回读校验。
- `onedrive.ts`：Microsoft Graph + 用户授权，默认应用专用文件夹（`approot`），
  上传会话、320 KiB 分片对齐（与 Google 分开配置）、会话重建。
- `quark.ts`：**只做能力核实报告**，不提供看似可用的按钮。报告逐项列出「待验证/不支持」与原因
  （文档说明没有删除命令、原生 Windows 不支持、需要真实账号确认非交互复用与刷新）。
- `resumable.ts`：通用可恢复上传，按服务端确认偏移续传、会话失效重建、有限重试加退避；
  网络/授权/空间不足分别归类，凭据错误不无限重试。

### 执行器（`apps/service/src/backup/runner.ts`）

手动、定时、重试共用一条路径：空闲等待 → 一致快照 → 加密 → 每目标独立上传 → 清单最后发布 → 完成。

- 每个目标独立成功/失败/重试；最多小并发 2；半成品清单不出现在可恢复列表（清单最后发布）。
- 本地 `uploaded` 标记不是唯一事实：每次仍核对远端存在与大小，被删除或被替换就重新上传。
- 没有可信远端内容校验值时，小对象下载回读算 hash，大对象如实标注「完整校验待完成」，不用大小冒充一致。
- 取消只停止安排新上传，已成功目标与可续传状态保留；解锁后补做等待中的运行。
- 重试/补传继续用原快照与冻结密文，不重新捕获已变化的工作区。

### 调度（`apps/service/src/backup/scheduler.ts`）

每天/每周按用户时区计算（`weekday` 为 0=周日…6=周六），启动时每个计划最多补一次；
先顺延 `next_run_at` 再执行，重复 tick／重启／重复点击不会并行捕获同一计划；服务忙时延后并提示。

### 恢复（`apps/service/src/backup/restore.ts`）

下载 → 校验密文 hash → 认证解密 → 验证明文 hash 与大小 → 预览 → 执行。

- 预览只读，列出活动/资料/媒体数量、时间、schema 版本与缺省项。
- 活动恢复默认导入为新活动副本；资料按逻辑包导入（重复导入按「标题 + 正文」跳过，来源引用按新映射改写）；
  完整工作区替换必须显式确认。
- 完整工作区替换只做「准备」：先生成恢复前便携备份（失败即中止），把已解密文件留在隔离目录并写出
  `apply-restore.json`，由停止服务后的恢复助手完成替换，恢复记录如实标为**部分完成**并给出命令，
  不显示「已恢复成功」而服务仍在使用旧连接。
- 换机：`connectRemoteVault`（可用「网盘类型 + 目录 + 远端仓库 ID」在还没有本地仓库时导入仓库头）、
  `listRemoteSnapshots`（只凭远端清单文件名列出可恢复版本）、`adoptRemoteSnapshot`（登记版本并重建对象索引）。

### 保留清理（`apps/service/src/backup/retention.ts`）

按目标保留最近 N 次成功版本，长期保留的版本不参与淘汰，也不占用「最近 N 次」名额；
先让过期版本退出可恢复集合，再删除不再被任何保留版本引用的对象；
引用集合同时考虑该仓库其它目标（否则那边已发布的清单会失效）与被固定的对象；
无删除能力的网盘只做逻辑过期并如实说明需要手动清理，不计入已释放空间。

### 日志与任务中心

- `LogEvent` 增加可选上下文（`eventId/taskId/runId/snapshotId/targetId/phase/errorCode`）与跨重启唯一的 `eventId`；
  旧日志按「时间 + 序号」合成等价游标。
- 新增磁盘 JSONL 分页历史查询 `GET /api/v1/admin/logs/history`（可按服务、级别、任务、运行、时间筛选），
  有界读取（每文件最多读末尾 4 MiB），并新增写入串行的大小轮转与服务退出前的队列 flush。
- 备份与恢复的日志只记录阶段转换与摘要，秘密（密码、恢复密钥、主密钥、OAuth token、上传会话 URL）不落日志。
- 任务中心新增 `backup` 域：展示每次运行的状态、每目标进度、可取消/可重试，并可跳转到该次运行的日志。

### 接口（`apps/service/src/backup/routes.ts`）

全部挂在 `/api/v1/admin/backups/*`，与现有管理 API 约定一致（门户通过 `/api/admin/*` 代理到服务）：
概览、仓库（创建/解锁/锁定/改密/连接已有仓库）、目标（列表/保存/断开/验证/授权开始与回调）、
计划（保存/删除/立即执行）、运行（启动/详情/重试/取消）、版本（列表/详情/长期保留/远端列表/找回/补传）、
恢复预览、清理预览与执行、恢复（启动/列表/详情）、夸克能力报告。

### 前端（`app/settings/backups/` + `app/features/backups/`）

「设置 → 云备份」：概览（最近完成、目标状态、当前运行的每目标进度与取消）、备份计划（范围/活动多选/作品筛选/
目标多选/每天每周/时间/保留次数/启用）、备份历史（每版本每目标状态、长期保留、补传到其它目标、
从网盘找回版本、清理预览与确认、恢复预览与恢复方式确认）、网盘与加密（创建仓库并一次性显示恢复密钥、
解锁/锁定/改密、仓库 ID、目标管理、Google/OneDrive 授权、夸克能力报告）。
错误文案区分待解锁、服务忙、登录失效、空间不足、网络中断、源文件缺失、密文校验失败。

### 恢复助手（`scripts/backup-apply-restore.ts`，`npm run backup:apply-restore`）

服务停止后执行文件替换：拒绝无 `--confirm`、拒绝服务仍在运行时执行、
兜底生成恢复前便携备份、替换两个数据库（清理 `-wal/-shm`）、把媒体写回本机媒体目录并重建
`artifacts.local_path` / `note_assets.local_path`，最后提示按平时方式重启。

## 五、网盘能力与限制

| 目标 | 实现情况 | 能力声明 | 本轮验证 |
| --- | --- | --- | --- |
| 本地测试目录 | 已实现 | 可恢复上传、可删除、SHA-256 远端校验、可列举 | 端到端自动验证 |
| Google Drive | 已实现（官方 API + 用户 OAuth + PKCE，默认应用专用目录） | 可恢复上传、可删除、可列举；远端只有 MD5，**不声明**内容校验 | 未联调 |
| OneDrive | 已实现（Graph + 用户授权，应用专用文件夹） | 可恢复上传、可删除、可列举；远端只有 quickXor/sha1，**不声明**内容校验 | 未联调 |
| 夸克网盘 | **未支持**（仅能力核实报告） | 不声明任何能力 | 未联调 |

对上表两行的说明：Google/OneDrive 的「不声明内容校验」意味着大对象上传后按计划只标注「已上传，完整校验待完成」，
恢复时仍执行完整认证解密与明文校验；这是有意为之，不用文件大小冒充字节一致。

## 六、未完成与限制（不得当作已完成）

1. **真实网盘未联调**：没有真实账号，Google Drive / OneDrive 的上传、续传、会话过期重建、下载校验只经过代码与
   结构层验证；真实端到端验证需要在用户授权后用专用目录与小样本执行。
2. **夸克网盘保持未完成**：只有能力核实报告，UI 会明确显示「未完成能力联调」，不提供可用的备份开关。
3. **完整工作区替换是两步操作**：应用只准备，替换由 `npm run backup:apply-restore` 在服务停止后执行；
   没有自动重启服务的机制（按计划不做不可靠的自动重启）。
4. **手动删除单个版本未实现**：当前只能按目标执行保留清理（含长期保留保护）或让版本自然过期；
   历史列表里的「删除该版本」动作没有实现。
5. **维护窗口是应用内协调**：通过写入型请求 503 + 长任务收敛等待实现，不是跨进程写锁；
   捕获期间正在执行的 Worker 回传仍可能落库（已用快照先后顺序与空闲等待缩小窗口，但不是分布式事务）。
6. **对象存在性核对的开销**：每次备份对已有对象仍做一次远端存在性检查（计划要求「本地标记不是唯一事实」），
   对象很多时会让一次增量备份产生较多列举/查询调用。
7. **多设备写仓库**：本期默认一个工作区作为仓库写入与清理者；其它设备只读与恢复，不支持双设备并行写/清理。
8. **未做浏览器点击走查**（原因见第四节）。

## 七、后续建议

1. 拿到真实账号后，用专用目录做小样本联调：授权 → 上传小文件 → 中断后续传 → 删除远端文件后再备份 →
   在另一台机器/另一数据目录恢复，并据此把上面第 1 条的「未联调」改为实测结论。
2. 若要减少增量备份的远端查询开销，可让适配器提供「按目录列举 + 名称映射」，一次列举完成存在性核对。
3. 如确需「删除单个版本」，可复用保留清理的独占对象判断，增加按版本的手工过期入口。

## 八、用户说明

1. **创建加密仓库**：设置 → 云备份 → 网盘与加密 → 输入解锁密码（≥ 8 位）→ 创建。
   页面会**只显示一次**恢复密钥，请立刻复制到密码管理器或纸上；两者都丢失就无法恢复。
2. **连接网盘**：同一个页面的「目标网盘」里选择类型。
   - 本地测试目录：填一个目录即可，用于先跑通流程。
   - Google Drive / OneDrive：填自己申请的 client ID（以及平台要求的 client secret），登记回调地址后点
     「保存并去授权」，在官方页面登录；刷新令牌写入系统凭据库，不会进数据库或日志。
   - 夸克网盘：只有能力核实报告，暂不能用于备份。
3. **设置定时**：备份计划里选范围（完整工作区 / 指定活动 / 创作资料）、目标、每天或每周与时间、保留最近 N 次。
   保存不会立即上传；需要立刻跑一次用「立即执行」或右上角「立即备份」。
4. **看结果**：概览显示每次运行的阶段、本次上传量与每个目标的结果；红色/黄色表示需要处理。
   失败可以只「重试失败目标」，也可以把某个版本「补传到其它目标」。
5. **恢复**：备份历史里选一个版本和目标 → 先看恢复预览（包含哪些活动/资料、媒体数量、缺省项）→
   选择恢复方式：活动默认导入为副本、资料按逻辑包导入（重复导入会跳过）、完整工作区会替换当前数据
   （需要确认，会先生成恢复前备份）。完整工作区替换会在停止服务后执行
   `npm run backup:apply-restore -- --plan <恢复计划文件> --confirm`。
6. **换机**：在旧设备复制仓库 ID；新设备在「网盘与加密」里用「连接已有仓库」填写网盘类型、目录与仓库 ID，
   解锁后在「备份历史 → 从网盘找回版本」里列出并找回需要的版本。
7. **锁定与自动解锁**：可以「立即锁定」；勾选「在这台设备记住」后用系统凭据库自动解锁。
   未解锁时定时任务只会记录「等待解锁」，解锁后补做一次，不会改用明文。

## 九、备份格式说明与独立恢复入口

远端布局（逻辑布局，各平台用各自的对象 ID 落地）：

```text
SthStart/<vaultId>/
  objects/vault.json                # 格式版本 + scrypt 参数 + 被包裹的主密钥（无明文主密钥/恢复密钥）
  objects/<不透明对象键>.bin         # 独立加密的不可变文件对象（键由仓库命名子密钥派生，不泄露明文 hash）
  snapshots/<snapshotId>.bin        # 加密的完整恢复清单，最后一次发布；发布后才可恢复
```

文件封装（`STHBAK01`）：`8 字节魔数 + 4 字节头部长度 + 头部 JSON + 1 字节 nonce 长度 + nonce + 密文正文 + 16 字节标签`。
头部 JSON 含格式版本、仓库 ID、对象 ID 与被包裹的文件密钥；AAD 绑定「仓库 + 对象」身份，
因此换机时读取头部即可认出对象身份并解密（身份被认证保护，改动头部会导致解包失败）。

独立恢复入口：

- **活动 / 资料 / 预览**：由应用服务执行，不需要旧设备的本地文件。
- **完整工作区替换**：`npm run backup:apply-restore -- --plan <apply-restore.json> --confirm`。
  该命令在服务停止后运行，会拒绝在没有 `--confirm` 或服务仍在运行时执行，先兜底生成恢复前便携备份，
  再替换数据库、写回媒体并把本机路径重建，最后提示按平时方式重启服务。
  也就是说，即使只剩密文与恢复计划，也不必依赖旧数据库才能把数据放回原位。
