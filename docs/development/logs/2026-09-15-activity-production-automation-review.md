## 2. 本轮直接修复的问题

### 批次能创建、能恢复，并保留生成依据

- 原批次编译提示词没有提供执行计划，实际派发会失败；现在创建时冻结执行计划、提示词配方、编译结果和 seed。
- 保存配方自带事务，嵌套在批次事务中会报错；现在由外层统一提交，原单图入口仍保留独立事务。
- 根据槽位配置或活动角色快照获取参考图，校验文件和工作流输入，按文生图/图生图用途派发；保存参考图来源。
- 同一幂等键的不同请求会被拒绝；在途槽位不能重复创建。已创建任务但批次关联没有写回时，会按稳定键找回已有 attempt。
- 查询批次同步公共任务和实际输出；修复进度重复计数，以及任务状态未变但错误码变化时不更新的问题。
- 重试创建新的批次项，保留原 attempt 和重试关系；结果未知不会自动重发。重启后继续未派发项，已派发项交给原 Generation Core 恢复机制。
- 页面先提交真实图像配置修订，不再使用不存在的 `default` 修订；若内容草稿尚未保存为采用版本，会明确提示。

### 采用内容与媒体时保护用户选择

- 直接保存草稿、生成、局部改写及采用候选共用锁定校验，补上原先仅检查“是否删除”而允许改写正文的漏洞。
- 新候选保存输入指纹；目标内容或人设依据变化后拒绝覆盖。重复采用已采用候选不重复追加。
- 批量采用先检查所有候选，禁止同一阶段的竞争候选同时写入，在一个事务内提交。
- 媒体采用以槽位补丁合并，未选择的槽位保留；采用成功后再更新页面。指纹由服务端计算，旧来源生成的新选择会被拒绝。
- 媒体画廊现在支持每槽位选择一张，再一次采用所有选择；失败保留选择，便于调整。
- 生产概览以采用版本计算已有内容，不再把未采用草稿当成生产完成；已有记录时不会因历史备用候选一直停在“审阅候选”。

### 任务、模板与交付

- 研究与企划任务原查询使用不存在的 `s.title`，被静默吞掉；改为读取会话表单标题。
- 修正话题库、企划会话、文本任务和媒体批次跳转；补齐任务接口的现有管理员凭据检查。
- 继续文本任务时从原快照恢复，跳过已成功阶段并把其结果带入后续上下文；增加页面继续按钮和阶段勾选。
- “我的模板”不再只填写标题、类型和地点：阶段说明、职责与规则会进入企划，修改或删除原模板不会改变已经冻结的会话。
- 保存模板时不再把所有角色塞进每个阶段；当前默认按角色选择顺序映射职责，寿星优先映射到 `lead`，不足的职责采用现有回退。此行为不等于已完成手动映射向导。
- 导出依据实际 MIME 类型/扩展名打包媒体，阅读器同步使用对应路径；正在引用的媒体缺失时阻止生成看似完整的包。
- 便携备份增加 `note_assets` 附件，使用实际文件大小；恢复之前校验清单、数据库及文件哈希，按数据库用途恢复到当前配置路径，更新附件路径。
- 更正备份说明：不包含系统钥匙串，但数据库中的普通配置仍会保留，不能笼统宣称“所有 API 密钥均已排除”。恢复实际站点前需要停止服务。
