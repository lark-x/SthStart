# 2026-08-28：Cloudflare 远程性能与笔记本地优先同步

状态：已完成基础实现，真实远程长期验收延后  
关联事项：FIX-003（已完成）、FIX-006（已完成）、VAL-013、VAL-014  
关联提交：待提交

## 本轮目标

- 降低 Cloudflare 高延迟对页面切换、笔记输入和保存的影响。
- 保留 Cloudflare Tunnel 与 Access，不降低远程鉴权强度。
- 让文本、链接和图片先在浏览器本机可靠保存，再由后台合并同步到 Mac。

## 已完成

- 首次管理会话由最多三次请求减少为两次，创建响应直接返回 CSRF Token。
- Portal BFF 增加会话、公共服务和 Portal 总耗时的 `Server-Timing`。
- 主要应用和设置入口支持空闲、悬停与触摸预取；全局 Query 缓存调整为远程友好策略。
- Notebook 增加数据库 revision 和客户端 UUID 幂等 Upsert，旧创建与更新接口保持兼容。
- Notebook 编辑器使用 IndexedDB 保存本机草稿、同步队列和未上传图片，文本约 300ms 本机落盘，网络同步约 1.5 秒合并触发。
- Notebook 安装独立离线应用壳，只在当前设备缓存笔记页面所需的哈希静态资源和已访问图片，使断网重开后仍能读取 IndexedDB 草稿。
- 保存成功直接更新列表与详情缓存，不再追加列表和详情重新请求。
- 图片先显示本机 Blob，后台以二进制流上传；服务端使用临时文件、大小计数和原子落盘，保留旧 Base64 JSON 兼容。
- 控制中心增加远程性能诊断；新增 `npm run doctor:remote` 和 Cloudflare 代理直连、静态缓存、协议比较说明。
- 运行时与浏览器端到端测试改用动态或独立端口，不再接管用户已经启动的本地服务。

## 重要决策

- 继续只使用 Cloudflare，不引入 Tailscale。
- 多设备冲突采用最后抵达服务器的保存覆盖，不生成冲突副本。
- Cloudflare 只允许缓存 `/_next/static/*`，私有 HTML、RSC、API 和图片不得使用 Cache Everything。
- 浏览器本地待同步图片总量限制为 100MB，单图继续限制为 8MB；未同步数据不能被自动清理。

## 已知限制与待办

- 中国大陆到 Cloudflare 边缘节点的冷启动仍受公网质量限制；本地优先保证编辑不被阻塞，但不能把首次打开变成局域网速度。
- 真实手机运营商网络和多设备长期交替编辑分别登记为 VAL-013、VAL-014。
- Notebook 图片仍使用独立 `note_assets`，尚未迁移到中央 Artifact，继续关联 DEV-007。
