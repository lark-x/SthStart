## 结论

三轮的主要模块已经实现：资料属性、资料/叙事联合检索、企划引用、搜集定义与执行历史、待整理、整理草稿、推荐与补查、来源更新检查、活动回流及工程导出。实现具备个人项目使用基础，但原先“全部勾选”不能代表交互与数据链路没有问题。

本次发现并修复了影响实际使用的缺陷。验收保持个人项目标准，以资料不漏、历史引用不漂移、正常生成可采用为重点。

## 已修复

| 问题 | 修复结果 |
| --- | --- |
| 实际笔记入口使用 NotebookWorkspace，新增筛选却只接在另一个列表组件 | 实际页面增加作品、角色、用途、资料性质、内容分类；搜索与分页走服务端 |
| 本地缓存会把其他筛选结果/页的已同步笔记重新混入列表 | 联网时只合并尚未同步的本地变更；没有服务端数据时保留缓存兜底 |
| 周任务被按日任务计算，执行结束又覆盖成每日时间 | 创建、修改、恢复、调度、执行结束统一使用目标时区和星期计算 |
| 改变定时时间仍沿用旧的 nextRunAt | 日程配置变化后重算；无来源的定义维持暂停 |
| 保存派生引用快照会增加企划版本，刚生成的候选立即变成过期 | 派生快照以版本条件保存，不增加用户输入版本；发生并发修改时给出冲突 |
| 模型看到正文却没有可回填的引用 ID | 提示词中的每条正文附带真实引用 ID；没有资料时也清理虚构 ID |
| 刷新企划后没有恢复已选资料，选择旧内容也只保留短摘要 | 恢复选项及冻结引用；新选择先预览，生成使用确认的快照；删除来源后旧快照仍能使用 |
| 删除全部引用后仍可能残留旧快照 | 生成时清除派生快照；采用候选优先使用对应任务的依据，不能回退混入其他任务的新依据 |
| 截断后的摘要 hash 与实际文本不一致，更新检查容易误报 | 分开记录实际引用文本 hash 和完整来源 hash |
| 更新检查只有“保留旧内容”，缺少有效的单条更新操作 | 增加“使用新内容”，只刷新被选择的引用，不更改旧活动 |
| 搜集引用指向旧版本 ID，永远检查不到后续版本 | 按来源身份找最近检查的版本，返回可明确采用的新版本 ID |
| 导入工程的源 ID 可能与本地资料碰撞 | 导入引用标记为外部来源，更新检查不能借用本地同 ID 内容；仍保留快照和证据 |
| 模型未整理或合并的原始搜集结果不进入待整理 | 每条搜到并保存的原始来源均保留执行关联与待整理入口，模型遗漏不再吞结果 |
| 不同 MCP 提供方的同名文档键混在一起 | 无 URL 文档的去重及来源身份包含提供方；重试整理保留提供方信息 |
| 未确认来源被直接标记为社区解读或原作定论 | 没有明确来源性质时保持“未确认”；AI 整理的新资料同样默认未确认、仅记录 |
| 整理采用后失去原始版本定位，作品和角色标签丢失 | 保存 sourceVersionId，资料属性可展开查看当时原文，并继承已有的作品/角色标签 |
| 整理采用中的正文、元数据和草稿状态分多步提交 | 使用一个本地事务，失败则整体回滚，保留原有并发编辑检测 |
| 推荐只考虑最近 400 条，主题匹配可能绕过作品约束 | 在可参考范围内评分，明确属于其他作品的资料先排除 |

## 验证与回归

- 服务端整套回归：278 项通过。包含活动企划、搜集、资料、导出与原有功能。
- 最后一处标签继承调整后，资料库与日历企划定向回归：36 项通过；全项目类型检查再次通过。
- 契约测试：16 项通过。
- 门户工具测试：10 项通过。
- 全项目类型检查通过；服务端和门户生产构建通过。
- 新增浏览器场景通过：实际 `/apps/notebook` 入口，先缓存不同作品的资料，再按作品和角色筛选，正文关键词搜索，最后检查窄屏入口。
- 浏览器使用独立的 `/tmp` 测试数据库、叙事库和资产目录，测试资料清理，不访问个人生产数据库。
- 相关代码静态检查无错误；企划组件有一条原有的 useMemo 依赖稳定性提示，不影响这次流程。

新增或加强的关键回归包括：

1. 周日执行、当天时间已过、上海时区跨 UTC 日期。
2. 不同 MCP 的同文档键不合并。
3. 截断摘要 hash、提示词引用 ID、来源更新及来源删除后的冻结引用。
4. 导入时本地相同 ID 仍存在，也不能误绑定。
5. 带资料生成的候选版本与当前企划版本一致。
6. 模型遗漏第二条来源时仍交付两条；重试、部分失败和多任务引用不重复复制来源。
7. 整理后保留来源版本定位与作品标签。

## 仍需如实保留的边界

- 本次未调用真实 MCP、真实模型，也没有评价原神等真实资料的准确性；已有自动化搜集使用模拟服务。
- 浏览器验证覆盖本次修改的实际入口，没有重新执行完整的两场活动人工对照，也没有验证“完全断网编辑后重连同步”的整条交互。
- 规范化 JSON 叙事导入仍是当前明确支持的批量导入路径，不代表已完成任意网站全量知识库导入。
- 已提供本地原文版本查看；真实外部文档的逐行深链接取决于来源提供的定位信息，不能把本地行号当作远端行号。
- 整理采用保持“新建/追加”两种方式，暂不增加替换指定正文块的编辑器能力。
- 定时任务依赖后端进程运行；后端停机期间不会执行，恢复后每个定义最多补跑一次。这是当前产品行为，不是桌面系统级定时器。

这些边界不阻碍个人项目先使用核心流程；后续优先用一组真实来源走通“首次积累 → 再次复用 → 只补查缺口”，再按实际使用问题补充。
