# 话题素材库与活动点子开发方案

日期：2026-09-14  
用途：交给其他模型执行。项目供个人使用，优先完成简单、可用的完整流程。

## 1. 目标与范围

目标：后台定时搜集关注作品的新梗、近期讨论、角色话题等，保存到独立页面。用户新增活动时直接选择已经积累的素材，让 AI 生成活动点子，再接入现有企划流程。

完整路径：

**定时搜集 → 话题素材库 → 勾选素材 → 生成三个点子 → 选中一个 → 带入活动企划。**

明确区别：

- 搜集不依赖用户打开页面，也不依赖某场活动。
- 定时阶段只生成摘要、分类和适合改编的方向，不提前生成完整点子或剧本。
- 点子生成发生在用户选中素材之后，允许组合多个话题和跨作品联动。
- 已有企划继续负责人物关系研究、缺失人设补齐、详细阶段安排和正式创建活动。

第一版不做全网爬虫、平台账号登录、通知推送、热度曲线、复杂订阅规则、自动发布或自动创建活动。

## 2. 当前基础与复用要求

当前仓库已存在 MCP 服务配置、MCP 客户端、活动研究任务和四步企划向导，其中一些文件仍为未提交改动。执行前先确认最新状态，保留已有工作，不重新实现或覆盖这些模块。

重点参考：

- `apps/service/src/mcp/`：服务配置、客户端、资料研究及来源记录。
- `app/features/activities/components/planning-wizard.tsx`：新建活动向导与待补人设流程。
- `apps/service/src/activities/planning.ts`：企划会话、任务、候选与创建活动。

实现原则：

- 复用 MCP 配置和凭据，不另做一套服务地址、密钥表单。
- 复用文本模型调用方式；本功能使用活动工作室绑定的文本模型，不新增模型配置页面。
- 话题搜集单独建任务，不强行调用必须提供主角和活动会话的现有角色研究接口；只抽取可复用的检索、工具参数生成和文本处理能力。
- 保持现有设计变量、页面容器、卡片、筛选、侧栏、按钮样式，不重新设计门户或邻舍。

## 3. 页面与用户流程

### 3.1 独立页面：话题素材库

新增路由 `/apps/inspiration`，在门户应用入口和活动列表页面提供入口。

页面从上到下：

1. 标题“话题素材库”，右侧“立即补采”“自动搜集设置”。
2. 一行状态：自动搜集是否开启、最近成功时间、下次执行时间、最近新增数量。
3. 筛选：关键词、作品多选、内容类型、时间范围；视图切换“全部 / 收藏 / 已使用 / 已忽略”。
4. 话题卡片列表，每页 24 条，后端筛选与分页。
5. 有勾选时，底部出现已选素材条和“生成活动点子”按钮。

默认展示最近 30 天收集或更新的素材，隐藏已忽略内容，按最新发现排序。收藏视图默认不限时间。不要把发布时间未知的旧内容标为刚发生。

内容类型固定四类：

- 新梗与趣味讨论。
- 角色相关话题。
- 新剧情与版本动态。
- 节日、纪念日与活动契机。

每张卡片显示：

- 标题、所属作品、内容类型。
- 约 80～150 字的解释，让没见过这个梗的人也能理解。
- 最多三个改编方向标签，如厨艺比赛、误会喜剧、旅行聚会。
- 信息属性：官方信息、社区讨论、未证实消息或不明来源；能判断时才标注。
- 来源发布时间、收集时间、来源数量；发布时间缺失时显示“发布时间未知”。
- 勾选、收藏、忽略、查看详情。

“查看详情”打开右侧栏，展示完整说明、涉及角色、多个来源链接及简短摘录、相关改编方向。不在卡片列表铺开全部原文。

收藏与已使用可以同时存在。已使用状态来自关联的正式活动，不因生成过点子就标记已使用。忽略可以恢复，后续搜到同一话题不能自动取消忽略。

### 3.2 自动搜集设置

使用页面内弹窗或侧栏，不新建复杂的任务管理中心。

| 配置 | 默认与行为 |
| --- | --- |
| 自动搜集 | 首次未配置时关闭；选好来源和关注内容后可开启 |
| 关注作品 | 多选已有作品，复用作品目录和别名 |
| 额外关键词 | 可选，逗号分隔，如料理梗、角色互动 |
| 信息来源 | 从现有已启用 MCP 中选择 |
| 搜集时间 | 每天一次，默认北京时间 09:00，可修改时刻 |
| 每轮新增上限 | 默认 20 条；高级选项允许 10、20、50 |

第一版只支持每天固定时间，暂不增加复杂周期表达式。

每个来源选择一个已允许调用的搜索工具；需要读取原文时，可再选一个读取工具。只有一个适用工具时自动选中，否则用工具下拉框选择。工具参数优先复用现有适配器；通用工具由现有文本模型按发现的输入结构生成参数，不让用户手写 JSON。

提示文字必须简短明确：“请选择能够检索近期网页或社区信息的资料源；剧情资料库不一定包含新梗。”不能因为 MCP 连接成功，就宣称它能提供近期热点。

保存设置后显示下次执行时间；如素材库为空，提供“现在采集第一批”按钮，不在保存时偷偷启动额外搜集。

### 3.3 从素材生成点子

素材库支持跨页勾选，最多选五条，页面建议一次选择 1～3 条。

点击“生成活动点子”后，在同页打开点子工作区，显示：

- 已选素材，可移除。
- 可选要求输入框，例如“用这几个梗给芙宁娜办一场聚会”。
- 可选活动主角，复用已有角色选择器。
- “生成三个点子”按钮。

默认生成三份有明显区别的点子，内容包括：

- 点子名称和一句话概述。
- 对所选素材的改编方式。
- 推荐参与人物及所属作品，简要说明推荐理由。
- 建议地点、活动风格。
- 两三个阶段的简短构思。
- 预期可留下的聊天、朋友圈或拍照桥段。

此处不生成完整聊天、图片或视频。跨作品人物的关系写成创作安排，不冒充原作事实。无法从素材证实的设定标为建议，不需要虚构可信度评分。

三个点子可以在玩法、参与者或地点上不同，不允许只是标题换词。“再来三个”新增一批候选，保留前一批，刷新后仍可查看。

每个点子提供“用这个点子创建活动”。第一版不做复杂点子收藏系统，话题收藏和可恢复的点子批次已经足够。

### 3.4 与新建活动衔接

新建活动向导第一步增加“从话题素材找灵感”。点击打开素材选择侧栏，复用素材库的筛选与卡片，不触发新的搜集。

两处入口调用同一个点子生成接口。活动内生成点子时，把已填写的主角、活动类型和要求一并传入。

采用点子后的行为：

- 从素材库进入：建立一份企划会话，跳转到新建活动页面并带上会话 ID，回到第一步检查活动意图。
- 从已有新建活动表单进入：先展示将填入的标题、主题和要求，再由“应用这个点子”完成填入；保留已有主角和日期，不覆盖非空输入，另提供明确的“替换标题与主题”选项。
- 保存结构化的点子与素材快照，不只拼成一段用户提示词。
- 推荐人物作为候选提示，不自动成为必选，不立即创建公共角色。匹配到多张本地人设时仍由用户选择；未匹配人物复用现有待补人设流程。
- 初步阶段作为企划生成参考，不直接采用为正式活动剧本。
- 后续用户可以继续 MCP 研究，也可以跳过研究进行企划生成。
- 详细企划生成必须读取所选点子和素材解释，避免带入之后又生成一份无关方案。

正式创建活动后，保留点子、素材摘要和来源快照，在活动信息中提供“灵感来源”。复用现有企划依据导出方式，把这些文本资料纳入活动包。

## 4. 后台与数据设计

### 4.1 定时搜集

在现有 Node 服务内增加轻量调度器，不引入 Redis、独立队列服务或操作系统 cron。

- 服务启动后运行，定期检查数据库里的下次执行时间，例如每分钟检查一次。
- 浏览器关闭不影响执行；电脑关机或后端停止时不能执行。
- 恢复运行后若已错过计划时间，只补采一次最近七天的信息，再计算下次执行时间，不逐次补跑历史任务。
- 每轮统一搜索最近七天；结果按来源、链接和话题去重，避免维护复杂的增量游标。
- 定时和手动补采共用同一任务入口。已有搜集任务运行时返回该任务，不再启动一份。
- 保存任务状态、开始结束时间、新增/合并/失败数量及简短错误；页面轮询即可，不必新增实时推送协议。
- 进程重启后将未结束任务标记为中断，清理其运行占用，再按规则补采；停止服务时清理定时器。

时间以设置中的固定时区解释，默认 Asia/Shanghai，不随部署机器的系统时区改变。

### 4.2 搜集处理流程

1. 按关注作品、别名和额外关键词生成有限的搜索请求。
2. 通过已配置的 MCP 获取近期结果；必要时补读关键原文。
3. 提取标题、URL、日期和可用正文。没有正文时保留“信息不足”，不要补写不存在的事实。
4. 先做链接去重，再让模型对本批及近七天相关条目做保守的话题归并。
5. 生成摘要、分类、涉及作品/角色和改编方向标签。
6. 更新素材库与执行记录。

去重约定：相同标准化 URL 更新已有来源；同一事件的多条报道合并来源；只有同名角色或相似标题时不自动合并。URL 只去掉明确的跟踪参数，不删除可能用于定位内容的参数。保留首次收集时间和最近发现时间。

每轮最多同时访问两个来源、最多调用 12 次工具；沿用 MCP 单次超时，整轮预算默认 180 秒。数量上限统计新增话题，合并已有来源不占新增名额。

来源部分失败时保存其余结果并标记“部分完成”；全部失败时明确显示失败。某次模型整理失败，保留已获取的原始候选供重试，不必重新搜索。第一版只提供“重试上次失败任务”，不做复杂自动重试策略。

### 4.3 最小数据结构

采用现有 SQLite 迁移机制，新增少量表；以下为逻辑对象，不要求引入额外存储系统。

| 对象 | 主要字段 |
| --- | --- |
| 搜集设置 | enabled、works、keywords、source/tool bindings、dailyTime、timezone、nextRunAt、maxNewTopics |
| 搜集任务 | 状态、触发方式、配置快照、起止时间、原始候选、结果统计、错误摘要 |
| 话题素材 | 标题、摘要、作品/角色、类型、信息属性、改编标签、首次/最近发现时间、收藏/忽略标记 |
| 话题来源 | topicId、MCP 来源 ID、URL/文档定位、标题、发布时间、摘录、内容哈希 |
| 点子批次 | 输入素材快照、用户要求、主角引用、模型信息、任务状态、候选点子、关联企划/活动 |

素材列表分页返回摘要，不携带完整原始检索结果。原始搜集候选只保留最近 30 天；话题、收藏、已采用点子和活动依据不随任务记录清理而删除。

建议在公共合同中增加 Topic、TopicSource、TopicCollectionSettings、TopicCollectionRun、ActivityIdeaBatch 类型，并为企划表单增加可选 inspiration 字段。该字段包含 ideaId 和使用时的素材/点子快照；旧会话缺失该字段时按原逻辑运行。

### 4.4 接口范围

复用项目现有 admin API 风格，新增以下能力即可：

- `GET /topics`：搜索、筛选、分页、数量。
- `GET /topics/:id`：详情和来源。
- `PATCH /topics/:id`：收藏、忽略与恢复。
- `GET/PUT /topic-collection/settings`：读取和保存搜集设置。
- `POST /topic-collection/runs`、`GET /topic-collection/runs/:id`：启动补采、查询进度；另提供最近记录列表与失败重试。
- `POST /activity-idea-batches`、`GET /activity-idea-batches/:id`：生成三个点子、读取结果。
- `POST /activity-idea-batches/:id/ideas/:ideaId/apply`：创建或更新目标企划会话，返回会话 ID；重复应用同一请求不创建重复会话。

以上路径均由现有服务路由前缀和门户代理承接。复用现有认证、凭据和错误展示机制，无需另建权限体系。

## 5. 实施顺序与交付

### 阶段一：先让素材积累起来

实现数据表、搜集设置、任务记录和 MCP 搜集整理；手动补采与定时调用同一个入口。验证关闭浏览器后服务仍能按计划执行。

### 阶段二：完成素材库页面

实现独立入口、卡片、筛选、详情、收藏/忽略、跨页勾选、设置弹窗和采集状态。没有素材时引导配置来源，不填充伪造热点。

### 阶段三：点子与活动衔接

实现点子批次、三个差异化方向、历史批次恢复；复用选择组件接入新建活动；保证正式企划读取素材依据，正式活动保存来源。

### 仅做必要验证

- 搜集时间计算、错过后补采、重复点击不并行启动、同一素材重复收集不重复入库。
- 来源失败或整理失败有可恢复结果；不把失败当成没有新内容。
- 完成一次“选择素材 → 三个点子 → 采用 → 企划 → 创建活动”的实际流程，刷新后能恢复。
- 检查桌面与窄屏的列表、详情、选择条和按钮可用，运行类型检查与构建。不要求大规模截图回归或外部来源全覆盖测试。

最终交付：可用功能、数据库迁移、简短配置说明、实际验证结果与明确剩余项。未完成的功能不要标记为完成；不要擅自覆盖工作区其他模型的改动或修改邻舍。
