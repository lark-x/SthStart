## 1. 产品边界和总体路径

### 1.1 必做需求

1. 手动开始与每天/每周定时备份。
2. 增量上传图片、视频及附件，每次备份仍有完整恢复清单。
3. Google Drive、OneDrive、夸克三个目标的接入工作；夸克先做能力核实，真实限制如实披露。
4. 一份备份可保存到一个或多个目标，各目标独立成功、失败和重试。
5. 上传前加密媒体、数据库和备份清单，恢复时解密校验。
6. 完整工作区、指定活动、创作资料三种备份范围。
7. 备份历史、单目标恢复、历史保留、共享对象清理。
8. 接入任务中心和日志，补足任务关联、历史读取及周期轮转。

### 1.2 明确不做

- 文件变更后实时同步，或每次保存立即上传。
- 多台电脑同时编辑、双向冲突合并。
- 直接同步正在运行的 SQLite/WAL/SHM 文件。
- 云端媒体直链替代本地资产路径，边下载边解密在线播放。
- 自动上传分享链接、公开发布作品、跨网盘公开分享。
- 网盘自动扩容、计费系统、企业权限或集群任务平台。
- 全盘加密、全文加密搜索、自定义密码学算法。
- 块级差分、跨用户去重、透明本地空间释放。本期按文件增量足够。

### 1.3 用户路径

```text
设置 → 云备份
  → 创建加密仓库并保存恢复密钥
  → 连接目标网盘
  → 设置范围、频率与保留规则
  → 立即备份 / 到时自动执行
  → 查看各目标结果

备份历史
  → 选择版本和一个完整目标
  → 下载并验证
  → 解锁、预览
  → 恢复为活动副本 / 导入资料 / 恢复工作区
```

所有备份及恢复都由本项目后端执行，不依赖当前 Codex 会话、插件或桌面任务自动化。网盘登录在应用自己的设置流程中完成。

## 3. 备份范围与恢复语义

### 3.1 完整工作区

包括业务数据库、叙事数据库及其登记的必要文件。保留角色、人设版本、活动、笔记、来源、提示词、生成追溯、配置与创作记录。

默认完整模式保留数据库可达的媒体，包括历史版本仍然引用的候选，排除无引用临时文件、缓存、备份暂存目录和备份自身。

不要在完整数据库仍引用某个历史媒体时悄悄省略它，然后声称可以完整恢复。若提供“仅当前采用媒体”选项，应称为精简备份，生成明确缺省清单，并让恢复后的历史候选显示未包含文件。可优先把该选项用于活动范围，完整工作区先保证完整性。

恢复语义：恢复整个工作区，需要停写和关闭数据库连接。先生成本地恢复前备份，不自动与当前数据库合并。

### 3.2 指定活动

选择一项或多项活动，保留当前工程需要的内容、角色快照、采用媒体、参考图、提示词来源、引用快照、回放配置及现有 project 导出覆盖的历史。

- 复用活动工程的内容编译与导入规则。
- 为保持媒体增量，不把整个工程 ZIP 当成唯一对象每次重传。应枚举工程 entries，元数据和媒体分别入对象仓库；恢复时可重组为现有工程包。
- 导出代码若将大媒体全部读进内存，增加文件引用/流式枚举路径，不为了备份整批视频而使用巨大 Buffer。
- 临时上传但未登记或尚在写入的文件不算完成资产。

恢复语义：默认导入为新活动，保留当前活动。工程已包含的冻结角色和资料不强制覆盖全局角色库或知识库。

### 3.3 创作资料

第三阶段完成独立范围：角色库、人设版本及参考图、创作资料、来源/引用/附件，以及所选叙事资料。可以选择全部资料或按作品筛选。

- 使用版本化逻辑包，仅导出选定业务数据及必要依赖，不把完整业务数据库夹带为“资料备份”。
- 有关联但未选中的跨作品原文，保存本次必要摘录或列为必要依赖；不能导出断链后仍标完整。
- 导入不做双向同步：首次导入新对象，相同备份重复导入可识别并跳过；已有同名对象默认新建或由用户选择，不静默覆盖。
- 角色、笔记、附件和来源 ID 按实际导入映射，作品+名称只用于建议匹配，不作为唯一身份。
- 若相关资料库功能尚未完成，按实际已实现内容备份并明确范围，不伪造不存在的表或字段。

### 3.4 凭据与任务状态

- 不备份 `.env`、系统钥匙串、云授权令牌、原始恢复密钥或明文解锁密码。
- 审核数据库中的 runtime_imports、配置 JSON、授权信息和临时上传会话，只在快照副本内清理实际敏感字段，绝不修改源数据库。
- 保留模型、工作流和资料源的非秘密配置，恢复后显示需重新连接的项。
- 运行中生成、搜集、上传任务恢复为中断/待处理，不恢复后立即自动重跑。
- 恢复工作区后，定时备份计划默认暂停，目标要求重新验证，避免旧数据库自动向错误账号写入或清理历史。
- 系统调试日志不属于默认创作备份范围；备份历史属于业务记录，但当前执行不能被错误恢复为仍在运行。

## 4. 增量仓库格式：文件只保存一次，版本清单完整

### 4.1 概念

一个加密仓库有稳定 `vaultId`，可以复制到多个目标。一个备份版本有稳定 `snapshotId`，对应某次冻结的内容。运行记录 `runId` 用于进度和重试，三者不要混用。

建议远端布局：

```text
SthStart/<vaultId>/
  vault.json                   # 格式、密码派生参数、被包裹的主密钥；无明文主密钥
  objects/<opaqueId>.bin        # 独立加密的不可变文件对象
  snapshots/<snapshotId>.bin    # 加密的完整恢复清单，最后发布
```

路径是逻辑布局；Google 使用文件 ID、OneDrive 使用 driveItem ID，适配器要解决实际存储映射，不依赖所有平台都支持路径唯一或原子重命名。

### 4.2 完整清单

解密后的清单至少包含：格式版本、仓库 ID、版本 ID、来源设备 ID、创建时间、范围及包含/排除选项、应用及数据库 schema 版本、业务描述、对象数组。

对象条目至少有逻辑相对路径、资源种类/ID、明文 SHA-256/大小、密文 SHA-256/大小、远端不透明对象键和必要引用信息。真实标题、文件名、提示词和资源关联只放在加密清单内。

清单必须包含本次恢复所需的全部对象，不能只列“比上次多了什么”。恢复某个版本不依赖其他版本清单，也不依赖源设备的本地索引。

### 4.3 文件去重

- 数据库每次制作完整文件快照，可压缩后加密；不做数据库页级增量。
- 媒体以实际内容 SHA-256 判定变化，不仅根据文件名和修改时间。
- 同一仓库相同内容复用一个已产生的密文对象；跨仓库不做去重。
- 远端对象名用随机映射或仓库内带密钥的 HMAC 派生，避免直接暴露明文文件 hash 和原始文件名。
- 本地对象索引记录同一内容对应的密文与加密头。已有密文应直接复用，不为每个备份/目标重新随机加密后覆盖同名对象。
- 原本的密文缓存丢失但云端仍有对象时，从有效副本重新获取/校验，或创建新对象身份；不能让旧清单中的密文 hash 失效。
- 生成中的可变文件不得登记为可复用对象。冻结文件被发现变化时重新捕获或让本次失败。

### 4.4 多目标提交

每个目标独立执行：

1. 确认仓库身份和加密头一致，绑定账号及根目录。
2. 列举/检查所需对象，缺失的上传，已存在的核对。
3. 完成所有对象的验证。
4. 最后上传完整加密清单并确认可读取。
5. 将该目标标为完成。

- 半成品清单不能出现在可恢复列表；临时清单使用单独名称，不把“正在上传”当成可恢复版本。
- 新增目标需要补齐该版本所有对象，不能引用另一个网盘上的文件。
- 一次运行可显示部分完成，例如 Google 完成、OneDrive 失败；保留成功目标。
- 重试同一目标使用原 snapshot 和对象，不重新捕获此刻已经变化的工作区。
- 用户在网盘删除/替换了文件，下一次检查发现后重新上传；本地 uploaded 标记不能作为唯一事实。
- 只要一个目标的完整副本和解锁材料还在，新电脑就能恢复。

## 5. 加密、密码与自动解锁

### 5.1 采用成熟原语

建议使用 Node.js `crypto` 的 AES-256-GCM 与 scrypt / HKDF，实现版本化文件封装；也可以采用经过核实、适合流式文件的成熟库，不自行设计加密算法。

- 仓库生成随机 256 位主密钥，密码不直接作为文件加密密钥。
- 密码通过 scrypt 和随机 salt 生成包裹密钥，参数随仓库头保存并校验上限。
- 主密钥分别派生数据加密、对象命名等不同用途的子密钥，不复用同一密钥执行所有用途。
- 每个新对象使用独立随机文件密钥及唯一随机 nonce，文件密钥由仓库密钥认证加密包裹；使用可靠随机源。
- 文件头记录格式版本、算法、nonce、包裹的文件密钥等必要信息，认证关联数据绑定仓库及对象身份。
- 不得为了稳定密文或断点续传固定/复用 nonce。续传必须使用已冻结的同一个密文文件字节。
- 解密先写临时文件，通过认证标签和内容校验后再供导入使用；标签不匹配、文件截断、密码错误都不能接受部分明文。
- 所有视频流式处理，不一次读入内存；本期不要求边解密边播放。

### 5.2 仓库解锁

- 创建仓库时设置密码，并生成高熵恢复密钥；恢复密钥提供第二份独立的主密钥包裹材料。
- 仓库头可公开保存 salt、KDF 参数和加密后的主密钥，不能含原始主密钥或恢复密钥。
- 首次设置显示恢复密钥并让用户保存，提供简短提示即可，不设计繁琐企业审批流程。
- 提供“仅本次解锁”“在此设备记住”。记住时使用既有 SecretStore，数据库只存凭据引用。
- 无可用钥匙串/文件密钥后端时，不能悄悄写明文密码，显示只能手动解锁或配置已有凭据后端。
- 定时到点但未解锁：记录等待解锁，不改用明文、不每分钟生成一条新失败记录。解锁后补做一次。
- 用户主动锁定后不再启动新加密/恢复任务。正在进行的上传可以完成已冻结密文，界面说明实际行为。

### 5.3 密码修改与能力边界

- 支持修改密码时重新包裹主密钥，主密钥未变化则无需重传全部媒体。
- 多目标分别记录仓库头更新结果；未成功目标标明仍需更新，不能宣称所有目标已换密码。
- 历史仓库头可能仍可被旧密码解锁，修改密码不等于撤销旧副本访问。泄露后的完整主密钥轮换不列入本期默认流程。
- 密码和恢复密钥都遗失时无法恢复；文案只需准确告知这一点。
- 本功能只加密云端/导出的备份；不声称本地媒体、模型输入或整个硬盘被加密。
- 云端仍可见密文大小、数量和时间。原始文件名、标题和清单内容不明文上传。

## 6. 快照一致性与暂存

### 6.1 最小可行的一致捕获

完整备份必须建立协调的维护窗口：

1. 调度器暂停启动新的业务写入任务，备份进入“等待当前写入完成”。
2. 让正在执行的请求和后台写入到达明确的安全点；不能只拦前端按钮。
3. 在维护窗口中阻止用户写入、后台调度、Worker 回传落库、导入、资产删除/GC 等会影响所选范围的操作。
4. 制作两个数据库快照，冻结对应资源清单，把所需文件复制/可靠固定到暂存区。
5. 释放维护窗口，恢复正常创作；之后的加密、网络上传不占用业务写入窗口。

先用可证明一致的复制方案。大量文件时可能需要较长暂存时间，界面如实显示，不承诺固定几秒。只有明确保证资产写后不可变、删除受 pin 保护时，才可用 hardlink/reflink 或先固定后复制缩短窗口。

### 6.2 等待与失败

- 对长时间运行任务可选择等待其完成后再捕获，不能自动取消用户的生图/搜集任务来抢快照。
- 等待达到配置预算后，本次显示延后/未完成并解除暂停，保留上次成功备份。调度不无限阻止正常创作。
- 捕获函数使用 try/finally 解锁；异常和重启后不能让项目永久停在维护模式。
- 维护期间用户保存收到可理解的稍后重试响应，保留前端草稿。
- 暂存前检查空间，失败保留清晰原因；备份目录必须排除自身与正在上传的缓存。
- 扫描发现必要文件缺失，列明文件与引用来源，本版本不能标“完整”。允许保留诊断信息，不继续伪装成功。
- 如初期仅完成停止服务的本地捕获，可用于阶段内开发验证，但第二阶段定时备份验收必须有应用可控的协调捕获路径。

## 7. 网盘适配器与接入策略

### 7.1 公共能力

使用有明确职责的适配器，不增加巨型存储框架。接口至少覆盖：连接状态、定位仓库、列出清单、检查对象、可恢复上传、下载、删除能力探测、配额/错误解释。

调用返回结构化结果，不让业务层依赖 CLI 输出文本或某个平台的文件对象。能力可包含 `resumableUpload`、`delete`、`remoteChecksum`、`list` 等。

- 上传检查按账号/drive/root/vault/object 组合记录，切账号或切目录不能继承之前的成功状态。
- 上传会话 URL 可能本身带授权，按秘密处理并保存过期时间，不写日志或导出普通数据库。
- 同名文件在不同网盘语义不同；检查真实 ID，不通过名称相同推断内容正确。
- 网络失败、授权过期、空间不足分别展示，有限重试加退避，凭据错误不无限重试。
- UI 使用普通中文；无需暴露 OAuth scope、块大小或文件 ID。

### 7.2 Google Drive

- 使用官方 Drive API 与用户 OAuth，个人应用可由用户配置自己的 client ID；不要提供虚构的公共 client secret。
- 优先使用应用创建的专用目录和适当 `drive.file` 权限，按官方接口验证授权范围。
- 支持可恢复上传会话、断点检查和过期会话重新创建。
- 大文件分片对齐按官方文档设置。Google 当前文档要求除最后一片之外使用 256 KiB 的倍数。
- 文件名不唯一，保持远端 ID 映射；上传回执丢失时查询对象再重试，避免大量重复副本。
- 正式接入前核对 OAuth 发布/测试状态和授权持续时间，避免定时任务依赖很快失效的授权而没有提示。

来源：[上传说明](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[权限范围](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)。

### 7.3 OneDrive

- 使用 Microsoft Graph 和用户授权，优先应用专用文件夹；个人项目不要求组织管理员后台权限。
- 实际验证目标个人/工作账号支持的权限组合，不只根据文档字段假定账号能访问。
- 大文件使用上传会话，持久化到期时间和已确认偏移，恢复上传或重建会话。
- 分片顺序及对齐按 Graph 要求；与 Google 的分片参数分开配置，不能共用一个写死值。
- 更新/冲突策略不能覆盖未知文件，仓库对象按不可变身份保存。

来源：[应用文件夹](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder)、[上传会话](https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession?view=graph-rest-1.0)。

### 7.4 夸克网盘

当前查到名为“夸克网盘官方 Skill”的仓库，其文档描述 OAuth、CLI、存储/下载/备份能力；并注明无删除命令、原生 Windows 不支持（使用 WSL）。这些是文档信息，不代表已经验证为可用于本项目的稳定后台 API。

先做一个小范围接入验证，记录：

1. 授权能否被非交互后端复用、刷新和检测失效。
2. 是否能列目录、上传、下载，能否获得稳定文件 ID 和机器可读结果。
3. 大文件上传、重试和断点恢复的实际能力。
4. 是否支持删除；不支持就不能伪造清理成功。
5. 当前系统环境能否调用，包括 Windows / WSL 差异。

适合时以 CLI 适配器调用确定命令，使用参数数组，避免 shell 拼接；不依赖每次由 AI 对话执行备份。若找到更合适的公开正式 API，可替换适配器并记录文档。

若没有可恢复上传，允许此目标显示“中断后重新上传当前文件”，已完成文件仍复用；不影响 Google/OneDrive 的续传能力。

若没有删除，允许加密备份和恢复，但自动清理仅标记逻辑过期、保留远端文件，并提示需在网盘端清理。不要因此引入逆向 Cookie 接口作为无说明替代。

若连必要的上传、列举、下载都无法稳定实现，应交付能力验证报告、明确未支持，不做一个看似可用的按钮。夸克目标保持未完成，不能以模拟适配器冒充三网盘全部可用；Google/OneDrive 的其他工作继续完成。

来源：[夸克仓库说明](https://github.com/quark-clouddrive/quarkclouddrive_offical/blob/main/README.md)。以上接口信息核对日期为 2026-09-16，开发时重新确认。

### 7.5 上传验证级别

- 必须确认服务端最终完成回执、文件存在和大小。
- 有远端内容校验值时，用对应算法校验密文；不要把 ETag、QuickXorHash、MD5、SHA-256 混为一谈。
- 无可信内容校验值时，通过下载并计算密文 hash 完成验证，或明确显示“已上传，完整校验待完成”。不能用文件大小宣称字节完全一致。
- 清单仅在所需对象达到完整验证要求后发布；已验证的未变对象可以复用验证结果，但检查远端身份/版本是否变化。
- 记录验证方式；恢复时仍执行完整认证解密和明文校验。

## 8. 调度、执行状态与数据结构

### 8.1 建议表/对象

| 对象 | 关键内容 |
| --- | --- |
| backup_vaults | 仓库 ID、格式版本、包裹密钥头、本机凭据引用、解锁策略 |
| backup_targets | 类型、账号标识、远端根、仓库 ID、凭据引用、能力和连接状态 |
| backup_plans | 名称、范围、目标集合、频率、时区、下次时间、启停、保留规则 |
| backup_runs | 计划及配置快照、触发方式、快照 ID、阶段、进度、错误、起止时间 |
| backup_snapshots | 冻结清单、本地暂存、范围、保留标记、格式版本 |
| backup_objects | 明文内容身份、密文身份/校验、大小、本地密文路径、固定状态 |
| backup_target_runs / objects | 每目标状态、上传回执、远端 ID、验证状态、续传凭据引用 |
| backup_restore_runs | 来源目标/版本、下载验证进度、恢复方式、恢复前备份位置、结果 |

可按实现合并表，但不能仅用一个全局 `uploaded=true` 表达多个目标。

### 8.2 状态与执行顺序

运行阶段建议：等待 → 等待解锁/空闲 → 创建快照 → 加密 → 上传 → 验证 → 完成/部分完成/失败/取消。

- 任务中心记录真实执行，定时计划本身不长期占用“运行中”。
- 默认同一工作区一次捕获、同一计划一次运行。多目标最多小并发（例如 2），不新增分布式队列。
- 保存计划默认不立即上传，提供明确“保存并立即备份”。
- 每天/每周按用户时区计算，默认 `Asia/Shanghai`；每天指定时间，每周指定星期和时间。
- 后端启动检查漏执行，每个计划最多补一次。重复 tick、重复点击、服务重启不能并行捕获同一计划。
- 改计划只影响未来执行，当前任务使用配置快照。
- 重试目标继续原版本；“重新备份当前内容”才创建新版本。
- 暂停计划不等于取消当前任务；取消停止安排新上传，保留已成功目标和可续传状态。
- 重启后恢复或标记中断，不能一直显示运行中；仍有完整冻结密文时可继续上传，没有时重新捕获并生成新 snapshot ID。
- 删除/禁用一个目标不删除其云端数据，也不影响其他目标。

## 9. 前端页面与交互

建议新增 `/settings/backups`，显示名称“云备份”，沿用现有设置布局与组件。

### 9.1 概览与设置

```text
云备份                          [立即备份]
最近完成：今天 03:12              2 个目标完成，1 个需要处理

[备份计划] [备份历史] [网盘与加密]
```

网盘卡显示账号、连接状态、目录概述、可用能力、重新连接/断开。加密卡显示已锁定/已解锁、记住本机、修改密码和恢复密钥管理，不在页面常驻显示密钥。

计划表单：范围、活动/作品选择（按范围显示）、目标多选、每天/每周、时间、保留最近 N 次。高级字段收起，不暴露密文算法和分片参数。

### 9.2 备份历史

每行显示日期、范围、逻辑内容大小、本次实际上传量、目标状态、是否长期保留。

- 区分总内容体积和本次上传量，不把复用字节算成上传流量。
- 多目标上传流量可分别显示，避免三份副本显示成一份费用/流量。
- 操作：查看详情、重试失败目标、补到其他目标、验证、恢复、长期保留、删除该版本。
- 不完整版本可以查看错误，不能以“正常恢复”入口误导用户。

### 9.3 运行详情

显示当前阶段和每目标文件/字节进度，可跳转关联日志。上传速度可选，不要求复杂图表或精确剩余时间。

错误文案区分：待解锁、服务忙稍后备份、登录失效、空间不足、网络中断、源文件缺失、密文校验失败。

### 9.4 恢复预览

- 选择版本后列出包含的活动/角色/资料、媒体数量、时间、缺省项及应用版本要求。
- 下载与验证不修改当前数据。
- 活动默认恢复为副本；资料默认导入；完整工作区明确提示将替换当前数据。
- 完整替换提供一次明确确认和恢复前备份，不为每个文件重复确认。
- 在新设备提供“连接已有仓库”，可以从远端列清单重建历史，不依赖旧数据库。
- 长流程在服务端执行，刷新页面可以继续查看。

## 10. 恢复实现与保留清理

### 10.1 恢复闭环

1. 获取仓库头，密码或恢复密钥解锁。
2. 列出并读取完整清单，确认格式版本和范围。
3. 下载到隔离暂存目录，验证密文、认证解密、验证明文。
4. 检查清单路径、数据库完整性、必要引用和支持的 schema。
5. 生成预览；用户选择恢复方式并确认。
6. 执行活动/资料导入，或停写关闭数据库后恢复整个工作区。
7. 重建本地媒体路径，迁移到当前支持版本，标记授权需重新连接。
8. 报告恢复结果，保留恢复前备份。

- 不下载完就直接逐个覆盖正在运行的数据库。
- 完整工作区建议用现有 CLI 演进出的独立恢复助手：应用生成已校验恢复任务，后端进入维护并关闭所有数据库连接，由助手执行文件替换和重启流程；使用系统已有启动方式，不重复启动多个服务。
- 不能可靠自动重启的环境提供明确的恢复命令/重启提示，不能显示恢复成功但服务仍使用旧连接。
- 两个数据库或文件替换中途失败，应能通过恢复前副本回到可启动状态。个人项目可用明确的回滚步骤，不必实现复杂分布式事务。
- 备份格式高于本应用支持版本时拒绝替换并提示升级；不能强行向旧 schema 导入。
- 普通解密认证失败和空间不足不触碰当前工作区。

### 10.2 保留与对象清理

- 默认建议保留最近 10 次该计划在该目标上成功的版本，可调整；长期保留版本不参与自动淘汰。
- 保留按目标计算，失败的新版本不能让该目标上一份成功版本过期。
- 清理引用集合必须覆盖同一目标/仓库所有保留版本、所有计划和仍在上传的对象，不能只检查本次计划。
- 先使过期版本退出可恢复集合，再清理不再被任何保留清单引用的对象；适配器无原子目录操作时使用明确清理状态和幂等重试。
- 并发上传/恢复期间避免清理相关对象；采用仓库内简单锁或 pin 即可。
- 远端清单读取不全、解密失败、分页未完成时停止物理清理，不能把未知对象当垃圾。
- 本期默认一个工作区作为仓库写入与清理者。其他电脑可恢复/读；接管前明确暂停原写入者，不支持双设备并行清理。
- 无删除能力的网盘显示“历史保留，需手动清理”；不要把释放空间计为成功。
- 解锁后展示清理预览：删几个版本、多少独占对象、预计释放空间。定时规则可自动执行已经保存的保留策略，无需每次再次确认。
- 本地缓存清理不删除未完成上传所需密文；远端故障也不能连带删除本地原作。

## 11. 日志与任务中心必要补强

### 11.1 复用现有日志

不新增 ELK、Prometheus 等平台。扩展现有 LogEvent 的可选上下文：`taskId/runId`、`snapshotId`、`targetId`、`phase`、`errorCode`。旧事件缺少字段仍可读取。

- INFO：任务开始、快照完成、目标完成、恢复完成。
- WARN：部分失败、等待解锁、授权需更新、延后、缺失资源。
- ERROR：捕获/加密/上传/校验/恢复失败。
- 不逐字节写进度日志，进度存任务状态；日志记录阶段转换和必要摘要。

备份历史以数据库为准，不能解析日志推断哪些版本可恢复。日志被清理后仍能恢复备份。

### 11.2 历史读取与轮转

- 保留实时 SSE，同时增加磁盘 JSONL 日志的分页历史查询，可按任务、级别和时间筛选。
- 现有内存数字 ID 重启会复用，新增跨进程唯一事件 ID 或以启动会话+序号为游标；前端去重兼容旧日志。
- 避免一次读取全部日志文件到内存；有界读取即可，不要求新建大型日志数据库。
- 定期按大小和保留时间轮转清理，与写入链串行协调，避免删除仍在写入文件。
- 服务退出时尽力 flush 写入队列，并清理定时器和监听器。
- 实时流断开重连可补最近遗漏记录，不能仅显示重连后的新事件。
- 详情页“查看日志”打开对应任务筛选；下载只导出所选范围的已脱敏日志。

### 11.3 必须避免记录的内容

密码、恢复密钥、主密钥、OAuth token、Cookie、授权码、上传会话 URL、签名下载 URL 不写入日志。优先从源头不写，而不是依赖正则事后掩盖。

现有敏感诊断开关也不能允许写出上述秘密；原始 SDK/CLI 错误需转换后再记录。标题、文件路径等按现有脱敏习惯处理，不新增企业级审计要求。

## 15. 文件与接口组织建议

新增服务模块可放在 `apps/service/src/backup/`：

- `store.ts`、`contracts`（公共类型仍从实际 contracts 入口导出）。
- `capture.ts`、`manifest.ts`、`objects.ts`：范围枚举、快照与增量。
- `crypto.ts`、`vault.ts`：版本化加密封装和凭据关联。
- `runner.ts`、`scheduler.ts`：手动/定时共用执行。
- `restore.ts`、`retention.ts`：恢复与版本清理。
- `providers/google-drive.ts`、`onedrive.ts`、`quark.ts`、`local-test.ts`。
- `routes.ts`：账号、仓库、计划、任务、历史和恢复 API。

前端建议 `app/features/backups/` 与 `app/settings/backups/`，复用卡片、表单、确认弹层和任务组件。

接口按现有管理 API 约定设计，建议包含：

| 资源 | 操作 |
| --- | --- |
| vault | 创建、连接已有、解锁、锁定、记住本机、修改密码 |
| targets | 列表、授权开始/回调、连接验证、断开、能力 |
| plans | 保存、修改、暂停、立即执行 |
| runs | 状态、取消、重试指定目标、关联日志 |
| snapshots | 列表、远端发现、详情、验证、补传、保留、删除 |
| restores | 创建下载验证任务、预览、确认执行、结果 |

OAuth 回调使用实际部署方式匹配的 redirect URI 和 state；本地公共客户端按官方流程使用 PKCE 等机制，不在代码或日志硬编码真实凭据。

所有长任务返回任务 ID 后在服务端继续，刷新页面不取消。与现有 TypeBox 校验、查询缓存、错误处理方式保持一致。

## 16. 必要验证、交付与完成判定

### 16.1 验证范围

写少量有价值的自动测试：加密认证失败、文件增量、完整清单重建、多目标独立提交、定时防重复、共享文件保留清理、恢复前不覆盖当前数据。

日志至少验证跨重启历史、轮转后查询和秘密不出现在记录中。无需对每个 UI 字段、每个小函数单独写测试，不要求覆盖率数字。

Google/OneDrive 通过适配器模拟验证逻辑后，有账号条件再用小样本真实上传下载；夸克额外记录实际 CLI/API 版本及能力。不以真实 GPU 或大规模素材作为验收前提。

适用现有命令：

```sh
npm run typecheck
npm run test:contracts
npm run test --workspace @sthstart/service
npm run build
```

开发时先跑受影响测试，完成后运行适用检查。浏览器只需主桌面路径和一次窄屏走查。不要求压力测试、企业 SLA、多账号矩阵或渗透测试。
