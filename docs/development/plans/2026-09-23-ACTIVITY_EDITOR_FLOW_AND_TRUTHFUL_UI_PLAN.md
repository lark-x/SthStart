# 活动编辑工作台：流程收敛与真实能力修复实施方案

状态：待执行；制定于 2026-09-23。适用流程：Sol 制定 → Luna 执行 → Sol 对照任务编号验收。

## 1. 目标、边界与当前事实

### 用户目标

让活动编辑页形成一条可理解、可验证的路径：**基础企划 → 剧情创作 → 视觉素材（可跳过）→ 回放预览 → 导出**。用户能明确知道“草稿已保存”和“内容已形成版本”的区别，AI 入口不重复，配置的作用范围透明，页面不声称未接通的能力。保留现有活动数据和已可用的高级功能。

### 本轮明确不做

- 不引入前端框架，不重新制作整个站点的设计系统，不改活动列表/创建向导。
- 不实现新的云端绘图适配器、真正的图生图或视频生成，不新建 MCP 检索服务；这些能力尚未接通时从活动编辑页移除/隐藏相应入口，而不是伪装成功。
- 不更改数据库表结构、不批量重写用户旧活动、不删除旧字段或历史版本。不改变生成候选的既有服务端采纳语义。
- 不默认运行全仓库测试、全量 E2E、性能测试或真实付费模型调用。

## 2. 产品与实现决策（执行模型无需重新选择）

1. 工作台采用五步导航。进入“回放”或“导出”前沿用 `prepareContent` 的草稿落盘/提交版本逻辑；纯文本活动允许预览和导出。既有 `tab=settings|content|records|media|playback|export` 链接继续可用。
2. 文本 AI 的**唯一常驻入口是右侧 AI 面板**。常用生成在右侧执行；复杂的整场生成、规划、局部重写可由右侧“高级生成”打开已有弹窗。分镜图像生成属于不同操作，保留在镜头/素材上下文中。右侧候选只做状态摘要与“审阅”入口，真正采用统一走现有候选差异审阅流程。
3. 模型选择保持**应用级绑定**，不新建活动级/单次覆盖的服务端配置。UI 明示“修改后影响所有活动”；取消伪 `scope.model/profileId`，展示真实绑定状态，切换失败回滚并显示错误。
4. 本轮不接通 MCP 检索。保留已有数据字段，但活动编辑页移除模拟知识预览、固定背景文案以及“自动执行 MCP”承诺。仍可编辑并使用真正接入提示词的阶段主旨、系统提示词微调。旧 `mcpQuery/mcpSourceIds` 数据保持不变、暂不呈现为可用开关。
5. 单分镜生成只提供真实 ComfyUI **文生图**。隐藏云端 API、假图生图/重绘、视频选项；后端在无引擎/失败/超时及不支持的视频请求时返回明确错误，不创建模拟产物。批量素材流程不因本决定删除。
6. 运行时以 `document.scenes` 为分镜编辑主源，旧 `stage.scenes` 作为兼容读取/镜像。**不做数据库迁移**；已有两处内容不一致时按下面 T1 的规则合并，不能静默丢弃旧媒体引用。

## 3. 分项实施任务

### T0 — 基线与范围确认

- **范围**：只读记录相关文件当前状态；确认下列任务涉及路径仍存在，记录原有未提交改动、测试/截图运行环境。不要对既有改动做恢复或清理。
- **验收**：交付记录能区分“执行前已有”与“本轮修改”；若发现与方案互斥的新实现，先停下受影响任务，其他独立任务继续。
- **验证**：只读检查，不运行测试。

### T1 — 分镜场次单一编辑主源与安全回写（先于 T2、T7）

- **主要文件**：`app/features/activities/components/scene-beat-editor.tsx`、`activity-studio-workspace.tsx`、`stage-rail-nav.tsx`、`apps/service/src/activities/comfy-runner.ts`；可新增一个活动域内的纯函数帮助文件及靶向测试。
- **行为**：统一按阶段 ID 从 `document.scenes` 读取；若该阶段在顶层无场次，回退旧 `stage.scenes`。两边同 ID 冲突时，文本/排序以顶层为准，但顶层分镜没有媒体 URL/类型而旧嵌套分镜有时补齐媒体字段。不要把其他阶段的场次混入当前阶段。编辑/新增/删除只走一个受控更新函数，然后同步生成嵌套镜像，避免各按钮独立维护两套数组。计数和导轨状态使用同一有效场次集合。
- **生成回写**：请求前先 flush 当前草稿，保证服务端读取到本轮分镜文字；服务端编译提示词从同一有效场次查找。单分镜生成成功后返回素材，不再直接 `UPDATE activity_drafts` 绕开草稿版本。前端将返回 URL 合并到**最新**草稿状态并按草稿保存队列持久化；生成期间用户改了文字时不能用点击时的旧文档整体覆盖。目标分镜已删除则提示“素材已生成但未绑定”，不复活分镜。
- **边界**：不修改 TypeBox 文档结构、不批量规范化旧记录、不删除 `stage.scenes`；其他服务端消费者仍可读兼容镜像。冲突字段除上述媒体补齐外不自动覆盖。
- **验收**：旧文档仅有嵌套场次、仅有顶层场次、两边都有且部分媒体不同，均能正确显示、编辑并再次打开；新增/删改不产生重复场次；用户在生图等待期间编辑台词不会被结果覆盖。
- **最小验证**：新增/调整有效场次与合并更新的纯函数测试；模拟一次生成结果回写并检查草稿版本与文字保留。若触及服务端存储，跑相应单个活动测试文件，不跑全仓库。

### T2 — 新建内容与状态文案真实化（依赖 T1）

- **主要文件**：`activity-studio-workspace.tsx`、`scene-beat-editor.tsx`、`stage-rail-nav.tsx`。
- **行为**：新增幕只建立标题/排序/参与者等必要结构；地点可继承本活动已填的真实地点，其余说明用空值与表单 placeholder，不自动填入雪山、营地、时间、环境或动作故事。新增场可以有空白分镜以便编辑，但动作/台词/结果留空。没有任何幕时中间画布显示“新建第一幕”的空状态，不能把 `undefined` 阶段交给分镜编辑器。旧活动的现有文字原样保留。分幕导轨将“已成片”改为准确的“分镜配图齐全”或计数；0 场/0 镜要显示 0，不用 `|| 1` 伪造数量。
- **边界**：不清洗用户已有的示例文本；不将仅有图片 URL 的阶段判为已导出。
- **验收**：在任意活动新增幕/场，不会生成不相关剧情；无幕与空阶段均显示可操作的空状态且不报错；分镜 0/部分/全部有图时状态与真实数量一致。
- **验证**：有效场次/状态纯函数测试 + 一次手动页面检查。

### T3 — 单分镜生图只展示且执行真实能力（依赖 T1）

- **主要文件**：`scene-beat-editor.tsx`、`apps/service/src/activities/comfy-runner.ts`、`routes.ts`；可能复用现有生成状态/错误组件。
- **行为**：镜头检查器只展示 ComfyUI 引擎、真实 checkpoint、提示词与受支持的文生图参数；去掉云端 API、图生图强度和视频生成的假入口。未选到可用引擎/模型时阻止提交并给出配置链接。后端不再用模拟 SVG 当成功产物；ComfyUI 不可用、任务无输出或超时要保留原媒体引用并返回可理解的错误，不能写入活动素材库。收到 `mediaType='video'` 时显式拒绝，不把图片冒充视频。
- **边界**：不增加云端 API、工作流编排或视频服务；不动活动其他批量生图与上传功能。为兼容旧调用，可保留请求契约里的可选字段，但不能宣称已支持。
- **验收**：真实 ComfyUI 成功时产生可访问图片并绑定正确分镜；断开 ComfyUI 时页面显示失败、分镜无新 URL、无模拟素材；不支持的模式得到明确错误。
- **验证**：对 `comfy-runner` 做模拟网络的成功/失败靶向测试（不可依赖真实 GPU）；必要时运行 `apps/service/src/activities-images.test.ts` 中相关测试。

### T4 — 文本模型与知识上下文的作用范围透明化（可与 T3 独立）

- **主要文件**：`activity-studio-workspace.tsx`、`records-editor.tsx`；若抽取模型选择组件，放活动域组件目录。
- **行为**：右侧模型区域标“所有活动的默认文本模型”，切换前说明作用范围；可选项仅列已启用且具备文本能力的模型，当前就绪状态以实际应用绑定为准。切换失败恢复原选项并显示可见错误，不只写 console。生成按钮依实际 `appLlmStatus.text.ready` 启用；移除无效的 `scope.model/profileId` 参数。删除固定雪山知识切片、模拟“检索中/检索结果”和“自动执行 MCP”文案；阶段配置仅展示已被 `buildStagePrompt` 使用的主旨及系统提示词覆盖，旧 MCP 字段只保留在文档里，不主动删除。
- **边界**：不改变公共服务路由数据模型，不接入 MCP 网络调用，不隐式切换全局模型。保留企划向导及其他页面已有的 MCP 功能。
- **验收**：切换模型后另一个活动看到同一应用绑定；错误时选择器不虚假停在新值；没配模型时不能发起生成；页面无假 MCP 检索结果，旧阶段字段仍在保存后的文档中。
- **验证**：模型选择成功/失败状态的轻量测试或组件交互检查；已有阶段文本生成靶向测试保证 `stagePremise/systemPromptOverride` 仍传入提示词。

### T5 — 文本生成入口和候选审阅收敛（依赖 T4）

- **主要文件**：`activity-studio-workspace.tsx`、`records-editor.tsx`、`scene-beat-editor.tsx`、`generation-modal.tsx`、`use-activity-generation.ts`、`candidate-review-panel.tsx`。
- **行为**：移除剧情页标题、记录内部和分镜场次上重复的**文本**生成按钮；保留镜头生图等不同动作。右侧 AI 面板统一显示当前幕、目标（“本幕剧情/续写对话/朋友圈文案/配图描述”）、指令、生成状态、失败与候选数。把目前误称“场次分镜流”的 `shot`、误称“阶段大纲”的 `stage` 改为与服务端实际产物对应的文案。右侧提供唯一“生成”按钮及“高级生成”入口；高级弹窗保留整场、规划、局部重写等模式。
- **任务/候选状态**：工作台与高级弹窗共享一个当前文本任务 ID/轮询源；URL `jobId` 可恢复指定任务，但打开弹窗不能悄悄切到最新历史任务。候选摘要点击后进入已有差异审阅组件；采纳成功才清空当前任务并刷新草稿/活动，失败保留候选与错误。不允许一处“一键采纳”、另一处“逐项审阅”导致语义不同；处理锁定/冲突沿用服务端规则。删除没有可见开关却可能定时发请求的 `autoContinue` 定时逻辑；不自动消耗模型调用。
- **边界**：不改生成模式的后端含义或候选数据结构，不自动采纳，不把生图与文本任务混成同一任务。共享状态实现可等价重构，但必须可恢复任务并防止同屏重复发起。
- **验收**：在对话/朋友圈/分镜三个视图中，同屏只有右侧文本生成入口；一次生成只创建一个任务；不同入口打开高级弹窗时上下文幕正确；结果可逐项比较、采纳或保留；失败/锁定时不丢候选；页面停留 40 秒不会自动发新任务。
- **验证**：一个针对单任务状态/候选采纳的靶向交互测试（如现有测试设施适用），及含两个阶段的手动页面流程；不调用真实付费模型，可用已有模拟/测试数据。

### T6 — 恢复回放与导出前一致性检查（依赖 T1；可在 T5 后联调）

- **主要文件**：`activity-studio-workspace.tsx`、`playback-workstation.tsx`、`export-panel.tsx`、`apps/service/src/activities/routes.ts`、`exports.ts`，必要时调整活动查询失效处理。
- **行为**：五步导航中加入“4. 回放预览”，导出改为第五步；`tab=playback` 进入回放。回放前先 `prepareContent`，向现有 `PlaybackWorkstation` 传入当前内容/回放版本。复用自动编排、播放、调整、保存能力。无媒体版本时，用 `mediaRevisionId='none'` 和空绑定完成纯文本预览；预览路由不得因没有媒体版本直接 409。内容/媒体版本改变后，已有回放若不匹配则标“需重新编排”，不能静默播放旧内容。
- **导出**：导出页显示所选格式与当前内容/媒体/回放版本状态；对过期回放明确提示。服务端导出只使用与当前内容/媒体匹配的回放版本，不匹配时按当前版本自动编排并在 UI 告知用户；不能默默打包旧时间线。已有无回放版本的导出能力保留，纯文本活动可导出。UI 不宣称下载的是现成 MP4，明确视频工程需要后续本地渲染。
- **边界**：沿用现有回放与 ZIP 服务，不新建播放器/导出格式，不要求先配图才能预览，不自动覆盖用户保存的旧回放版本。
- **验收**：有媒体与无媒体活动均能进入回放、播放、保存；从旧 `tab=playback` 链接正确定位；编辑内容后再次进入提示重编排；导出包使用当前内容且没有旧回放混入。
- **验证**：`node --import tsx/esm --test apps/service/src/activity-playback-export.test.ts` 的相关用例；补“无媒体预览”和“旧回放不被导出”案例，页面手动检查一次。

### T7 — 导航、响应式与文案收敛（依赖 T2、T5、T6）

- **主要文件**：`activity-studio-workspace.tsx`、`records-editor.tsx`、`stage-rail-nav.tsx`、`scripts/take_screenshot.mjs`；必要时修改活动域样式。
- **布局**：保留工作台嵌入模式和固定视口。桌面左分幕/中编辑/右 AI 各自独立滚动；在中等宽度优先收起左导轨/右 AI；窄屏提供一直可见的五步切换与打开分幕/AI 的入口，不让 `hidden md:flex` 把主导航直接消失。中间主内容和对话正文宽度优先，避免三栏挤成窄字列。标题/正文及辅助字级按项目 token 与可读性规则调整，减少 `text-[10px]` 常驻信息。
- **交互**：剧情内容标签只保留工作台的一排，`RecordsEditor` 在嵌入模式不再重复渲染标签/阶段选择；独立使用该组件的其他入口仍保留其导航。`Ctrl/Meta+Enter` 仅在右侧提示词输入焦点内触发当前合法生成，运行中、无模型、无阶段时不触发；若保留快捷键提示，必须实际可用。移除未展示的“下一步”死计算/导入，或者在有真实动作时接入，不保留无用状态。
- **截图脚本**：更新旧活动标题、MCP 按钮和硬编码外部截图目录假设；截图写入工作区可见位置。至少能取桌面与窄屏画面，截图中实际展示当前活动工作台，而不是列表或错误页。
- **边界**：不改 AppShell 的全站布局，不引入新框架，不以隐藏功能代替移动端可达性。
- **验收**：1440 宽桌面、约 768 宽中屏、约 390 宽窄屏均可进入五步、切换幕、打开 AI；没有全局横向滚动或侧栏拉伸；长对话可阅读；同屏无重复文本生成/内容标签；截图可查看。
- **验证**：遵守 `app/AGENTS.md` 和 `frontend-ui-standards`：按现有 SOP 运行一次 `npm run deploy:docker` 同步环境，再运行 `node scripts/take_screenshot.mjs` 并实际查看截图；必要时仅加一个导航/快捷键靶向交互检查。若 Docker/浏览器环境不可用，如实记录并补静态检查，不能声称视觉验收通过。

### T8 — 集成收尾与交接（依赖 T1–T7）

- **范围**：检查空活动、旧活动、无模型、ComfyUI 不可用、无媒体、有媒体、生成候选冲突六类路径；检查 `git diff` 不包含无关文件或数据迁移。
- **验收**：T1–T7 每项可标“完成/部分/未完成”，有实际证据；五步主路径贯通；本轮未实现的云端 API、图生图、视频、MCP 检索不再显示为可用；没有新数据库表/依赖。
- **最小验证**：完成后运行一次 `npm run typecheck`；只运行 T3/T6 指定的相关服务单测及新增的纯函数/交互测试；UI 截图按 T7。无需默认运行 `npm run ci:core`、全量 E2E 或真实模型/GPU 调用。测试失败要记录具体错误，不把环境失败写成通过。

## 4. 任务依赖与执行顺序

`T0 → T1 → T2/T3 → T4 → T5 → T6 → T7 → T8`。T4 可与 T1–T3 独立进行；T6 的回放入口可先开发，但最终联调必须在 T1 的场次来源稳定后进行。每项完成后进行该项最小验证，不等到最后才发现跨模块不一致。

## 5. 执行者决策权限与停止条件

- **可自行决定**：活动域内组件/纯函数的拆分、等价状态管理写法、符合本方案的细小视觉尺寸、相关测试文件落点；对当前代码小幅漂移做同目标适配，记录原因。
- **必须暂停受影响任务并向用户确认**：需要数据库迁移或删除旧字段、接入新云端模型/MCP 服务、引入新前端框架、改变候选采纳语义、批量改写旧活动、需要清理他人未提交改动，或现有回放/导出架构无法在本边界内支持纯文本。其余独立任务可继续。
- 不用为了“测试全绿”扩大到无关模块；发现非本轮缺陷，记录并留给 Sol 验收判断。任何真实付费生成、外部部署、数据清理均不由此方案自动授权。

## 6. 回退与交付格式

本轮不涉及表结构迁移，回退重点是代码和草稿内容。执行者不得用硬重置清理工作树；修改前保留既有用户改动。分镜兼容读取和镜像写入须在新旧文档共存期间保留，避免回退版本读不到场次。删除模拟输出时不删除历史素材记录。

交付给 Sol 时按下表填写真实情况，不接受一句“已完成”：

| 任务 | 状态（完成/部分/未完成） | 实际修改文件 | 验收证据/测试结果 | 偏差与剩余风险 |
| --- | --- | --- | --- | --- |
| T0–T8 | 逐项列出 | 仅本轮触及 | 命令结果、截图、行为 | 无则写“无” |

Sol 验收重点：逐项核对本方案的可观察验收条件，尤其确认**没有假生成成功、没有旧内容覆盖、没有过期回放混入导出、窄屏主导航可达**；报告通过/部分/未完成和必须补做项，不凭执行者自述认定完成。
