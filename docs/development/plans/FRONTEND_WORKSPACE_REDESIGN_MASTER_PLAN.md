# SthStart 全站前端重设计与统一工作台实施计划

日期：2026-09-12  
状态：规划完成，待实施。  
交付范围：Markdown 设计与实施方案；本轮没有修改业务页面、安装依赖、部署网站或更新截图基线。  
目标：交给后续开发模型执行，完成全站布局、视觉与交互的统一重设计。

## 0. 核心决策

**将 SthStart 从分散的应用入口与各自布局的页面，改造成统一的个人创作工作台。**

采用一个全站应用外框、四类页面模板和一套视觉规则。首页围绕继续工作；角色页围绕浏览与编辑；活动和创作页围绕内容生产；设置围绕配置诊断。不同页面使用相同的导航、标题、工具栏、表面层次和操作语言，同时保留各自适合的内容布局。

此次重设计的明确决定：

1. 桌面使用持久左导航，页面内不再重复放全局应用切换和主题开关。
2. 默认主题采用中性浅灰背景、白色工作表面、深墨色文字和少量朱橙强调；现有暖色模式作为可选主题保留。
3. 工作界面使用统一无衬线字体；衬线字体仅可用于用户主动选择的长文阅读或作品展示。
4. 统一列表、工作台、阅读、配置四种布局；页头、边距、面板、辅助栏和滚动行为均有明确规则。
5. 优先显示内容、当前对象和主操作，减少欢迎文案、装饰英文、重复入口、边框套边框和无数据的巨大空面板。
6. 保留现有 React / Vinext / Tailwind 与状态、表单体系。默认不换运行框架；若交互基础确有缺口，可按需引入一个无样式组件库。
7. 已完成的人设 V2、导航注册表、弹层管理、保存状态和错误状态继续使用；此次重做页面构图和设计表达，不回退业务实现。
8. 全站改造须包含逐页结果与实际浏览器验收，不能以改了 theme.css 或截图基线全部更新替代完成证明。

## 2. 设计方向与视觉构图

### 2.1 视觉方向：清晰、安静、以作品为中心

采用“浅色创作桌面”的视觉方向：外框稳定，内容区域明亮，人物头像和生成作品承担主要视觉吸引力。品牌色用于主动作和当前位置，不把整张 AI 面板、每个入口、每条状态都染成橙色。

三个贯穿全站的视觉识别点：

- 左侧导航保持固定节奏，选中项使用浅橙背景和清楚的文字，不靠大面积色块。
- 主工作区是一块清晰的内容表面，组内靠标题、间距和细分隔线组织，减少嵌套卡片。
- 角色和媒体使用真实已有图片，文本与控件克制，让创作内容成为主角；无图片时用统一占位，不批量生成装饰图填空。

### 2.2 必须停止的视觉做法

- 工作页首屏的大号口号、英文眉题和重复产品介绍。
- 同一屏每个区块都有独立背景、粗边框、阴影和大圆角。
- 标题、按钮、Tab、输入框分别选择不同字体和形状。
- 为“填满屏幕”把短表单撑成两米宽，或为空列表保留整屏高度。
- 把低对比灰字当成干净，把缩小所有字体当成高密度。
- 用全局 !important 和针对页面名字的深层选择器修补共享组件。
- 标注“未配置”的黄色面板、正常 AI 面板和真正错误面板外观相近。
- 悬浮工具栏或手机吸底按钮遮挡输入区、键盘焦点及最后一项内容。

## 3. 信息架构与全站导航

### 3.1 导航结构

从现有 navigation.tsx 派生导航，保留 URL 与路由 ID。显示名称可简化，命令面板关键词保留原名称，避免旧用户找不到入口。

```text
SthStart
  工作台                 /

创作
  活动                   /apps/activities
  图像与视频             /apps/creative
  角色                   /apps/characters
  日历                   /apps/calendar

资料
  笔记                   /apps/notebook
  叙事档案               /apps/narrative

应用
  邻舍                   /apps/linshe

设置
  模型与公共服务         /settings/public-services
  生成配置               /settings/generation
  运行与日志             /settings/control-center

底部
  主题切换 · 命令入口
```

“设置”分组默认可折叠；进入设置路由时展开并显示当前位置。所有原有能力都可到达，不新建替代旧配置路径的第二套设置页。

### 3.2 全站外框

- AppShell 负责导航、页面区域和全局浮层挂载，不持有活动、角色或笔记业务草稿。
- PageHeader 只负责标题、面包屑/返回、对象状态、当前页面动作。
- 每个页面一个 h1、一个主内容 main landmark；迁移时清理页面原有 main，避免与外框嵌套。
- 子页返回优先恢复列表的筛选、分页与滚动位置；不能统一硬跳回首页。
- 不在每个业务页同时出现左导航、应用切换器、门户快捷入口和多个“返回首页”。
- 全局命令入口复用现有命令面板，不承诺新增跨所有内容的全文搜索。
- 邻舍嵌入模式使用精简外框，保留退出/返回；媒体全屏与专注阅读可暂时收起导航，并可明确退出。

### 3.3 1440px 桌面基础骨架

```text
┌───────────────┬──────────────────────────────────────────────────┐
│ SthStart      │ 当前位置 / 对象名         保存状态   次操作 主操作│
│               ├──────────────────────────────────────────────────┤
│ 工作台        │ 页面工具栏：搜索 / 筛选 / 视图                    │
│ 活动          │                                                  │
│ 图像与视频    │              当前任务的主要内容                  │
│ 角色          │                                                  │
│ 日历          │  列表、正文、编辑器或媒体预览                     │
│ …             │  按页面模板决定是否有辅助栏                      │
│               │                                                  │
```

这张骨架用于统一对齐和层级，不要求所有页面都常驻三栏。导航本身已经占一栏，复杂工作台再加侧栏时必须计算中央内容的可用宽度。

## 4. 布局系统与响应式规则

### 4.1 外框与尺寸

以下是设计初值，实施时以真实中文内容、200% 缩放和手机输入验证为准；不得为满足固定高度而裁切文字。

| 项目 | 目标 |
| --- | --- |
| 桌面导航 | 224px；可收起为 72px 图标栏，收起后有名称提示与可访问标签 |
| ≥1440px 视口 | 默认完整导航；工作区按内容宽度选择辅助栏 |
| 1024–1439px | 默认 72px 导航，用户可展开；窄编辑区优先收辅助栏 |
| <1024px | 56px 起的移动页头与导航抽屉；不常驻仅剩图标的窄栏 |
| 页头 | 桌面最小 64px，长标题/多行状态可增高；手机标题与主要动作同屏可见 |
| 内容内边距 | 手机 16px；普通桌面 24px；大屏 32px |
| 页面主区域最大宽度 | 浏览/媒体约 1600px；配置约 1120px；正文阅读另限行宽 |
| 主要工作区间距 | 24px；密集工作台栏间距 16px |
| 辅助栏 | 280–320px；仅在中央区仍至少 640px 时常驻 |
| 阶段/目录栏 | 168–208px；空间不足改选择器或抽屉 |
| 手机交互热区 | 主要触控动作至少 44×44px，视觉图标可以更小 |

断点是外框初始规则，复杂分栏还须使用容器可用宽度判定。禁止简单以 xl 存在就同时展开所有辅助栏。

### 4.2 四种页面模板

| 模板 | 使用页面 | 构图与滚动 |
| --- | --- | --- |
| BrowsePage | 角色、活动列表、媒体浏览、笔记列表 | 页头 + 筛选工具栏 + 内容网格/列表 + 分页；页面内容区负责纵向滚动 |
| WorkspacePage | 角色编辑、活动编辑、图像生成 | 对象页头 + 工作模式 + 主编辑/预览区；辅助栏可收起，不强制每页相同列宽 |
| ReadingPage | 笔记编辑/阅读、叙事档案 | 左列表/树可收，中央正文 680–800px，右详情按需；正文是视觉中心 |
| SettingsPage | 模型、生成配置、运行与日志 | 同一页头，紧凑分区导航，主配置列表/表单；日志独立受控深色表面 |

首页是 BrowsePage 的工作概览变体，日历是内容型特殊组件；它们使用相同外框和页头，不额外创造第五、第六套全局规则。

### 4.3 工作台分栏示例

```text
活动： 对象页头与保存状态
      [设定] [内容] [媒体] [播放]
      阶段列表  |  内容编排 / 主预览  |  当前对象详情（按需）

角色： 对象页头与发布状态
      [人设] [外观]
      主编辑正文                 |  角色预览 / 试演（按需）

生成： 模式与当前任务
      参数区 320–400px           |  媒体预览 / 结果网格
      主生成动作                 |  当前任务状态
```

当可用内容宽度不足约 1180px 时，活动右详情默认转抽屉；更窄时阶段转选择器。不能把正文压到 300px 还声称“大屏三栏”。

### 4.4 滚动与固定元素

- 页面模板只指定一个主纵向滚动区。可独立滚动的目录、结果列表和日志必须有明确用途，不能每层容器都 overflow-auto。
- 桌面工作台可在 100dvh 外框内组织滚动；手机默认允许自然文档流，避免键盘弹出后固定高度裁切。
- sticky 页头、Tab、局部工具栏使用共享偏移变量，不各写 top:0 互相覆盖。
- 吸底动作栏必须预留自身高度与 safe-area；内容聚焦时能滚动到键盘上方。
- 抽屉打开才锁定其所属滚动环境；嵌套弹层使用已有 overlay 管理，不再次各自改 body overflow。
- 不用 CSS order 制造与键盘顺序不一致的阅读顺序；大屏与手机均保持任务语义顺序。

## 5. 视觉规范与设计变量

### 5.1 两种主题

新默认主题主动拉开背景、内容和控件的层次。暖色主题保留原偏好，不通过全屏滤镜实现，也不默认增加深色模式。

| 语义 | 默认主题初值 | 暖色主题初值 |
| --- | --- | --- |
| 应用背景 | #F5F6F8 | #F1ECE2 |
| 导航背景 | #ECEFF3 | #EAE4D9 |
| 内容表面 | #FFFFFF | #FFFCF5 |
| 弱背景 / 悬停 | #F0F3F7 | #F3EDE2 |
| 输入表面 | #FFFFFF | #FFFEFA |
| 主要文字 | #17212E | #242923 |
| 次要文字 | #566273 | #5E675F |
| 分组细线 | #E2E7ED | #E6DED2 |
| 输入边框 | #8994A3 | #8C9186 |
| 主要强调 | #B84420 | #AE421F |
| 强调悬停 | #963517 | #923619 |
| 选中浅底 | #FFF1EB | #FBEADF |
| 焦点环 | #315DCE | #315DCE |

这些色值不是已通过测量的最终配色。要对真实背景、透明度、禁用态和字体计算对比度，再固定为最终 token。普通文字目标至少 4.5:1，需要辨识的控件边界/状态至少 3:1；纯装饰分隔线不机械套用同一要求。以 [WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)中的具体适用条件验收，不宣称只测颜色便达到完整合规。

保留既有状态色语义 success / warning / danger / info 的 fg、bg、border、solid、on-solid 分工并重新测量。错误用红，等待配置用中性说明，运行中用信息色；品牌橙不兼任所有状态。

### 5.2 字体与层级

| 内容 | 字号 / 行高 / 字重目标 |
| --- | --- |
| 页面标题 | 24px / 32px / 600；手机 20px / 28px |
| 区域标题 | 18px / 26px / 600 |
| 卡片与列表标题 | 16px / 24px / 600 |
| 正文与主要编辑内容 | 16px / 26px / 400 |
| 导航、标签、按钮 | 14px / 20px / 500 |
| 时间、来源等次要元信息 | 12–13px / 18px / 400 |
| 日志与代码 | 13–14px 等宽字体，必要时用户缩放 |

- 实现优先用 rem；中文使用稳定系统无衬线字体，避免把未实际加载的字体当成已生效。
- 不为本轮统一引入远程字体依赖；确有品牌字体需求再本地托管并测量体积。
- 不将状态、表单报错和主要操作缩到 12px；也不靠全局加粗增加层级。
- 长角色名和作品名提供合理换行/截断；完整标题通过可操作详情或提示获取，不能只靠鼠标悬停。

### 5.3 空间、形状与阴影

- 基础间距序列：4、8、12、16、24、32、48px；允许图标对齐使用局部 2px，但不各页自建尺度。
- 控件圆角 8px、面板 12px、弹窗 16px；胶囊仅用于标签和状态，不用于所有按钮。
- 普通按钮和字段高 40px；紧凑工具栏 36px；手机热区保持 44px，不能只放大文字。
- 每个视觉区最多“外层工作表面 + 必要输入边界”两层表达；组内优先分隔线，不再卡片里套卡片里套输入卡片。
- 内容面板默认不加投影；菜单/抽屉/弹窗用递增浮层阴影，不在所有卡片上使用同等阴影。
- 品牌折角、不对称圆角、卡片悬停大幅位移退出工作界面。
- 标签最多展示与当前任务有关的 2–3 个；其余 +N 展开，不重复显示作品名。

### 5.4 动效与层级

- 悬停/颜色过渡约 120ms，展开与弹层约 180ms；禁止大面积弹跳、卡片旋转或长入场动画。
- prefers-reduced-motion 时取消非必要位移动画；进度仍有文字状态。
- 层级以命名 token 管理：页面、sticky、菜单、抽屉、模态、提示。模态堆叠由现有管理器统一，不能仅靠不断增加 z-index。
- Toast 不承担唯一错误说明，不盖住模态主动作；关键保存错误留在当前表单。

## 6. 组件体系与框架选型

### 6.1 默认技术选择

继续使用当前 React 19、Vinext/Vite、Tailwind 4、TanStack Query、React Hook Form、CVA 和 Lucide。这里的版本来自当前 manifest，不构成建议升级到某个外部最新版本。

本次画面问题主要源于构图、样式归属和交互层级。更换 React 为另一运行框架会扩大路由、SSR、状态和测试迁移范围，没有本轮证据证明这种投入能够改善视觉。因此不安排运行框架迁移。

### 6.2 允许引入的轻量交互基础

| 方案 | 决策 | 理由与约束 |
| --- | --- | --- |
| 现有组件 + 统一 token / 布局 | 默认采用 | 已有弹层、表单、状态和键盘修复，直接复用可减少回归 |
| Radix Primitives | 首选的条件性补充 | 在已有组件缺乏必要交互时，按需接入菜单、Popover、Tabs 或弹层原语，不携带另一套视觉主题 |
| React Aria Components | 备选，不与 Radix 同时铺开 | 若复杂组合选择、日期输入的实际需求更适合它，可在小样中比较；不能为改颜色引入第二套基础系统 |
| 成套后台主题、另一运行框架 | 本轮不采用 | 本项目需要自定义创作界面，无证据支持全面替换现有页面和状态层 |

Radix 官方将其定义为可渐进接入、无默认样式并处理焦点和键盘等细节的基础组件库，可按需安装使用。参见 [Radix Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction)。其 SSR 支持不等于在本项目 Vinext、当前 React 版本和现有 Provider 下已验证，仍需本地兼容检查，参见 [Radix SSR](https://www.radix-ui.com/primitives/docs/guides/server-side-rendering)。React Aria 的安装、组件与样式接入见 [官方入门](https://react-aria.adobe.com/getting-started)。

“轻量”由实际首屏和路由产物衡量，不凭包名或官网形容词作结论。不承诺任何包在项目中固定只增加几 KB。

引入新依赖的具体门槛：

1. 明确现有组件缺的能力及一个可重现交互问题；若只是样式不统一，则修改现有样式即可。
2. 做一个受控组件小样，验证 SSR/hydration、React Hook Form、中文输入法、嵌套浮层、暖色主题与键盘操作。
3. 比较替换前后相关路由的压缩 JS、CSS 和交互，记录包版本、许可与 peer dependencies；不做无依据的全栈升级。
4. 经当前 ui 目录包装，业务只调用项目组件接口；同类能力只有一个实现。
5. 不运行脚手架覆盖现有组件和 theme；保留现有路径与 lockfile，仅提交必要依赖变化。

### 6.3 组件分层

| 层级 | 内容 | 规则 |
| --- | --- | --- |
| 设计变量 | 颜色、字阶、间距、尺寸、层级 | theme.css 为唯一语义定义源 |
| 基础控件 | Button、Input、Select、Dialog、Drawer、Tabs、Badge 等 | 沿用现有文件与 API，收敛不必要变体 |
| 通用任务组件 | PageHeader、Toolbar、FilterBar、EmptyState、SaveStatus、AsyncState、ConfirmDialog | 不自行请求业务接口，不隐含业务数据 |
| 页面模板 | BrowsePage、WorkspacePage、ReadingPage、SettingsPage | 定义布局、滚动和插槽，复用/演进现有 page-layout.tsx |
| 业务组件 | 角色卡、活动阶段、媒体任务、配置项、笔记正文 | 负责业务内容，不复制全局导航或主题规则 |

只为实际迁移页面需要的组件抽象，不建立几十个未使用的“设计系统组件”。也不增加 Storybook 等独立运行环境作为交付前提；用本地组件样板页和已有测试足够。

## 7. 全站交互规范

### 7.1 操作层级

- 一个任务区域只突出一个实色主动作。其他动作分为次级、文字和更多菜单；危险动作不与常规操作混为同样的橙色按钮。
- 页面动作固定在对象页头右侧；选择工具靠近列表；生成按钮靠近参数；阅读工具靠近正文。
- “保存草稿”“保存并使用”“生成候选”“采用候选”“导出”保持各自业务含义，不能为了简短统一改成“完成”。
- 已选数量为 0 时不展示整条批量工具栏；进入批量模式后有退出、清空和范围说明，不能把“本页”显示成“全部”。
- 图标按钮有名称；重要操作不能只有图标；列表整行链接内的独立按钮不能嵌套交互元素。

### 7.2 表单、保存与离开

- 同类字段标签和帮助说明位置一致，标签不能只用 placeholder。
- 基础设置先出现，高级参数默认折叠但保留值；折叠、换主题、换布局不能卸载丢值。
- 明确未保存、保存中、已保存、保存失败、版本冲突和已发布状态；UI 不能乐观地把请求已发当成服务器成功。
- 保存失败说明保留到恢复或用户处理，支持原有重试；不是仅闪一个 Toast。
- 离开保护覆盖链接、路由切换、抽屉关闭和浏览器刷新等适用场景。自动保存已经确认成功时不重复阻拦。
- 文件上传显示选择、上传中、可用、失败，取消候选不创建正式角色或活动。

### 7.3 异步、空态与错误

统一状态种类：初次加载、后台刷新、真空数据、筛选无结果、未配置、离线可编辑、请求失败、权限/会话问题、版本冲突。

- 初次加载使用稳定骨架；后台刷新保留已有内容，不把整个工作台变回 loading。
- 空态一条具体说明与一个有效下一步；搜索无结果提供清除筛选，不引导无关新建。
- 未配置紧邻当前受阻动作，链接到对应配置并保存返回路径和草稿；禁止只在页面顶端提示后让按钮无解释禁用。
- 生成任务显示真实阶段/时长/错误；未知进度不能伪装成精确百分比。取消成功和取消请求已发区分。
- 正常状态文字克制；只有影响本页任务的异常才展开提示，不全站常驻一大块状态墙。

### 7.4 响应式与可访问性

- 所有主要任务可仅用键盘完成；Tab 顺序对应视觉顺序，焦点清楚且不会被 sticky 元素遮住。
- Tabs 和导航链接遵守各自语义；日期格、树、弹层复用已有语义与键盘行为。
- 中文输入法组合输入期间不触发误提交、快捷键或搜索选择；文本域 Enter 保持换行。
- 模态标题、描述、焦点进入/恢复、Escape 与遮罩关闭策略统一；未保存内容的关闭规则不被通用弹层覆盖。
- 200% 文字放大与 360px 宽度下主要任务仍可用。日期网格、媒体画布和数据表可有标明的局部横向滚动，普通页面不能整体横向溢出。
- 减少动效、离线、触屏与软键盘状态均纳入验收，不能仅用宽屏鼠标截图判断完成。

## 8. 逐页改造规格

### 8.1 首页：工作概览

页面重点改为最近正在做的内容。左导航已经提供应用入口，首页不再以六张等权应用卡作为主体。

- 顶部只留“工作台”标题和一个新建菜单，不保留大号问候与营销式副标题。
- 主区展示最近工作，优先使用现有 RecentWork 数据：对象名、类型、更新时间、真实状态、继续入口。无数据时自然收缩。
- 辅区展示已有日历中的近期事件和当前必要服务提醒；如果现有接口无法提供，不为填版面新增统计后端，保留日历入口即可。
- 常用入口收为少量轻量文字/图标链接，初次使用空态提供创建角色或活动的明确路径。
- 不新增没有数据依据的“创作效率”“累计灵感”等统计，不隐藏真正阻止创作的服务异常。
- 1440×900 下首屏出现最近对象或有效的新建空态；无需越过大段欢迎区。

### 8.2 角色库：可浏览的内容库

- BrowsePage，默认工具栏：搜索、作品、标签、更多筛选；已生效条件独占按需出现的第二行。
- 收藏、分组、演绎、来源、生日和高级筛选全部保留；初始显示数量不等于删除能力。
- 真实头像/立绘成为卡片识别点。默认紧凑卡采用约 72px 方形缩略图与信息区，已有图片可以放大预览；不把小头像拉成全屏封面。
- 卡片信息固定顺序：名字 → 作品/演绎 → 两行摘要 → 草稿/发布状态。作品名不同时重复出现在标签区。
- 桌面按最小约 220px 自适应列数，不以固定六列为目标；手机默认一列紧凑横向卡，避免把名字和操作挤进半屏。
- “添加角色”作为主操作，下拉含搜索、文件、粘贴、手写；批量选择在进入模式后出现。
- 筛选、分页与返回位置继续保留原 URL/session 状态逻辑。

### 8.3 角色新建/编辑：围绕 V2 四块内容

- 页头：头像/角色名、草稿与发布状态、保存并使用、更多操作。
- 主模式只有“人设”“外观”，来源、关系、版本、模型配置在明确的更多设置入口中可达。
- 人设：名字/作品 + personaText + speechText；例句、约束、摘要和生日按需展开。
- 外观：baseText + defaultOutfitText + 参考图，默认穿着与本场活动穿着的含义说明保持。
- 宽屏右侧可放试演/预览，小屏改抽屉；试演按钮不和保存争夺同一主动作。
- 迁移复核项显示具体数量与入口，原文档案可查，不把完整迁移 JSON 放在主编辑区。
- 原有多分区 DOM 中隐藏的表单状态要真正收敛，避免两个输入同时编辑同一个草稿。

### 8.4 活动列表与新建

活动列表使用 BrowsePage：标题、日期、参与者缩略图、阶段进度/真实状态、继续编辑。媒体封面仅使用已有资产；无封面时正常列表仍完整。

新建活动使用 WorkspacePage 的设置/企划双区：

- 左区先选模板，再填名称/日期/地点和参与者；规则折叠，不要求用户先填满大量空文本框。
- 右区：一句生成要求 → 生成企划 → 候选预览 → 阶段列表。模型状态并在生成区域说明。
- 阶段默认紧凑行，只展开当前编辑项；使用真实稳定 ID，不因重排或标题改变重置。
- 页尾/吸底仅保留一个随状态说明的创建主动作，明确采用哪份内容；不把生成候选等同于创建成功。
- 手机顺序为设置、选人、企划、阶段与创建，不靠视觉换序打乱读屏与键盘。
- 寿星、日期、企划冻结快照、幂等与候选确认机制保持。

### 8.5 活动编辑：全站的核心工作台

- 对象页头固定活动名、保存/版本状态和当前主要动作。
- 使用现有设定、内容、媒体、播放模式，标签名称以实际能力校准；不为统一布局重命名底层状态或 URL 数据。
- 内容模式：左阶段列表，中间记录编排，右当前记录详情按需显示；阶段与记录不同时全部展开成长表单。
- 生成候选、采用、拒绝与历史入口明确分开。未采用候选与正式内容有清楚视觉区别，不靠文字颜色一项区分。
- 媒体模式将预览作为中心，提示词来源与参数作为右侧详情；使用现有来源定位和重生成流程。
- 播放模式扩大播放区域，编辑工具收起，退出后恢复位置；媒体画布可使用深色，不把整站改深色。
- 1280px 下辅助栏自动收起，内容区域仍可读；移动端通过阶段选择器与详情抽屉编辑。

### 8.6 图像与视频：参数与结果有明确主次

- 沿用当前能力切换；尚未配置的功能显示明确状态，不制造看似可用的新入口。
- 宽屏左 320–400px 参数区，右侧结果/预览。提示词、画幅、有效配置与生成按钮优先可见；负面词、种子、步数等高级项折叠且保留值。
- 结果为空时一张紧凑空态；有任务时显示当前任务条，有作品时媒体网格成为主内容。
- 媒体与任务模式保留当前选择；提交成功可以切到任务，但轮询不能每次把用户强拉回任务页。
- 大图使用正确比例和 object-fit；缩略图可以裁剪，但原图预览完整显示，保留尺寸/格式与下载动作。
- 单个结果详情统一展示实际输入、来源、任务状态和再生成入口；技术 ID 默认折叠。
- 不要求新增编辑画布、时间轴或复杂媒体浏览框架。

### 8.7 日历

- 页头放月份、上/下月、今天；作品/生日/活动筛选在第二层工具栏。
- 桌面月历与选中日期详情；手机以日期选择 + 当日/近期议程为主，避免七列文字全部压成两三字。
- 寿星头像、名字和日期为主要信息；颜色辅以标签区分生日和活动。
- 同日多寿星、二月二十九、空日、农历待确认、长事件名和筛选状态全部检查。
- 复用既有日期与生日契约，不用 UI 库默认日期对象改写业务历法、时区或人工确认逻辑。

### 8.8 笔记

- 列表采用紧凑标题/摘要/更新时间行，可选小缩略图；筛选不占半屏。
- 编辑使用 ReadingPage：列表可收、正文中央、属性侧栏按需，标题和主要文本最突出。
- 保留离线、本地草稿、同步队列与冲突状态；保存提示由真实本地/服务端状态驱动，不能全部简化成“已保存”。
- 手机聚焦正文，导航和属性为抽屉；工具栏不盖住软键盘上方的最后几行。
- `/apps/notebook/offline` 保持无网络可达和编辑可用；不得为了加载统一外框而强依赖在线查询。

### 8.9 叙事档案

- ReadingPage：目录树、正文、来源/关联详情三部分；默认让正文宽度和行距稳定。
- 数据源和导入改成有状态的工具入口，首次无数据时明确展示；不是每次打开都先看大块技术导入说明。
- 目录选中与正文位置关联，长章节名可读；折叠侧栏不丢当前节点。
- 正文使用 16–18px，限制行宽；代码/原文 JSON 在专用查看面板中显示。
- 手机主看正文，目录与详情分别打开，避免树、正文和表格顺序堆成极长页面。

### 8.10 模型与公共服务

- SettingsPage，保留现有模型、绑定、向量/其他服务、应用凭据等分区。
- 模型使用配置列表行，显示名称、能力、连接/凭据状态、使用方与操作；一条记录时也保持紧凑完整。
- 编辑采用一致的侧栏表单或弹窗，选一种为同类统一模式；危险操作在更多菜单与明确确认中。
- 搜索和新建靠近列表；技术字段有准确标签，默认隐藏密钥原值。
- 测试连接与保存配置分开反馈。未测试、连接正常、失败、凭据缺失不能用一个绿点或“正常”混淆。
- 模型优先级、应用绑定及现有返回路径不因视觉重组改变。

### 8.11 生成配置

- 引擎、工作流、Worker、分配和诊断延续现有分类与契约。
- 列表 + 当前对象详情，不将每一个状态值做成大卡片；首次无配置给当前所需的下一步。
- 引擎/Worker 状态和实际探测时间一起显示；过期状态与实时连接区分。
- 工作流结构化编辑与原始 JSON 模式保留，主表单使用共享 Field；大 JSON 编辑器按需加载，不进入每个页面首屏。
- 状态刷新保留正在编辑的表单，不能用最新查询结果重置未保存参数。

### 8.12 运行与日志

- 服务列表为主：服务名、实际状态、必要端口/连接、启停/重试；概览只显示可行动的问题。
- 日志使用独立深色 LogSurface，过滤、暂停自动跟随、复制与下载贴近日志；正文和参数表仍使用全站主题。
- 危险动作显示准确对象，失败后状态重新读取；不能以按钮点击成功假装服务已经运行。
- 控制中心已有配置、远程性能、模型相关入口保留，重复配置内容用链接指向权威页面，不创建新的设置来源。

### 8.13 邻舍入口

- SthStart 外框提供清晰的返回、外部打开、刷新/重连与实际服务状态。
- 邻舍 iframe/独立页面内部保留其样式、滚动和键盘行为，不通过跨域假设控制其 DOM。
- 连接中、启动未完成、连接失败和已就绪分别显示；入口样式统一不代表后端状态可用。
- 嵌入页面至少保留一个恢复全站导航的动作，全屏模式可退出。

### 8.14 路由覆盖清单

| 路由 | 模板 | 必测状态 |
| --- | --- | --- |
| `/` | 工作概览 | 有最近工作、无记录、必要服务异常 |
| `/apps/characters` | BrowsePage | 有图/无图、复杂筛选、批量、分页 |
| `/apps/characters/new` | WorkspacePage | 手写、导入、草稿失败 |
| `/apps/characters/[id]` | WorkspacePage | V2 正文、发布、冲突、迁移复核、试演 |
| `/apps/activities` | BrowsePage | 空、草稿、已发布、长标题 |
| `/apps/activities/new` | WorkspacePage | 手动、AI 企划、寿星、冻结冲突 |

## 9. 工程落地与旧样式退出

### 9.1 文件与职责

- `app/layout.tsx`：保留 Providers、离线注册、同步和命令面板，接入稳定 AppShell。客户端交互只放必要叶子，不能把整个应用变为纯客户端渲染。
- `app/components/shared/navigation.tsx`：扩展显示分组和名称；Sidebar、命令面板、移动导航同源。
- `app/components/shared/page-header.tsx`：移除全局应用/主题工具职责，保留对象标题、返回、状态和页面动作。
- `app/components/shared/page-layout.tsx`：演进为四类布局，复用已有容器，不平行长期保留两套等价模板。
- `app/styles/theme.css`：统一语义变量及两种主题；旧 paper / ink / accent 仅作兼容别名，迁移完成后核查消费者。
- `app/globals.css`：最终仅保留基础 reset、全局排版、无障碍/减少动效与必要共享基础规则；页面样式转到模板或所属 feature。
- `app/components/ui`：复用并收敛状态、尺寸和变体；不允许业务页覆盖其颜色/形状语义。
- `app/features/*`：按逐页规格迁移构图，保留 queries、mutations、保存队列、稳定 ID 与业务字段。

### 9.2 样式迁移策略

1. 新 shell 和新模板使用明确根标识，避免与旧 portal-*、studio-*、notebook-* 规则交叉命中。
2. 每完成一页，删除其已无调用者的旧样式；不能所有页面都迁完后才发现旧选择器还影响新组件。
3. 不改 Tailwind 通用 radius token 来间接改变全部组件，优先明确 control / panel / dialog。
4. 业务特例使用有名称的 variant，例如 media / log；不通过 className 覆盖一长串 token 实现例外。
5. 允许减少动效、必要输入兼容等有依据的全局规则，不能机械删除所有 !important；每个保留项记录理由。
6. 删除旧代码前检查实际调用；不大规模改格式或重命名无关模块，保持评审差异可读。
7. CSS Modules 或局部 Tailwind 二选一按现有模块最少变更实现；不为“统一”同时新增 CSS-in-JS 运行时。

### 9.3 业务状态与路由保护

- AppShell 切换主题、导航收起、侧栏开关不重新挂载 QueryProvider、UIProvider 和保存管理器。
- 复用现有服务端路由和缓存 key；不引入第二套 React Router 或全局 store 保存同一份服务端数据。
- 页面输入与服务器查询结果分开，后台轮询、切 Tab、开抽屉不覆盖 dirty form。
- UI偏好可用本地存储；已有筛选 URL、生日字段、笔记 IndexedDB、活动任务快照继续按原机制工作。
- 默认主题改版不清除已有暖色偏好，保留 localStorage 键兼容并验证首帧没有主题闪烁/水合警告。
- 离线页面不能因共享 shell 新增在线依赖而白屏；资源缓存升级与离线正文存储分开，不能用清空 IndexedDB 解决样式缓存问题。

## 10. 实施阶段、依赖与交付

采用“统一骨架 + 三张代表页面打样 + 全站推广 + 清理验收”的顺序，避免再做一轮只有按钮统一的交付。

| 阶段 | 工作 | 必须交付 | 相对规模 |
| --- | --- | --- | --- |
| D0 基线与盘点 | 核对当前版本、未提交变更、路由、数据样本、既有组件 | 实际页面与状态清单、当前截图/性能基线、差异范围 | 小 |
| D1 设计规范落地 | token、排版、控件状态、组件样板 | 默认/暖色样板与计算样式证据，依赖取舍记录 | 中 |
| D2 全站外框 | Sidebar、移动导航、页头、四类模板、滚动规则 | 新 shell 可在代表页运行，导航/草稿/离线不回归 | 中 |
| D3 三页代表实现 | 角色库、活动编辑、模型配置 | 同数据前后对照、桌面与手机实际交互；页面构图达到本文目标 | 大 |
| D4 核心创作推广 | 首页、角色编辑、活动列表/新建、创作中心、日历 | 全链路创建/编辑/候选/保存，状态保持 | 大 |
| D5 资料与设置推广 | 笔记、叙事、生成配置、控制中心、邻舍外框 | 阅读/配置布局统一，离线与日志特殊场景通过 | 中到大 |
| D6 清理与验收 | 清理旧 CSS、核查残余路由、响应式/可访问性/性能回归 | 逐路由完成矩阵、测试结果、构建与部署说明 | 中 |

这是相对工作量，不能在未完成 D0 前承诺固定工期。D1/D2 可小步交错；D4/D5 依赖 D3 确认过的设计规则。

D3 是执行模型内部质量检查点，不要求每改一个页面就停下来向用户要许可。应展示可审阅的实际页面并继续独立工作；若用户提出方向修正，优先调整共同规则再推广。

多模型协作时，外框、token、ui 基础组件、globals.css 和导航由一个集成负责人维护；其他执行者按业务域分工，不能分别发明配色或同时覆盖公共样式。每个业务域交付实际路由和状态结果，而不只是文件列表。

## 11. 视觉和功能验收

### 11.1 基线与样本

- 记录真实服务 URL、源码/构建版本、主题、视口、浏览器与样本数据。区分当前源码与正在运行的旧容器构建。
- 代表数据覆盖：24位角色含有图/无图/长名，多阶段活动，零媒体与若干不同画幅结果，少量模型配置，长笔记，深目录叙事。
- 验证数据来源清楚，测试夹具与真实数据分开；不向日常库写入虚构项目只是为了截图好看。
- 比较前后使用相同内容、视口、主题与滚动位置，不用空页对满页证明空间改善。
- 浏览器验收使用新检查标签或确认无未保存内容后刷新，避免覆盖用户正在编辑的页面。

### 11.2 检查矩阵

| 维度 | 必检要求 |
| --- | --- |
| 视口 | 1920×1080、1440×900、1280×720、768×1024、390×844；360px 和 200% 放大作边界检查 |
| 主题 | 默认与暖色；所有主要模板都覆盖，不只看首页 |
| 页面状态 | 加载、有内容、空、无搜索结果、未配置、失败、冲突与离线按路由适用情况 |
| 操作 | 鼠标、键盘、触摸、软键盘；焦点恢复、Escape、快捷键和中文输入法 |
| 内容边界 | 长角色名/URL、很多筛选、多阶段、表格和不同媒体比例 |
| 构建 | 开发预览与生产构建均检查，不能只看热更新效果 |

不要求所有路由乘所有状态乘所有视口做完全笛卡尔积。D3 三个代表页与四种模板完整覆盖，其他页面按高风险状态补充，并明确记录未检查项。

### 11.3 可量化验收目标

- 1440×900、默认数据下，列表第一页内容顶部目标距视口顶部不超过约 240px；工具栏正常换行与放大文字时可自然增加，不截内容追数字。
- 1280×720 的生成页能看见主生成动作或明确的配置阻塞入口；活动页能定位当前阶段和生成/编辑入口。
- 常规页无页面级横向滚动，长内容不会把导航或主动作推到屏幕外。
- computed style 验证 control=8px、panel=12px、dialog=16px；检查真正内容表面，不能只测遮罩容器。
- 工作界面常用标签/控件不低于 14px、主要正文不低于 16px；辅助元信息不低于 12px。
- 每个页面一个 h1、一个 main；主动作、保存状态和当前位置都能通过文本或语义定位。
- 任一主题下按钮、输入、焦点、菜单、空态和错误有明确层级，状态不只靠颜色。
- 页面迁移后主题切换、侧栏展开和后台状态刷新不丢输入、不重置选择、不跳滚动。

数值只能检查结构，不能代替美观评审。每个代表页还应确认：主角明确、对齐稳定、留白有秩序、内容密度合适、颜色克制、没有无意义重复面板。未达到时修改布局，不能仅更新测试图片接受现状。

### 11.4 功能回归重点

- 人设：V2 编辑、导入确认、取消、试演、外观候选、保存发布和版本冲突。
- 活动：企划会话、寿星/日期、选人、阶段切换、候选采用、局部改写、历史、媒体来源、导出播放。
- 创作：参数折叠保留、配置返回、任务提交/取消/失败、媒体/任务切换、结果查看。
- 笔记：本地存储、断网、重连、同步与离开保护。
- 配置：模型编辑、凭据、绑定、连接测试与服务状态；不因样式变更写入默认值。
- 导航：深链接、返回列表、浏览器前进后退、手机抽屉关闭、全屏退出。

### 11.5 性能与测试策略

- 不为样式修改新增大量实现镜像单测，复用现有 portal、frontend-experience、activities、calendar、visual 测试。
- 新增测试只覆盖真正改变的交互契约，例如 shell 不重挂载、布局切换不丢草稿、导航/焦点与离线启动。
- 首屏公共 shell 不导入整个角色编辑器、媒体播放器、工作流编辑器或所有业务图标模块副作用；大型详情与媒体预览按需加载。
- 新依赖造成代表路由首屏压缩 JS 增长超过约 40KB 时必须说明并优化；这是审查触发值，不是已经测得的成本。
- 大列表先使用已有分页与稳定渲染。只有实际测出卡顿才引入虚拟列表，不在本次增加全局虚拟化框架。
- 性能报告使用同一设备/内容/构建条件和多次测量；没有测量就不声称加载更快。

按实际 package.json 执行类型检查、定向 lint、已有相关测试和门户生产构建。可用入口包括：

```text
npm run typecheck
npm run test:portal
npm run build:portal
git diff --check
```

浏览器回归使用现有 Playwright 配置选取相关场景；不要为更新样式直接无检查地批量 update-snapshots。全量后端测试按实际逻辑变更决定，不把前端重设计变成无关后端修复。
