# SthStart 前端风格统一与界面体验优化完整方案

> 日期：2026-09-12  
> 用途：交给其他模型或工程师实施的前端审查与设计方案。  
> 本轮交付：仅生成本文档，不修改前端代码、数据库或运行环境。  
> 审查依据：当前工作区的主题、全局样式、共享组件、页面结构、导航、反馈和查询机制；结合此前用户提供的页面截图。未在本轮完整操作所有运行页面，因此代码风险与待实测问题分别标注。

## 1. 结论与推荐方向

当前前端已有纸色背景、暖橙强调色、护眼主题、共享 UI 组件，也已开始采用 1920px 容器、双栏工作台和自适应卡片网格。基础方向可以保留，主要问题是新旧规范并存，导致不同页面像由不同系统拼成。

推荐统一为：**暖色、清晰、适合长期工作的创作工作台**。

本方案不重新设计品牌，不把所有页面机械变成双栏。重点是建立统一规则，并按列表、编辑、阅读、生成和配置五类任务合理组织内容：

1. 视觉统一：颜色、字体、圆角、边框、按钮、状态和弹窗使用同一套语义规范。
2. 布局合理：大屏利用宽度，编辑与辅助信息并排；正文保留阅读宽度；小屏保持清楚的操作顺序。
3. 操作一致：导航、搜索、保存、重试、删除、批量操作和错误提示遵循相同模式。
4. 状态可信：区分未加载、没有数据、无搜索结果、配置缺失、执行失败、离线和保存成功。
5. 实施可控：先统一基础组件，再逐页迁移；保护现有草稿、版本、离线和模型接入功能。

### 1.1 与上一份计划的关系

配套文档：[模型接入修复与门户双栏布局改造实施计划](./MODEL_INTEGRATION_AND_PORTAL_LAYOUT_PLAN.md)。

- 上一份负责模型接入、绑定闭环和第一轮布局改造；本文补充全门户设计系统与交互一致性。
- 当前代码已出现 `PageContainer`、`WorkbenchColumns`、`CardGrid` 和 `PageHeader.compact`，不应再次把它们当作待从零新增的功能。
- 模型默认绑定和后端契约按上一份计划处理，本文不重新授权修改绑定、不新增全局默认模型。
- 本文的规范是后续前端统一的目标；实施前对照当前代码，仅完成差异，不回滚已完成的有效改造。

### 1.2 范围

覆盖门户首页、活动列表/创建/编辑、角色库/编辑、日历、创作中心、创作笔记、叙事档案、公共服务、控制中心、生成配置，以及共享导航、弹窗、提示和基础控件。

邻舍内部页面保持原产品布局，只核对门户入口和配置跳转的一致性。媒体作品、图片、视频、角色头像不跟随主题进行颜色重绘。日志和媒体预览可保留专用深色背景，但必须纳入受控的组件变体。

不包含：重写业务框架、替换状态库、新增深色模式、拖拽分栏系统、全局密度设置、通用消息中心、没有数据来源的新统计模块。

## 2. 当前问题清单与优先级

优先级定义：P1 为影响操作正确性、可访问性或全局一致性的基础问题；P2 为主要页面体验问题；P3 为测量后再做的细节与性能优化。本轮没有确认到需要以 P0 描述的数据损坏问题。

## 3. 统一视觉规范

### 3.1 颜色与主题

保留当前品牌基础色：默认纸色 `#f4f0e7`、表面 `#fffdf8`、文字 `#18201d`、强调色 `#c04c28`；护眼主题继续使用现有暖杏调色。使用现有变量名称作为基础，不再平行创建第二套主题。

页面只引用语义 token：

| 用途 | 规范 |
| --- | --- |
| 页面背景 | bg-app / paper |
| 普通面板 | surface |
| 悬浮、弹窗 | surface-raised |
| 次级背景 | surface-muted |
| 悬停 | surface-hover，不直接 hover:bg-white |
| 正文/说明 | fg-default、fg-muted、fg-subtle |
| 分隔与边框 | border-subtle/default/strong |
| 主操作 | accent / accent-dark / on-accent |
| 状态 | 每种状态拆分 fg、bg、border、solid、on-solid |

目前 success/danger 等基础色未必适合直接作为小字号正文或白字实底按钮，应增加对应文字色/实底色 token。测量实际背景上的对比度后调整，不以“颜色看起来差不多”验收。

品牌橙只强调选中项、链接和主要操作，不把所有普通区块染橙。危险操作保留独立 danger 语义，不使用普通 accent hover 掩盖删除性质。状态不能只用颜色表达，必须有文字或图标。

护眼主题覆盖 Toast、Dialog、Select、hover、disabled、empty、error 等全部状态；媒体内容不染色。不要声称主题能降低屏幕硬件蓝光或提供医学护眼效果，文案使用“暖色显示/护眼配色”。

### 3.2 字体与排版

- 保留页面标题的衬线风格作为品牌特点；面板标题、操作和表单统一无衬线。
- 不引入依赖外网下载的新字体；继续使用系统字体回退。
- 页面 H1：桌面 28px、小屏 24px；紧凑工作台 H1：桌面 24px、小屏 22px。
- 面板 H2：18px/600；区块 H3：16px/600；正文和控件：14px；长文阅读：16px、行高约 1.75。
- 说明文字：13–14px；12px 只用于不影响决策的元信息，不用于错误正文和主要操作。
- 内容行高约 1.5–1.7。避免大段加粗、宽字距和英文大写辅助标题。
- 每页一个主要 H1，区块标题按层级排列，不用 h5 仅为获得某种视觉大小。
- 名称可以截断，但卡片或详情必须提供完整内容；说明和错误允许换行。URL/ID 使用 break-all 或可复制详情，不能撑宽布局。

### 3.3 圆角、边框、阴影

选择**统一、规则的轻圆角**作为业务 UI 默认：

| 元素 | 圆角 |
| --- | ---: |
| 输入框、按钮、小选项 | 8px |
| 卡片、面板 | 12px |
| 弹窗、抽屉上角 | 16px |
| 标签、头像圆形等明确胶囊元素 | 9999px |

不对称折角只保留在门户品牌标识或单一展示装饰中；从业务按钮、输入框、卡片移除。按钮大小不再决定形状。

普通卡片使用 1px 边框，默认无阴影或最轻阴影；悬浮层才使用明显阴影。禁止在“带背景页面 → 带阴影面板 → 带阴影卡片 → 带边框表单”中层层套盒，优先分隔线和标题区分层级。

### 3.4 间距与尺寸

使用 4px 基础网格，推荐间距为 4、8、12、16、24、32px。

- 页面左右：手机 16px，其他 24px；最大容器 1920px。
- 页面区块：16px；面板内边距：16px；大型阅读区可 24px。
- 字段标签与输入：6–8px；字段组间距：12–16px。
- 默认按钮、Input、Select：40px；紧凑工具栏控件：36px；大按钮：48px。
- 触摸设备主要点击区域至少 44px，允许视觉高度与触摸命中区分别处理，但不得遮挡邻近控件。
- 图标：操作 16px、导航 18px、状态 16–20px；统一 Lucide，不混用 emoji 作为业务图标。

### 3.5 动效

状态/颜色过渡约 120–180ms，面板展开不超过 200ms。普通工具按钮不悬浮位移，避免鼠标目标抖动。保留已有 prefers-reduced-motion 支持；弹窗状态不能依赖动画完成才能操作。

## 4. 导航和页面框架

### 4.1 单一导航注册表

提取共享导航数据供 AppSwitcher、门户入口、命令面板使用。字段最少包括 `id/title/href/group/icon/keywords`；不同界面可配置可见性，但不能各维护一份互相遗漏的路由名单。

建议分组：

- 创作：活动工作室、创作中心、角色资料库、角色日历、创作笔记、叙事档案。
- 应用：邻舍。
- 管理：公共服务、生成配置、控制中心。

保留现有紧凑应用切换器，不新增常驻宽全局侧栏，以免占掉用户要求用于内容的宽度。命令面板是快捷入口，不能成为唯一入口。

页头统一结构：

```text
返回/面包屑       当前页面标题 + 必要状态             应用切换 / 显示偏好
可选一句说明                              当前页面主要操作 / 更多
分类导航（如有）
搜索、筛选、排序、数量（如有）
主要内容
```

应用切换与护眼开关各出现一次。业务子面板不重复“返回门户”。记录详情优先返回所属列表，并保留原筛选和分页；门户入口作为更高层面包屑。

### 4.2 主次操作

每个任务区域最多一个填充强调色主按钮：列表的“新建”、编辑器的“保存”、生成区的“生成”。其他操作使用 outline/ghost。页面可以有多个任务区域，但同一工具栏不能将刷新、导入、创建、导出都做成同等强度。

危险操作放行内次级按钮或“更多”，必须有文字说明。常用编辑入口保持直接可见，不能为了整齐把全部操作藏起来。

## 5. 五类页面布局模板

### 5.1 列表型：活动、角色、笔记、模板

紧凑 PageHeader → 搜索筛选工具栏 → 状态/数量 → 内容网格 → 分页或加载更多。

- 有头像、封面和摘要的对象使用 CardGrid，最小卡宽 280–320px；偏配置比较的数据使用列表行，不把所有数据做成大卡。
- 默认视图由页面任务决定，本轮不统一新增“卡片/表格切换”。
- 搜索、筛选、排序和分页状态写入 URL；搜索使用约 250ms 防抖并处理中文输入法 composition，按 Enter 可立即提交。
- 区分全库为空与筛选无结果；后者优先“清除筛选”，不是“创建第一条”。
- 批量选择出现时展示工具条与选择范围，翻页选择是否保留必须明确，不能暗中批量删除不可见对象。
- 卡片高度只对齐关键区域，不强制固定很大的 min-height。卡片 footer 对齐，名称、摘要和状态保留统一顺序。

### 5.2 编辑型：活动、角色、复杂配置

桌面保留双栏方向；>=1280px 设置与工作内容并排，低于该宽度单栏。普通双栏比例 40/60，辅助信息侧栏约 320–360px。

- 复杂业务分区放局部 tabs 或锚点导航，不拆成多层互相嵌套的 tabs。
- 说明靠近字段，必填/可选、校验错误、已保存/未保存/保存中使用一致表达。
- 主要保存入口保持可达，状态与保存按钮同区。不要出现页面顶部“保存”和底部“提交”实际做同一件事而命名不同。
- 窗口缩放、组件重排、query 更新不卸载或覆盖 dirty form。离开确认沿用可靠草稿保存能力，有已保存会话的生成任务不得被误判成完全丢失。

### 5.3 阅读型：叙事、笔记正文

目录/列表＋阅读正文。原有阅读工作区已有双栏或多区时，收敛尺寸即可，不为了统一而破坏阅读导航。

- 中文正文推荐约 36–44em 宽，正文区域内部居中，媒体可扩展。
- 左侧目录约 240–280px；小屏使用抽屉，保留返回目录和当前章节标识。
- 行宽限制属于有意义的留白，不应把长文章拉到整个 1920px。
- 同屏元信息只展示与阅读有关的来源、标签和关联；无元信息时不制造空侧栏。

### 5.4 生成型：活动企划、图片/视频工作台

参数/输入＋结果/候选。模型或工作流状态在生成入口附近，而不是放在无关页面底部。

- 未提交：说明输入要求；排队：显示真实队列状态；执行中：显示当前阶段；成功：展示结果和下一步；失败：保留输入并提供重试。
- 后端无真实百分比时使用不确定进度，不能让假进度条缓慢逼近 99%。
- 结果媒体按比例展示，完整预览默认 contain，缩略图可 cover 并提供完整查看。
- 候选“预览”和“应用”明确分开；生成成功不等于已经覆盖当前活动或角色。
- 高频进度更新不不断触发 Toast，只在关键状态变化时通知。

### 5.5 配置/监控型：公共服务、控制中心、生成配置

窄状态栏＋分类＋配置内容。可读名称为主，内部 ID 可复制但不占主标题。

- 选择配置后能看到“作用于谁”“当前生效哪个”“保存是否成功”。
- 日志/任务采用高密度行，错误摘要与详情分开；状态区不重复大标题。
- 深色日志是 `LogSurface` 变体，统一级别颜色与对比度，不把整页换成另一套品牌。
- 配置未加载时不能把表单当作空配置提交；保存失败保留所有输入。

## 6. 逐页优化清单

| 页面 | 保留 | 本轮优化重点 | 验收结果 |
| --- | --- | --- | --- |
| 门户首页 | 品牌、应用入口、最近工作 | 压缩大幅介绍；应用入口和最近工作共享对齐线；删除重复进入按钮 | 首屏看见主要入口，管理入口与创作入口层级明确 |
| 活动列表 | 搜索、归档、导入、复制 | 卡片规范、日期/角色/状态顺序、操作层级和统一删除确认 | 宽屏高密度，长标题不挤坏操作 |
| 新建活动 | 已有双栏与企划会话 | AI 状态和生成入口靠上；阶段编辑紧凑；技术会话信息折叠 | 首屏可找到设置、角色入口和生成动作 |
| 活动编辑 | 记录/设定/素材/回放 | tabs、保存状态、固定操作和各工作区边框统一 | 切换分区不丢草稿，预览不被固定栏遮住 |

## 7. 共享组件与交互收敛

### 7.1 优先修改现有组件

| 组件 | 规范变更 |
| --- | --- |
| PageHeader | compact/default 两种密度，共享字号、操作布局；全局工具和业务操作分组 |
| PageContainer | 统一容器边距；调用页面移除重复外层 px，避免双重留白 |
| WorkbenchColumns | 保留已有 40/60 与响应式行为；列最小宽度和 DOM 顺序明确 |
| SidebarColumns | 修复 sidebarFirst，保持桌面 main 在弹性列、sidebar 在固定列；改用显式 grid-area 并验证键盘顺序 |
| Button | 尺寸统一、圆角独立于 size；loading 设置 aria-busy；图标尺寸规范 |
| Input/Select/Textarea | 同高、同圆角、同错误处理；readOnly 与 disabled 语义区分 |
| Badge/StatusIndicator | 合并状态映射，不用 online 表示所有“已启用”；显示文字状态 |
| Card | header/content/footer 统一间距，默认轻边框；不要继续页面内覆写大量形状 |
| Alert | 组件内提供标题、内容、行动区和可选技术详情；错误与警告有独立语义 |
| Dialog/Drawer | 复用焦点、关闭和滚动锁逻辑，宽度/尺寸由显式 variant 控制 |

**SidebarColumns 修复规则：**如需要手机 side-first，DOM 先 sidebar 再 main；桌面通过命名 grid-area 恢复 main/sidebar 位置。对含表单的页面优先保持阅读与键盘顺序一致，不仅依赖 CSS order 制造视觉与焦点顺序冲突。该组件当前无业务调用，应先有一个明确场景和测试再推广。

### 7.2 最小新增组件

- `FormField`：label、required、hint、error 与 aria-describedby，减少每个页面手写校验结构。
- `PageTabs`：统一页面级 tab 样式和键盘行为；真正切换同页面板使用 tablist/tab/tabpanel，导航到新页面使用链接语义。
- `ConfirmDialog`：有对象名称、后果、取消和确认；可恢复删除提供撤销，不可恢复删除明确说明。
- `AsyncState`：loading/error/empty/no-results/offline 的共享呈现，允许页面提供动作，不接管业务请求。
- `SaveStatus`：未修改/未保存/保存中/已保存/失败/冲突的共享视觉表达，不重写保存机制。

不创建“万能业务表单”或“所有列表通用管理器”。共享组件负责视觉与基本交互，业务状态继续留在 feature 层。

### 7.3 弹层、焦点和关闭行为

1. 用稳定回调处理 Escape/遮罩关闭，避免每次父级渲染重建焦点和滚动锁。
2. 滚动锁支持嵌套引用计数并恢复原 overflow；只关闭最上层弹窗，不误关下层工作台。
3. 首次焦点放在合理的输入或标题，危险确认默认聚焦取消；关闭后恢复有效触发器，触发器已不存在则回到页面合理位置。
4. 焦点候选排除 hidden、不可见、disabled、inert 等对象。背景内容对辅助技术和交互不可达，不能只依赖 aria-modal 声明。
5. 短表单用 Dialog；长对象详情用 Drawer；复杂多分区编辑用页面。不层层嵌套三四个弹窗。
6. dirty form 关闭由调用方按真实可恢复性判断；提交中是否可关闭明确约定。可后台执行的任务不通过禁用整个页面阻止离开。
7. 手机弹窗在视口内可滚动，头部和底部动作可达，输入法打开不遮住当前输入与保存按钮。

### 7.4 Toast 和错误反馈

- 成功 Toast 默认 3–4 秒；说明较长或可操作的通知至少 6 秒；指针悬停/键盘聚焦时暂停计时。
- 关键失败保留页面内 Alert 和重试，Toast 只作补充；不让唯一错误信息 4 秒后消失。
- 最多同时展示 3 条普通通知，重复任务合并更新，不无限堆叠。
- Toast 宽度使用 `min(384px, calc(100vw - 32px))`，考虑安全区和吸底操作条；不要同时 left/right/w-full 导致手机溢出。
- 明确层级：普通内容 < sticky < backdrop/dialog < nested dialog < notification。通知不能挡住弹窗关闭和提交按钮；弹窗内错误优先内联。
- 提示采用“发生了什么＋影响＋下一步”，技术码放可展开详情，可复制但脱敏。

## 8. 保存、错误、离线与异步状态

### 8.1 状态矩阵

| 状态 | 页面表达 | 操作 |
| --- | --- | --- |
| 首次加载 | 与最终布局相近的 Skeleton | 保留导航；阻止依赖未加载数据的提交 |
| 后台刷新 | 保留旧数据，小范围“更新中” | 不清空内容或重置表单 |
| 无数据 | 简短空态与首次创建入口 | 不展示大面积错误色 |
| 搜索无结果 | 当前条件摘要 | 清除或调整条件 |
| 加载失败 | 当前区域 Alert | 重试；有旧数据时注明可能不是最新 |
| 未配置依赖 | 说明缺哪个应用/模型/引擎 | 直接配置对应对象 |
| 保存中 | 按钮 loading + SaveStatus | 防重复提交，保留上下文 |
| 保存失败 | 字段错误或表单 Alert | 保留输入，重试或修正 |
| 版本冲突 | 比较本地与服务器版本 | 用户选择处理，不直接覆盖 |
| 离线 | 可读离线状态与同步信息 | 仅展示实际支持的离线能力 |
| 任务排队/执行 | 真实阶段 | 支持时取消，不假装已完成 |

### 8.2 查询与草稿

- 不全局开启聚焦刷新来解决局部配置同步；对模型状态、任务和必要列表定点处理。
- 同一 mutation 成功后只失效相关 query；不要每次按钮点击刷新全部门户。
- 独立维护“服务器快照”“本地修改”“正在提交的版本”。refetch 只能更新未修改字段或触发冲突处理，不直接 reset dirty form。
- 页面布局移动只改容器结构，避免因新 key 或条件分支反复挂载表单。
- 现有笔记离线能力保持；没有离线队列的服务操作，不能因为全局 offlineFirst 而显示“已提交稍后完成”的虚假承诺。逐调用点确认行为，修改需有测试。
- 异常边界、404 和 loading 若由框架提供，应在当前 vinext 路由行为下验证；不要添加约定文件后就声称已生效。

## 9. 响应式和可访问性验收

### 9.1 固定视口

必须检查 1920×1080、1440×900、1280×720、1024×768、390×844。增加 200% 缩放，用同一组数据比较默认和护眼主题。

桌面 >=1280px 才要求通用双栏；日历、目录树、媒体等可按内容最小宽度设置专用断点，不用一个断点强制所有工作区。小屏不得只缩小字号来保留桌面列数。

### 9.2 明确标准

- 主要任务入口在首屏可见：活动生成、列表新建、编辑保存、配置当前对象。
- 1920px 下标准卡片列表在数据充足时至少展示五列；少量卡片不撑成巨卡。
- 整页无横向滚动；表格、代码、时间轴需要横向滚动时局部承载并有提示。
- tabs、标签、工具栏可换行或局部滚动，不把页面撑宽。
- 所有图标按钮有可访问名称，键盘焦点清楚且不被固定条遮挡。
- 状态不只依赖颜色，错误与字段关联；页面标题、导航、主内容结构清楚。
- 普通文字对比目标至少 4.5:1，大号文字和重要非文本控件目标至少 3:1；需测量实际组合，不等同于已获得标准认证。
- 没有悬停的触摸设备仍能找到关键动作；不能靠 hover 才显示唯一编辑或删除入口。
- 读屏通知不在每次轮询时重复播报，重要失败可感知。
- reduced-motion 开启后流程正常，媒体播放器不受全局视觉动画关闭误伤。

## 10. 性能与稳定性优化边界

本轮没有运行性能基准，不能据静态代码声称某页面慢。先测量，再优化：

1. 在生产构建下记录首屏请求数、响应时间、JS 体积、布局偏移和关键交互耗时；开发模式数据不作为验收依据。
2. 检查生成工作台、媒体预览、复杂编辑器是否在页面首次进入时全部加载；仅对不在首屏且确实重的模块做按需加载。
3. 图片明确尺寸和比例，缩略图使用合理资源，首屏外懒加载；保留媒体内容完整预览。
4. 长列表先使用已有分页；只有真实数据量和性能测量证明必要时才引入虚拟列表，并考虑读屏、查找和焦点。
5. 任务轮询随终态停止，页面不可见时适度暂停；重试采用合理退避，避免服务失败时所有面板同时高频请求。
6. 保留已有按 hover/focus 的路由预取和节流网络判断，不扩大为预取全部管理数据。
7. 同一 API 的缓存共享，稳定 query key；不为样式统一重写 React Query 或 offline store。

优化验收以同环境、同数据前后比较为准，至少不增加不必要首屏请求和明显布局跳动；不要为了追求数字删除错误处理、附件预览或必要内容。

## 14. 建议完成次序

第一优先级是**控件与主题统一、导航完整性、弹层稳定性和可信状态反馈**；第二优先级是**各任务页面的密度与布局**；最后再做**动效和基于测量的性能优化**。

验收不以“所有页面都铺满屏幕”为目标，而以“用户能更快看见重要内容、知道当前状态、找到下一步，并在不同页面获得同样的操作体验”为目标。
