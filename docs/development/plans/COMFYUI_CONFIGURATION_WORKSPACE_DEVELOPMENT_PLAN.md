# ComfyUI 配置工作台改造：完整开发计划

日期：2026-09-13  
状态：待开发；产品范围已按用户最新需求收敛  
目标：更好的模型选择、工作流选择、简单参数配置和试生成体验  
实施原则：重做现有配置页体验，复用并完善后端，不新建平行系统

## 1. 本计划的优先级与范围

本文取代 `COMFYUI_INTEGRATION_V2_FEASIBILITY_AND_IMPLEMENTATION_PLAN.md` 作为当前实施依据。旧文档仅保留为远期研究，不执行其中的模型注册中心、硬件档位、认证体系和六套工作流建设。

用户要的是：选工作流 → 选兼容模型 → 配置参数 → 生成，并且能够方便地保存、测试和复用配置。不是维护 ComfyUI 基础设施。

本次不以减少开发时间为目标，但同样不以增加架构层数衡量质量。每项新增能力必须对应明确的用户操作。

### 必须交付

1. 原 `/settings/generation` 改为统一配置工作台，不增加第二个后台入口。
2. ComfyUI 直连为新连接的默认方式；已有 Worker 连接继续可用，归入高级选项。
3. 原生 API 工作流导入、配置包导入、工作流复制、草稿恢复、版本保存与配置包导出。
4. 从真实连接读取模型列表，配置兼容模型选项，按需支持已有 LoRA 槽位。
5. 可视化参数映射、默认值、允许范围、显示层级与画幅设置。
6. 常用生成预设：保存、编辑、复制、禁用、设为默认。
7. 在配置工作流的同一页面试生成，并核对实际使用参数与结果。
8. 创作中心选择已开放的工作流、模型和预设，表单随选择变化。
9. 后端权限与参数校验、完整任务快照、旧配置兼容和自动化回归。

### 不做

自动下载安装模型、自定义节点安装管理、远程 shell、训练 LoRA、GPU 自动选型、显存性能承诺、通用节点画布、任意 GUI 工作流转换、重新开发任务引擎、重新设计角色人设、移除服装或其他业务数据、修改邻舍内部。

正式范围优先保证文生图、图生图的完整新体验；保留已有视频功能和配置，不趁机迁移 h3-* 用途。通用表单可展示已声明的视频参数，但不承诺因此接入新的视频模型。

## 2. 现状与必须修正的问题

本节依据当前工作区源码静态检查，不代表已测试用户的 Windows / ComfyUI 环境。

| 现有实现 | 当前问题 | 改造要求 |
| --- | --- | --- |
| generation-settings 组合工作流、引擎、Worker、绑定和诊断 | 以技术对象罗列，配置与结果分离 | 按“连接、工作流、预设与默认用途”组织 |
| WorkflowPanel 有 JSON 导入按钮 | 后端实际要求 ID、名称和 definition 等项目配置包字段 | 新增原生 API JSON 分析与包装，不能只复用原按钮文案 |
| WorkflowEditor 多个 JSON 输入框 | 用户需手工维护输入结构、绑定、输出等 | 默认图形化配置，高级模式才显示 JSON |
| EnginePanel 支持 ComfyUI 地址 | 缺少连通性检查与已安装模型选择体验 | 增加连接测试、模型/节点只读发现 |
| WorkerPanel 显示 model、temperature | 人工备注容易被误认为实际生成模型与采样参数 | 从普通配置区移除；旧值保留在兼容高级区并说明用途 |
| AssignmentPanel 按用途绑定固定版本 | 当前图片/视频选项还按引擎类型硬编码过滤 | 改为实际输入/输出与执行适配能力判断，保留不支持场景的明确提示 |
| CreativeTaskInput 主要是固定参数，没有预设选择 | 仅增加前端下拉框不会改变真实执行 | 增加受控 presetId 解析与参数通道 |
| task-store 禁止客户端任意指定工作流 | 是有价值的安全边界 | 保留，通过后端授权预设实现工作流选择 |
| 快照、幂等、调度与产物仓库已存在 | 不能另起任务体系，否则丢失恢复与溯源 | 新配置与试运行都复用原任务核心 |

关键源码：`app/features/generation/*`、`app/apps/creative/creative-client.tsx`、`app/features/creative/*`、`apps/service/src/management.ts`、`creative.ts`、`generation/*`、`worker.ts`、`workers/windows-worker/*`、`packages/contracts/src/index.ts`。

## 3. Windows 连接方案

### 默认：Web 界面 + SthStart 后端直连

浏览器 → SthStart Service → Windows 上的 ComfyUI。

这不是浏览器运行模型。Windows 上仍需安装并启动 ComfyUI、模型和工作流所需节点；普通 API 对接不需要额外安装本项目 Worker 或 ComfyUI 插件。ComfyUI 已提供模型、节点、任务、图片上传与结果接口。[官方 API 文档](https://docs.comfy.org/development/comfyui-server/comms_routes)

### 可选：沿用 Windows Worker

浏览器 → SthStart Service → Windows Worker → ComfyUI。

适用于已有部署或需要本地媒体处理等情况。保留 token、IP 白名单、单任务并发与磁盘保护，不要求用户重新配置正常工作的 Worker。

当前项目直连输入只支持图片；视频/音频输入仍依赖 Worker。不能仅删除页面上的类型限制就宣称支持全部媒体。Worker 已提交任务的取消目前只是停止本地跟踪，本轮继续真实说明，不显示“远端已停止”。

### 部署边界

| 部署 | 地址理解与要求 |
| --- | --- |
| Service 和 ComfyUI 同在 Windows 宿主进程 | 可使用回环地址；地址指向后端所在机器 |
| Service 在 Docker，ComfyUI 在 Windows 宿主 | 容器中的 127.0.0.1 不是宿主；需核实宿主可达地址、监听与防火墙 |
| Service 在另一台局域网机器 | 使用目标 Windows 的受控局域网地址，仅允许所需访问 |
| Service 在公网、ComfyUI 在家中内网 | 需要安全网络通道；不是填写一个 localhost 就能连通 |

测试连接必须由后端发起。浏览器不拿 ComfyUI/Worker 凭据，不开一个任意 URL 代理；默认不直连内网 API。不得自动修改 Windows 防火墙、路由、跨域策略或把 ComfyUI 暴露公网。

## 4. 产品结构与布局

沿用既有 AppShell、主题、表单和弹层组件，不为本次增加前端框架。页面结构重做，设计令牌不另起一套。

### 4.1 配置页：三个主标签

- **工作流**：主要工作区，默认进入这里；没有连接时显示引导卡。
- **连接**：统一管理直连与 Worker，普通用户主要填名称和地址。
- **预设与用途**：常用生成配置、哪些入口可选、默认配置。

原诊断信息保留为连接详情内的“高级诊断”，不再占据日常主流程。

### 4.2 工作流工作区

宽屏 >=1440px：左工作流列表 240px、中间编辑区至少 560px、右侧试运行区 340px；剩余宽度弹性分配，布局须按实际可用宽度降级。

1024–1439px：列表收窄或改选择器，编辑区为主体，试运行结果按按钮打开侧抽屉。

<1024px：单列；工作流选择器 → 编辑页签 → 操作栏；结果独立页签/全屏抽屉，不在手机强塞三栏。

现有导航会占宽度，不能只看 window.innerWidth 就强行启用三列。桌面可独立滚动各栏；手机自然滚动，软键盘弹出时输入和操作不被固定栏遮挡。

### 4.3 全局交互规范

- 页头固定当前工作流名称、保存状态、当前版本；ID 与技术信息折叠。
- 每个上下文只突出一个主动作，不能让“保存、测试、启用、生成”同时使用最高视觉权重。
- 表单标签常驻，不仅使用 placeholder；错误定位到具体字段/页签，原输入保留。
- 使用已有中性/暖色主题；触控主要按钮 >=44px；键盘可完成导入、选择、保存与试运行。
- 切换工作流/关闭抽屉时保留草稿；发生保存失败或版本冲突必须提示，不静默覆盖。
- 数据局部加载：某个连接离线，不让整个配置页面进入失败空白。

## 5. 连接功能规格

### 常用字段

名称、连接方式（默认“ComfyUI 直连”）、地址、可选凭据、启用状态。“内部 ID”自动生成，高级区可查看。

高级区包含并发、请求头和已有 Worker 配置；新建单 GPU 连接的建议并发为 1，但不静默更改旧连接值。

### 必须支持的操作

- 新建、编辑、测试连接、刷新模型列表、禁用。
- 删除前显示引用该连接的默认用途、预设和工作流；有活动任务或引用时阻止删除并提示处理方式，不能级联删除业务数据。
- 列表展示：名称、方式、地址摘要、连接状态、最近检查时间。
- 详情展示 ComfyUI 可达性与可获取的基础信息。连接成功不代表所有工作流可运行，也不因拿不到 GPU 信息而判连接失败。
- 凭据读取不返回明文；编辑留空表示保持原值，清除必须显式选择，避免误删。

### 只读发现

后端适配器提供统一的 `testConnection`、`listModels`、`getNodeDefinitions`。ComfyUI 直连访问现有 API；Worker 模式走受鉴权的最小透传/规范化接口。

发现数据先使用短期内存缓存，默认 60 秒，手动刷新绕过缓存；合并重复请求、限制上游响应大小和超时。失败保留最后成功结果并标“可能过期”，不能解释为模型被删除。

不建模型注册数据库。模型列表是实时/缓存视图；找不到接口或旧 Worker 不支持时显示明确原因，允许查看旧配置和原样运行兼容任务，不伪造空列表。

## 6. 工作流导入与编辑

### 6.1 支持三种输入

| 输入 | 行为 |
| --- | --- |
| 原生 ComfyUI API JSON，节点 ID 为对象键 | 分析图 → 用户填写名称/选择连接 → 配置参数 → 保存 |
| 本项目配置包 | 恢复 definition、参数映射、界面配置和预设；导入连接引用需重新确认 |
| 含 nodes/links 的 GUI JSON | 明确提示改用 API 格式导出，保留文件；不做未经验证的自动转换 |

不将 `/workflow_templates` 误用为“用户所有已保存工作流”的枚举接口。第一版工作流来源就是用户导入和项目已有记录。

导入先只分析，不自动发布、不提交生成、不覆盖同名记录。名称重复可提示“复制为新工作流”；ID 由系统生成。已有工作流的重新导入创建草稿，明确展示配置映射是否失效。

### 6.2 编辑区四个标签

1. **模型**：实际模型组件、允许的切换选项、LoRA 槽位。
2. **参数**：业务字段、默认值、范围和显示层级。
3. **输入与输出**：参考图槽位、必填、媒体类型、输出节点与预览类型。
4. **高级**：API JSON、节点映射、版本信息、导入来源。

新用户可以按顺序完成；熟练用户直接切换，不做不能回退的强制向导。

### 6.3 自动分析的范围

- 从 definition 和节点信息识别标量输入、枚举与输出节点候选。
- 提示词、反向提示词、尺寸、seed 等语义使用已知节点适配 + 用户确认；未知节点只显示技术字段，不猜成正确语义。
- 排除节点连线数组，不能把 `[nodeId, outputIndex]` 直接暴露成普通参数。
- 保留未知节点与所有未映射输入，不能通过可视化保存删掉原图内容。
- 绑定目标必须是存在的 nodeId / inputs / inputName；类型兼容。一个语义需要影响多个节点时明确标不支持自动映射，保留高级工作流配置，不悄悄只改第一个。
- 沿用当前单目标 nodeBindings，本轮不引入通用图改写器。测试覆盖多采样器情况下既有 seed/noise_seed 替换行为，避免界面承诺与真实执行不一致。

## 7. 模型选择：真实且不误导

模型选择本质是修改工作流加载节点的输入值，不是修改 Worker.model 备注。

### 7.1 单个主模型

例如 checkpoint 工作流：展示“主模型”下拉框，来源为目标连接的相应库存/加载节点枚举。选择后写入已确认的节点输入，试运行和日常生成都使用该选择。

### 7.2 多组件模型

diffusion model、文本编码器、VAE 等分别保留加载节点映射。常用面板可以显示“模型组合”名称，展开后看到所有组件。

第一版不建独立模型组合库：不同组合保存为普通生成预设。需要固定配套组件的工作流，不允许日常单独切换主模型；通过预设切换整组。

### 7.3 兼容范围

模型文件存在不代表适合当前工作流，不同家族可能需要不同加载器与图结构。[官方模型说明](https://docs.comfy.org/basic-concepts/models)

- 可配置者从库存中明确圈定允许选择的模型；默认仅允许导入图中原有模型。
- 后端校验“用户允许列表 ∩ 当前可见库存/加载节点枚举”；过期缓存需刷新后再确认缺失，不能自动改选其他模型。
- 若不能证明跨组件兼容，要求选择成套预设，不输出“自动兼容”的结论。
- 已配置但当前缺失的模型保留名称，标缺失，不从表单中静默删除。
- 模型列表支持搜索，保留相对路径；同名不同子目录不能混淆。禁止任意绝对路径或路径穿越。

### 7.4 LoRA

支持工作流已有 LoRA 加载槽位的模型选择和强度调整；没有槽位时显示“此工作流未配置 LoRA”，不动态插入节点。

关闭行为由工作流具体定义：有受支持旁路开关则映射开关，否则可配置强度为零，但仍可能需要文件存在。不能把“零强度”当作无需模型文件。不得把 LoRA 名称或参数写入角色人设文本。

## 8. 参数表单与预设

### 8.1 配置者可编辑的字段属性

| 属性 | 职责 |
| --- | --- |
| 字段键与节点绑定 | 决定实际执行修改的位置 |
| 名称、说明、顺序、分组 | 日常界面表达 |
| 类型 | 文本、长文本、整数、小数、布尔、枚举、模型选择；媒体沿用媒体槽 |
| 默认值与允许范围 | 后端与前端共同遵循，不重复维护两套规则 |
| 显示层级 | 常用 / 高级 / 固定；固定字段不能被客户端覆盖 |
| 枚举/允许模型 | 控制合法选项，既有未知值不能自动替换 |

图片常用：提示词、支持时的反向提示词、画幅/尺寸、seed。Steps、CFG、采样器和调度器默认放高级区或固定。图生图按工作流增加原图和重绘强度。没有映射的参数不展示。

### 8.2 校验规则

- 沿用现有 inputSchema，增加版本标识和明确支持的字段子集，不引入任意脚本或远程 Schema 引用。
- 默认值、min/max/step、枚举唯一存于 inputSchema；界面配置只引用字段键。
- 除单字段范围外支持简单组合限制：maxPixels、batchSize、合法尺寸组合。尺寸 preset 是具体宽高值，不是另一套权威边界。
- 各模型参数使用工作流自己的默认值，不再全局固定 1024、20 steps 或 4096 上限作为完整校验。
- Service 拒绝 NaN、无穷、非法类型、未知参数、越界、固定字段覆盖；不要静默截断或钳制。
- 媒体权限、大小、类型仍走原有输入链路。客户端提交 artifactId，不提交机器文件路径。
- 预设和用户参数冲突时优先级为：工作流默认 → 已选预设 → 本次允许修改的输入。随后统一校验。

### 8.3 常用预设

预设不是另一份工作流，而是“确切工作流版本 + 连接 + 模型选择 + 一组参数值 + 开放用途”。

支持创建、另存为、改名、编辑、复制、禁用和显式设为默认；例如“角色立绘”“横向场景图”。是否存提示词由用户决定，默认不把当前临时提示词或私人参考图保存为共享预设。

切换预设只替换它明确包含的值；若会覆盖用户已编辑值或清除不适用媒体，先展示差异并确认。新旧字段不兼容的输入保留可恢复草稿，不悄悄丢失。

预设引用版本固定，不自动追随 latest。工作流新版本出现时提供“复制预设到新版本”，检查映射和参数差异，不能原地升级所有用户预设。

## 9. 同页试生成

试生成是本次核心功能，不能只做一个链接跳到创作中心。

1. 用户在右侧测试区填写提示词与所需媒体。
2. 点击“保存并试生成”：先验证并保存当前内容为不可变工作流版本，再创建真实任务。没有变化则复用该内容对应版本。
3. 保存版本不自动开放到创作中心；现有 `is_published` 可以继续表示版本可解析，真正业务开放由预设/用途绑定控制，UI 不称“发布即全站启用”。
4. 试运行接口只允许管理员，服务端选择固定测试用途和应用身份；不能把内部 isInternal 开关开放给普通客户端。
5. 保存成功、提交失败要分别显示；重试提交沿用原幂等键，结果未知先查询，不再保存/提交一份。
6. 任务复用现有队列、状态、媒体仓库与恢复机制。页面关闭不取消后端任务，重新打开能找到历史测试。
7. 显示排队/执行/错误/结果，以及真实工作流版本、模型、输入参数、实际 seed 和实际耗时；来源为任务快照，不从当前表单推算。
8. 结果支持放大、下载、复制参数、另存预设。结果区域编辑器改变后标“来自此前版本”，避免误认当前配置已测成功。
9. 不伪造百分比与生成结果；暂不支持远端取消的连接明确显示“停止跟踪”及警告。

测试任务建议归属已有 `creative-center` 应用的固定 `configuration-test` 用途，测试输入走该应用现有授权上传，产物默认在测试记录中可查；是否纳入普通创作列表用用途筛选明确区分，不另建媒体仓库。

## 10. 创作中心与其他业务入口

### 10.1 日常创作

第一行：工作流选择 → 预设选择；模型仅在当前配置允许单独调整时展示，否则显示预设中的模型组合摘要。

下一部分：提示词、画幅、按需输入图；高级参数折叠。右侧/下方仍复用现有生成结果与媒体库。

“工作流选择”来源不是全量管理员工作流，而是至少有一个对当前应用/用途启用的预设所引用的工作流。选工作流后选其可用预设；每个开放工作流至少提供一个基础预设。

### 10.2 服务端解析与默认用途

- 新请求允许 `presetId`、`presetRevision` 与 `parameters`；不允许裸 `workflowId/engineId/definition`。
- 服务端验证预设属于当前应用/用途、已启用、版本有效、连接有效，然后解析内部工作流和引擎。
- 未传 presetId 的旧客户端继续使用已有用途绑定，原请求形状不变。
- “设为默认”在短事务里同步既有用途绑定和新增 default_preset_id；默认模型/参数覆盖由新版解析器加载该预设，不能只更新工作流 ID 而丢掉模型选择。
- 显式选择非默认预设不会修改全站默认。
- 预设读取与任务创建固定同一 revision；过期请求返回冲突并提示重新确认，不能静默用另一套参数执行。
- 日常用户可调整字段来自服务端契约，不信任前端 visibility 或 allowlist。

### 10.3 其他消费者

活动配图、角色头像等继续使用各自应用与用途默认配置。可以复用统一表单/参数解析，但本轮不强制在每个页面加入工作流下拉框。

新参数校验必须位于共享生成入口，不能只有创作中心校验，导致活动内部调用绕过。保留已采用图片、引用、回放与人设快照，不自动替换现有媒体。

## 11. 最小数据方案

原则：复用已有工作流、版本、连接、绑定、任务和媒体表。仅为持久草稿与预设新增两张表；不建模型/GPU/依赖认证表。以下为拟定设计，迁移序号以开发时最新数据库为准。

### 11.1 扩展既有工作流版本

- `config_format_version INTEGER NOT NULL DEFAULT 1`：旧配置保持 V1，新编辑器保存 V2。
- `editor_config_json TEXT NULL`：字段显示信息、模型字段分类/切换策略、画幅组合与简单跨字段约束。
- default、enum、数值范围仍只写 input_schema_json；实际路径仍只写 node_bindings_json；媒体与输出仍用原列。
- 工作流表增加可选 archived_at，以归档替代删除历史版本。

editor_config 示例为结构说明，不是新增并行参数源：

```json
{
  "version": 2,
  "fields": {
    "prompt": { "label": "提示词", "section": "basic", "order": 1 },
    "steps": { "label": "步数", "section": "advanced", "order": 10 },
    "checkpoint": { "label": "主模型", "section": "basic", "widget": "model", "modelCategory": "checkpoints" }
  },
  "modelSelection": "individual",
  "sizePresets": [],
  "constraints": {}
}
```

### 11.2 工作流草稿表

`generation_workflow_drafts`：workflow_id 主键/FK、base_version、revision、draft_json、updated_at。单工作流一个管理草稿，多窗口用 revision 乐观锁。

草稿包含尚未保存的整个配置，是编辑状态，不是运行时第二份权威配置；执行永远读取不可变版本。保存后标记已同步 base_version，不能让旧草稿覆盖后来版本。

新导入先创建未发布版本的工作流外壳和草稿；只有保存版本后才可试运行/创建预设。离线编辑以本地草稿辅助，恢复连接时冲突确认后同步。

### 11.3 预设表

`generation_presets`：id、name、description、app_id、purpose、workflow_id/version 复合引用、engine_id、values_json、enabled、revision、created_at、updated_at。

- values_json 仅保存覆盖值，不复制 workflow definition、字段 Schema 或完整模型库存。
- 对应用/用途/启用状态建索引；删除/禁用被默认引用的预设前要求换默认或显式取消默认。
- 预设修改递增 revision；已经创建的任务不跟随变化。
- 编辑默认预设的工作流/连接引用时，必须在同一事务同步对应用途绑定；若该操作会改变默认执行，保存前明确提示影响。禁止预设和绑定指向不同版本后由两种客户端执行出不同结果。
- 跨用途复用通过“复制预设”完成，不在一条记录中保存难以授权的任意 appId 数组。

`app_generation_assignments` 增加 nullable default_preset_id；未填时完全沿用旧配置，保证迁移时默认行为不变。

### 11.4 任务溯源

复用 request_params_json 和 workflow_snapshot_json。前者增加可选 selection 元信息：presetId/revision、connectionId、resolvedValues 和测试用途标记；不要再新增一张配置快照表。

生成请求哈希应覆盖确切工作流版本、连接、规范化输入与媒体引用等执行身份；同幂等键但模型/预设配置变化必须冲突。同一幂等键已存在时先核对原请求，不能因预设后来编辑而把成功请求误执行第二次。

### 11.5 已有重复存储

当前工作流媒体配置存在版本列与 legacy 媒体表双写。此轮不新增副本、不顺手删表。新编辑器仍通过同一适配层保存；若有差异保留报告，另批迁移清理。

## 12. API 与协议改造清单

以下新接口为建议名称，实施时遵循项目路由风格。既有创建/导入/版本/用途接口继续兼容。

| 接口 | 内容 |
| --- | --- |
| `POST /api/v1/admin/generation/engines/:id/test` | 后端测试已配置连接，只返回脱敏状态 |
| `GET /api/v1/admin/generation/engines/:id/models` | 类型/搜索/分页/刷新库存视图 |
| `GET /api/v1/admin/generation/engines/:id/nodes` | 按工作流所需 class_type 获取节点输入信息 |
| `POST /api/v1/admin/generation/workflows/analyze` | 接收 API JSON 或配置包，返回候选映射、错误与导入草稿，不执行 |
| `GET/PUT /api/v1/admin/generation/workflows/:id/draft` | 草稿读取与带 revision 保存 |
| `POST /api/v1/admin/generation/workflows/:id/duplicate` | 新 ID 复制配置，不复制任务和密钥 |
| `GET /api/v1/admin/generation/workflows/:id/versions/:version/export` | 导出不含凭据和私有媒体文件的配置包 |
| `POST /api/v1/admin/generation/workflows/:id/test-runs` | 保存/引用确切版本后的鉴权试运行；返回原任务体系 ID |
| `GET/POST /api/v1/admin/generation/presets` | 管理预设列表/新建 |
| `PUT /api/v1/admin/generation/presets/:id` | 带 revision 编辑、禁用，校验引用与覆盖值 |
| `GET /api/v1/admin/creative/options?purpose=...` | 当前应用可用预设、工作流和表单契约的安全投影 |

创作提交接口仍用既有 creative/tasks，兼容新增 presetId/revision/parameters。字段同名同时出现在旧顶层输入与新 parameters 时拒绝含糊请求，或通过显式协议版本只接受一套，不能有隐式优先级。

Worker 仅增加鉴权后的模型/节点只读发现端点与 supportedFeatures 可选字段；旧 Worker 不支持时返回“需升级以读取列表”。不要让前端保存另一份 Worker 后面 ComfyUI 的访问地址或密钥。

本轮直连/Worker 的切换不自动改变工作流 engine_kind。跨执行方式复制或迁移配置应生成新的工作流/版本，重新确认输入媒体与输出支持，原绑定保持不变。

## 13. 安全、错误与边界

- 所有编辑、导入、发现、测试都经过现有管理鉴权；日常应用只得到自己的可选预设。
- 不向前端返回凭据、完整环境变量、本地绝对路径；模型相对名仅在有权限的配置/生成契约范围内返回。
- 导入限制文件大小、节点数、嵌套深度并做敏感字段检查；不得执行导入 JSON 中的脚本或表达式。
- 连接测试仅访问已配置并验证的 HTTP(S) 引擎目标，不能跟随重定向绕过目标限制。
- 安装列表不证明权重兼容；只做基础节点、绑定、模型选项与参数检查，错误可解释即可，不建立“认证平台”。
- 检查配置不调用 POST /prompt；只有“试生成/生成”明确触发实际任务。
- 模型缺失、节点缺失、参数非法、权限不足、连接超时分别给出可操作说明。
- OOM/上游失败显示真实原因，不自动换模型、减尺寸或重试，除非用户明确操作。
- 取消能力沿用实际支持范围；不得用全局中断误杀其他用户在 ComfyUI 中运行的任务。
- 历史成功不显示为永久“验证通过”；最多标“该版本最近一次测试成功”，并显示模型和时间。

## 14. 兼容迁移与上线

1. 记录现有连接、工作流、版本、用途绑定与任务样本；备份并验证可恢复。
2. 执行加法迁移，旧字段不删除，旧 default_preset_id 为空，原任务继续运行。
3. 将旧配置投影成新编辑器：可识别字段显示正常控件；无法识别的保留高级区，标“需确认”，不丢失原 JSON。
4. 原生 API 导入走新分析器；旧配置包仍走兼容解析，不要求用户重做全部配置。
5. 不自动创建会改变旧参数的默认预设。用户首次编辑/另存时再保存新版本和预设。
6. 新配置页替换原入口；开发过程可短期用受控开关回退，但交付后不能长期维护两个同等入口。
7. 新创作选择上线后，旧客户端未传预设时仍按用途绑定工作。h3-* 旧用途、视频任务和媒体引用不迁移重命名。
8. 既有 Worker 正常配置保留；“默认直连”只影响新建向导，不强制替换用户部署。
9. 本轮不自动升级 ComfyUI、下载权重、调整防火墙或重启生产服务；实施部署时另按用户授权执行。

回滚优先切回旧页面/接口投影、恢复旧默认绑定；保留新增表与任务数据。数据库恢复须停写并评估新增数据，不能直接拿旧备份覆盖上线后的成果。

## 16. 分阶段开发与退出条件

### A：固定交互与契约

交付连接、工作流、预设三个页面的关键状态设计，以及字段/预设/任务选择契约。选一套现有可运行图片工作流作为贯穿样本，不指定必须下载哪个热门模型。

退出：能明确说明用户如何从导入走到试生成，以及一个下拉框选择如何落到真实节点输入。

### B：后端配置与真实发现

交付加法迁移、草稿/预设 API、模型/节点发现、参数验证、旧配置适配。先用协议 mock 做覆盖，但界面不得把 mock 状态当实机在线。

退出：旧请求仍可执行；模型选择影响真实快照；非法模型与参数在提交前被拒绝。

### C：替换现有配置页

交付工作流工作区、导入分析、模型/参数编辑、自动保存、版本/冲突处理与配置导出。移除主流程的 JSON 手填和 ID 要求，保留高级功能。

退出：无需手写 JSON 可配置样本工作流；复杂未知配置可保留并继续高级编辑。

### D：试运行与创作选择

交付同页真实任务、结果与参数核对；创作中心的工作流/模型/预设选择；默认用途更新与权限检查。

退出：选不同允许模型或预设实际改变快照与输出链路；配置测试不改变默认用途；刷新页面能找回运行中的测试。

### E：兼容、视觉与实机验收

交付旧配置迁移报告、自动化结果、目标 Windows 上真实图片闭环、两套主题与多视口证据、操作说明和回滚说明。

退出：下方验收清单通过。机器/模型不可用时仅能宣布“代码部分完成，实机验收待完成”，不能宣称全部功能可用。

不以固定天数压缩体验工作，也不因“不在乎效率”增加无关系统。按退出条件逐阶段确认质量。
