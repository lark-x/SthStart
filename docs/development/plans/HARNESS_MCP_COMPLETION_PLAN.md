# Harness MCP 能力补全计划

日期：2026-10-06（Asia/Shanghai）  
状态：2026-10-06已实现P0–P6及P7文档、客户端/自动化验收；P7真实外部模型与付费小样、逐镜/逐句质量验收待指定测试作品和批准额度。当前源码Story 9工具、Publication 22工具；未部署。实施证据见 [实施记录](../logs/harness-mcp-completion-implementation.md)。

## 1. 目标与完成标准

使已配对项目的 harness 能从一个新会话开始，自行找到工作对象，读取正式资料和冻结来源，编写与调整制作方案，检查配置，等待人工批准，执行制作，读取真实产物进行审阅，并完成选图、选音频和导出。恢复会话时以服务端记录为准，不要求用户重新提供此前的作品、运行或产物 ID。

正式剧情仍经提案审阅后生效；制作草稿允许 MCP 编辑；费用批准仍由网页人工完成。技术执行成功与作品质量合格分别记录，不以任务 succeeded 代替画面、动作或读音验收。

整体完成须满足：

1. 新会话仅依赖项目配对即可列出作品、找回运行、读取来源与历史候选，无须管理员凭据。
2. harness 可查看实际图片，了解音频与导出文件状态；客户端不支持媒体时有明确降级路径。
3. 方案配置来自可查询的有效选项，提交前可以得到稳定、可定位的问题列表。
4. 单句或单镜头修改不会要求重新输出整份文档，保留并发修改检测及正确的媒体失效规则。
5. 已批准制作、停止、重绘、配音重试和导出保持幂等、额度和未知结果处理规则。
6. 新旧工具兼容；至少验证 DSH 和一个其他标准 MCP 客户端。
7. 自动化测试、真实模型联调、媒体质量审查分别给出证据和未验证项。

## 3. 设计原则

- 两套 MCP 继续分工，项目 ID 来自配对环境，模型不能借参数切换项目。
- TypeBox 共享契约先行，再实现服务、Portal 白名单、MCP 适配器和必要的网页调用；私有实现类型不迁入 contracts。
- 工具复用业务服务，不在 MCP 层直接写数据库、调用另一条生成链或实现第二套费用逻辑。
- 读取接口分页、有上限；长正文分段；作品和任务列表返回摘要，详情按需读取。
- 写入使用明确的 expectedDraftVersion/baseRevision。发生冲突先返回最新版本和冲突信息，不自动覆盖。
- 所有产物通过项目、作品、镜头/对白归属及服务端产物引用校验；不能凭任意 artifactId 访问文件。
- 不向工具返回密钥、管理员 Cookie、本机绝对文件路径或完整第三方请求日志。
- 原有工具名、语义保持稳定。新名称为计划建议，实施时以契约审查定稿；不为追求工具数量拆碎操作。
- 不引入长期无人值守自动重绘。模型审阅可以提出建议，花费仍受现有批准和额度控制。

## 4. 阶段与交付顺序

### P0：固定契约、测试入口与兼容基线

**范围**

- 核对当前工作区差异、十四工具的请求/响应、桥接路由和调用方，保留已有未提交工作。
- 建立“工具—契约—路由—鉴权—测试”对照表。
- 补 Publication 的 stdio 客户端测试，覆盖初始化、工具发现、八工具请求映射及错误响应。
- 扩展测试入口，使 `test:mcp` 清楚覆盖两套 MCP 协议测试；桥接、存储和 worker 测试仍按职责分组。
- 校验测试命令与项目 Node 支持范围，必要时统一显式 tsx 加载。
- 为新增工具确定结构化错误约定：错误码、可读说明、是否可重试、当前版本、具体字段/目标；保留原有文本兼容输出。
- 列表游标采用确定性排序；不将变化中的整份文档塞入列表。

**验收**

- 现有十四工具行为未改变；制作 MCP 的真实 stdio 适配层有可重复的模拟上游测试。
- 未知工具、非法参数、HTTP 错误、超时、非 JSON 响应均返回受控错误。
- 契约字段不会被 Fastify 响应序列化遗漏；跨项目访问与撤销凭据用例通过。

### P1：作品发现与会话恢复

**建议新增工具**

| 工具 | 核心输入 | 核心输出 |
| --- | --- | --- |
| list_publications | cursor、limit、可选标题过滤 | 作品 ID、标题、草稿版本、更新时间、最近运行摘要、nextCursor |
| list_runs | activityId、cursor、limit、可选状态 | 运行 ID、批准 ID、状态、实际用量、时间与nextCursor；详情继续用get_run_status |

**实现**

- 作品列表只返回本项目的独立制作作品，不把旧活动误归入新模式。
- 基于现有存储增加作品摘要查询；扩展当前最多50条的运行查询为真正分页。
- 增加相应项目桥接路由与精确 Portal 白名单。
- 区分“存在历史批准”与“该批准对当前草稿和配置有效”，不得只凭 approval 非空提示可启动。
- 列表和状态里给出确定性的下一步原因，如待提交、待人工批准、执行中、存在未知结果；不由模型猜测状态。

**验收**

- 新会话可发现已有作品，取得最近运行并恢复查询，不依赖旧聊天中的 ID。
- 空列表、多页、相同时间排序、其他项目 ID、已撤销凭据均覆盖。

### P2：候选历史与真实产物读取

**建议新增工具**

| 工具 | 用途 |
| --- | --- |
| list_shot_images | 分页读取某镜头图片历史、当前选择、文件是否可用、来源是否过期 |
| list_utterance_audio | 分页读取某句音频历史、时长、当前选择、来源是否过期 |
| get_publication_media | 读取当前作品图像、音频、导出文件的摘要及可用状态 |
| read_publication_artifact | 在作品范围内读取指定产物的元数据或受限预览 |

**实现**

- 复用 history、audioHistory 和产物引用；为图片历史补齐与音频一致的 staleSource 语义。
- 核对图片、音频、封面、视频、ZIP各自的归属路径；导出产物也必须验证归属。
- 图片以有尺寸和字节上限的 MCP image 内容返回预览；元数据注明预览变换，不把缩略图伪称原图。
- 音频先保证元数据、时长和受鉴权播放/资源路径；对支持 MCP audio 的客户端提供有上限的预览。客户端能力不足时明确要求网页听审。
- 视频及 ZIP 不以内联巨大 base64 返回；提供元数据、对应网页入口，必要时提供受鉴权资源读取。资源 URI 不携带桥接 Token。
- 权限检查贯穿媒体请求，凭据撤销后后续读取失效。不要把预览实现为可以抓取任意 URL 的通用代理。
- 无多模态能力的 harness 仍能查询元数据，但不得报告自己已看图或听音频。

**验收**

- harness 可读取至少两个同镜头候选图并选择其中一个；文件缺失、隔离、归属错误和过期来源有明确结果。
- 超大媒体被限流/拒绝或返回受控预览，不阻塞 stdio 主通道。
- 对非当前选择但属于该作品历史的合法产物仍可审阅。

### P3：配置发现、方案校验与执行预检

**建议新增工具**

| 工具 | 用途 |
| --- | --- |
| get_publication_options | 按类别读取可用工作流、预设、语音配置/声音，以及明确授权的参考资产与 LoRA 选项 |
| validate_publication_plan | 检查候选文档，返回字段问题、影响的镜头/对白和修复建议；不保存、不发起模型调用 |
| preview_publication_run | 针对已保存版本计算最终配置、预计图片数/配音字符数、依赖状态、批准有效性与失效原因 |

**实现**

- 复用 image-options、speech 配置、worker.configuration 与已有文档校验。
- 参考图只列作品可用的资产；不要直接开放全局媒体库。LoRA 可用状态需复用现有校验，并隐藏内部路径。
- 对配置返回 id、名称、版本、必要能力和可用性，不返回密钥引用细节。
- 候选文档检查覆盖来源固定、角色引用、ID重复、结构化英文提示词、镜头/对白限制、声音与工作流选项。
- 明确草稿保存允许不完整与可执行方案必须完整的区别；统一工具描述、契约和服务对“6–12关键帧”的执行规则。
- 预检报告 FFmpeg/FFprobe、模型/LoRA、媒体等确定性依赖；未实际联网验证的提供商能力标记未验证。
- 数量和字符数是额度估算，不伪造货币费用。最终启动仍重新校验，不能把预检当永久保证。

**验收**

- harness 能从真实选项编写方案，对无效配置定位到字段或镜头。
- 校验/预检不改变草稿、不创建生成任务、不消耗模型额度。
- 预检后配置变化会使原批准失效，并在启动时被再次拦截。

### 第一批交付关口：P0–P3

用户可以启动一个新 harness 会话，让其找回作品、读取冻结章节与已有图片、选择可用配置并提交可审阅方案。仅此一批即可单独交付，不依赖后续扩展。

### P4：局部编辑与冲突处理

**建议新增工具：patch_publication_plan**

- 输入 activityId、expectedDraftVersion 和有数量上限的类型化操作数组。
- 首批只支持更新标题/发布文案、角色视觉与声音绑定、镜头画面描述/提示词/设置、对白文本及声音绑定。
- 操作使用稳定 ID，不使用数组下标；可编辑字段白名单不得包含 source、媒体选择、批准、预算或任务状态。
- 区分未传字段与显式 null；整批原子提交，经同一完整文档验证和 save 流程生成新版本。
- 返回新版本、变更目标、失效图像/音频、批准影响摘要。
- 版本冲突返回409及当前版本信息；harness重新读取后重做补丁。首版不做自动三方合并。
- 新增/删除/重排镜头继续用现有完整方案提交，待实际需要证明后再扩展局部操作。

**验收**

- 仅改一句时只使对应音频失效；改镜头视觉提示词只使对应图片失效。
- 后台媒体回写与用户编辑并发时不会静默丢失内容。
- 跨目标非法操作整批失败，不发生部分保存；旧完整提交工具继续可用。

### P5：配音调整与独立导出

**建议新增工具**

| 工具 | 用途及约束 |
| --- | --- |
| select_utterance_audio | 从本句历史选音频，带版本检查及过期来源确认 |
| retry_utterance_audio | 仅在已批准且仍有效的声音/文本配置与剩余字符额度内重试指定句 |
| export_publication | 针对确定草稿版本创建幂等导出，不重新生图或配音 |
| get_publication_task | 查询独立导出及子任务，避免要求客户端知道内部任务关联方式 |

**实现**

- 选音频和导出复用既有服务；配音重试补齐 worker 原子额度预留及幂等，不通过重新启动整轮来重试一句。
- 已成功且相同的配音优先复用；重复请求返回原任务，不能重复消费字符额度。
- running/unknown 状态禁止自动重投；停止语义保持“停止后续、尽力取消上游”。
- 改声音、正文或配置后，需要重新核对批准；不借重试绕过旧批准快照。
- 配音重试不可超出当前批准剩余额度；没有剩余额度时回到网页重新审批，不自动增额。
- 独立导出绑定不可变版本；仅改选图也可重新导出，缺图/缺音/文字溢出/依赖缺失须明确失败。
- 沿用现有导出任务关联；若需要扩展任务查询契约，明确活动归属，不创建平行任务系统。

**验收**

- 选音频、单句重试、独立导出分别覆盖版本冲突、归属、幂等、失效和额度边界。
- 导出重复调用不新增模型请求；成功文件可在 P2 读取元数据或访问入口。

### 第二批交付关口：P4–P5

harness 可完成“提出具体修订—修改一句或一镜—人工重新批准（如需要）—定向制作—审阅候选—重新导出”，无需反复重写全文或重跑整部作品。

### P6：剧情历史与提案续接

**建议新增 Story 工具**

| 工具 | 用途 |
| --- | --- |
| list_proposals | 分页查本项目提案，可按状态/目标筛选；返回基准版本及是否已过期 |
| list_entry_revisions | 查询资料的不可变修订摘要 |
| read_entry_revision | 分段读取指定修订，验证属于当前项目及目标条目 |

**实现**

- 复用 StoryStore 版本和提案记录；所有读取保持项目范围。
- 新会话可发现未处理提案，再用已有状态工具读取详情，避免重复提交相同工作。
- 修订读取保留迁移基线标识；不得把迁移生成的当前快照当成真实早期历史。
- 先支持读取两个修订进行比较，不在首批强加独立 diff 工具；大文档结构化差异作为后续按需扩展。
- 过期提案通过读取最新版本后提交新提案解决，不自动接受、不静默更新其 baseRevision。

**验收**

- 待审、接受、拒绝、过期提案可查询且语义正确。
- 角色与文档版本均能读取；跨项目修订和不匹配目标被拒绝。

### P7：接入文档、端到端验收与交付

- 更新 Story/Publication 使用指南和 DSH 提示说明，移除固定“六/八工具”的过时描述或明确版本。
- 文档为每套 MCP 提供通用 stdio 配置模板、必需环境、配对与撤销步骤、媒体能力限制和故障恢复流程。
- 提供三条完整示例：新会话恢复作品；检查/提交方案；审阅候选并导出。
- DSH 与另一标准客户端验证工具发现、分页、结构化错误及媒体显示；不为此改造第三方 harness 内部实现。
- 建立分层验收报告，逐项列出代码/模拟/真实工具调用/真实媒体质量证据。
- 真实付费验收单独使用测试项目与明确额度；部署作为独立交付动作安排，不作为本计划文档编写或每阶段测试的默认步骤。

**验收**

- 新旧工具调用均有回归结果；新增工具具备请求验证、跨项目拒绝和桥接白名单覆盖。
- 至少一个真实 harness 从项目配对开始完成发现、读取、方案校验、提交、状态恢复和产物读取。
- 在明确批准的真实小样中验证按需重绘/配音；记录实际调用数，不把CPU导出计为额外模型制作。
- 逐镜检查主体、动作、构图、角色；逐句检查声音与读音。质量未通过的项目保留具体缺陷，不能写成整体通过。

## 5. 依赖与实施批次

| 批次 | 包含阶段 | 依赖 | 交付价值 |
| --- | --- | --- | --- |
| A | P0 → P1、P2、P3 | P0先定契约；其余可按模块实现，接入时顺序合并 | 发现作品、读取实际素材、准备有效方案 |
| B | P4 → P5 | 依赖A的状态、历史与预检能力 | 局部修改、定向修复、独立导出 |
| C | P6、P7 | P6依赖P0；完整验收依赖A/B | 剧情续接、跨客户端交付 |

建议实现顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7。P6可在制作模块施工期间独立开发，但共享 Story 契约与测试变更应避免同时修改同一文件。

每阶段完成后更新实施记录，写清新增工具、测试结果、兼容变化与剩余限制。不给未经拆解的固定工期；P2媒体兼容与P5配音重试是主要不确定项，应在各自开始时先做最小验证。

## 6. 数据、权限与兼容决策

| 事项 | 本计划决策 |
| --- | --- |
| 数据迁移 | 优先复用现有表；分页、媒体读取、配置查询通常不需要迁移。确需新增持久化字段时另列迁移设计，临时旧库验证后再安排真实库操作 |
| 凭据范围 | Story只读与提案；Publication只访问项目作品及其合法引用。新只读工具不扩大到全局资产或其他项目 |
| 费用批准 | 不新增approve工具；新重试仍执行批准配置并受剩余额度限制 |
| 产物传输 | 小预览内联、大文件受鉴权读取/网页访问；令牌不进入URL或工具输出 |
| 错误兼容 | 新工具提供稳定错误码；旧工具保留可读文本，逐步补结构化信息，不突然改变既有返回包装 |
| 存储兼容 | 旧活动、旧story_*桥接与原生会话保留；不把新制作语义写回旧SceneBeat |
| 取消和重启 | 复用现有持久任务；重启查证既有调用，未知结果不自动重投 |
| 工具数量 | 按真实操作组织；配置查询按类别参数聚合，避免每种配置拆成独立工具 |

## 7. 测试矩阵

| 层次 | 必测内容 | 触发时机 |
| --- | --- | --- |
| 契约 | 输入边界、响应包装、可选/null、分页/错误、旧字段兼容 | 每次共享契约变更 |
| 存储/业务 | 项目归属、稳定分页、CAS、局部失效、原子预算、幂等、未知结果 | 对应业务阶段 |
| Bridge/Portal | 方法和路径白名单、撤销、跨项目、请求/响应体限制、媒体鉴权 | 新增桥接路由时 |
| MCP stdio | 真实启动适配器、发现工具、逐工具参数映射、错误/超时、媒体内容 | 每个工具交付时 |
| Worker | 配音重试、停止、重启、重复请求、导出不触发生成 | P5及受影响阶段 |
| 客户端 | DSH及另一客户端的列表、调用、图片预览和降级 | P2最小验证、P7整体验收 |
| 真实小样 | 模型实际工具调用、批准、执行、媒体审阅与下载 | 单独的真实验收步骤 |

运行规则：共享契约变更运行 `npm run test:contracts`，跨层签名变更运行 `npm run typecheck`，业务和代理运行相关文件测试；前端有变更再验证受影响视图。无关模块不重复全站测试。真实模型调用、数据库迁移和部署不混入日常自动化测试。

## 8. 风险与处理

| 风险 | 处理与完成判据 |
| --- | --- |
| 多模态输出在不同harness中的支持不同 | P2先验证图片内容；音频明确客户端能力；未支持时返回可用网页入口及未审阅状态 |
| 大方案和媒体使上下文膨胀 | 摘要列表、分页、预览尺寸上限、局部修改；正文与原始媒体按需获取 |
| 后台回写引起频繁版本冲突 | 保留CAS；错误给出最新版本，局部补丁便于重新应用，不自动覆盖用户编辑 |
| 有效批准判断过于简单 | 配置和文档同时校验；所有开始/重试入口复查，不以历史approval存在为充分条件 |
| 配音重试形成重复收费 | 同键同请求返回原任务；原子预留；成功复用；unknown阻断；无额度回到人工审批 |
| 文件ID可猜造成越权 | 项目→作品→镜头/对白/导出引用逐层校验，拒绝仅按artifact表存在即放行 |
| 技术成功被误认成质量通过 | 任务状态和审阅结论分开呈现，真实验收逐镜/逐句留证 |
| 老文档与新状态冲突 | 本计划明确日期与基线；交付时更新面向用户指南，历史日志保留历史语境 |

## 9. 后续可选范围

下列事项不阻塞本轮完成，另行评估收益后安排：

- MCP内创建新制作作品：目前仍从网页选择冻结章节；若加入，须明确来源选择与幂等创建，不隐式批准制作。
- MCP结构化审阅记录：模型问题清单持久化、人工标记已处理；首轮先通过现有会话与验收报告表达。
- 长任务状态订阅：首版继续按ID轮询；事件通知按客户端支持情况决定。
- 章节/镜头更细粒度变更、批量剧情提案与可审阅的差异摘要。
- 构图裁切编辑、角色参考资产导入、声音情绪指令与更细字幕对齐。

不包含平台自动上传、连续动画/图生视频、语音克隆、LoRA训练、任意文件读写、远程公网MCP托管，也不把OS级沙箱建设并入本轮。
