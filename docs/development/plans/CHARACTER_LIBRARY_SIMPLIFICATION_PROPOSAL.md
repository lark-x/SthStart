# 人设模块简化与多渠道获取方案

日期：2026-09-08。状态：方案建议，尚未实施。

后续已根据用户确认整理为[详细开发计划](CHARACTER_LIBRARY_REMEDIATION_IMPLEMENTATION_SPEC.md)。实施范围以该文件为准：至少一个真实来源的角色卡搜索、预览和确认导入现为必交付项，并补充外观参考、多模态识图、活动资产与提示词溯源整改。下文保留早期提案及当时的检索记录。

目标：用少量操作获得适合群聊、朋友圈和活动生图的角色。默认流程为“找角色 → 确认人设 → 试演 → 保存并使用”。保留现有角色版本、活动快照和公共服务接口，详细字段按需展开。

## 1. 当前基础与问题

代码核查位置：`app/features/characters/components/character-editor.tsx`、`identity-section.tsx`、`apps/service/src/characters.ts`。

- 已有角色库、结构化草稿、头像、关系、资料来源、发布版本及 AI 草稿生成。
- 当前编辑页面分五个区，列表字段多，常规创建仍要求用户理解多个相近概念。
- 已有 Tavern V2 JSON 的基础导入/导出，不等于完整酒馆运行时兼容。
- 当前导入把 description 同时放到 summary 和 identity，把 system_prompt、post_history_instructions、creator_notes 合并到 extraRules；这个映射需要调整，作者备注不应直接成为角色行为规则。
- 当前在线研究主要尝试萌娘百科，再退回搜索页正文；搜索结果页面不能代替实际资料原文。
- 来源已保存页面级摘录，但不能把它当成完善的逐字段证据链。

## 2. 用户界面

### 2.1 角色库首页

主操作为“添加角色”，弹出四个入口：

1. 搜角色：名字 + 作品，可选来源。
2. 导入角色卡：拖入 PNG/JSON；首批只承诺明确支持的格式。
3. 粘贴资料：网址或文字，解析前自动识别类型，解析后复核。
4. 自己写：名字 + 一段描述，直接保存；AI 整理为可选操作。

角色卡显示头像、名字、作品、一句话简介、设定版本及来源类型。过滤条件首批只保留作品、标签、最近使用，不铺开高级筛选。

### 2.2 默认简洁编辑

常驻内容：头像、名字、作品，以及三个可折叠的正文区：

- 人设简介：身份、背景、性格，允许自然语言编辑。
- 说话方式：语气、习惯、两三句对话示例。
- 外貌：辨识特征、默认服装、参考图。

只有名字必填；内容不足时提示具体缺项，不强迫用户补齐几十个字段。主要按钮“保存并使用”，旁边提供“试演”。已有自动保存保留，版本历史放进更多操作。

原有详细编辑器保留在“详细设定”中。简洁编辑只更新其负责的字段，未编辑的关系、偏好、来源等保持不变。AI 将自然语言拆到结构化字段时先给出差异预览，不在切换模式时反复改写整份角色。

### 2.3 轻量试演

提供固定测试场景：收到生日邀请、群里有人迟到、给合照配朋友圈文字，允许自定义一句测试消息。使用真实角色编译逻辑和已配置文本服务，仅生成少量候选。

试演结果可标记“语气太正式”“口头禅太多”“偏离设定”，再生成修改建议。修改建议由用户选择采用；试演消息不写入活动记录，不自动污染角色正式设定。

默认资料搜索优先百科和作品资料，卡社区作为“现成扮演卡”来源。可选内容分级过滤，不自动下载或展示与用户当前选择无关的内容。

不把 Character.AI、JanitorAI 或需要账户绕过的站点列为首批必达导入渠道。本轮未验证这些站点可靠的官方角色导出接口。用户手中已有合法取得的文件或文字仍可通过通用导入使用。

## 4. 获取流程

### 4.1 名字搜索

输入“角色名 + 作品” → 返回候选身份 → 用户选择 → 获取所选来源 → 生成简洁人设预览 → 修改或确认保存。

先消歧再生成：同名角色、不同作品、同一角色的不同剧情时期必须区分。搜索失败显示具体站点失败与兜底入口，不把纯模型补全包装成“已找到资料”。

第一版仅一个稳定资料适配器加通用导入。界面可以列出其他渠道的外部入口，但不得把外部跳转标成“已接入一键导入”。

### 4.2 酒馆卡导入

文件解析不依赖 AI；解析结果可以直接保存。需要整理成适合活动的简介时才调用模型。

首批格式：Tavern V2 JSON、带角色定义的 PNG，并识别 V3 JSON/PNG 的版本信息。V3 基础字段可转换，但未实现字段必须列为“保留但未启用”。CHARX、多媒体包和完整世界书运行规则分后续阶段实现。

PNG 的角色数据嵌在元数据中，普通截图或被网站重新压缩后的图片可能不包含定义，必须提示“这是一张头像图片”，不能伪装为成功导入。相关依据：[SillyTavern FAQ](https://docs.sillytavern.app/usage/faq/)、[V3 规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)。

导入预览显示头像、名字、卡作者、描述、语气、场景、开场白和世界书条目数量，并明确映射结果：

| 原始字段 | 建议处理 |
| --- | --- |
| name / description / personality | 名字、人设正文、性格；简介压缩为可选 AI 操作 |
| mes_example | 保留对话轮次与占位符语义，不能简单按换行拆成独立台词 |
| scenario / first_mes / alternate_greetings | 保留为原卡场景及开场素材，不直接套到所有活动 |
| creator_notes / creator / tags | 元数据和作者说明，不当成模型运行指令 |
| system_prompt / post_history_instructions | 原样归档；默认不覆盖本应用任务协议，用户可从中选取有效的人设规则 |
| character_book | 保留原始世界书与兼容性说明；未实现触发规则时明确未启用 |
| extensions / 未识别字段 | 原样保留；不执行其中脚本、HTML 或工具调用 |

保留原文件哈希与原始载荷，支持导出原卡。重新导出编辑后的兼容卡时报告无法表达的内容；不能宣称 PNG、世界书和所有酒馆扩展完全无损互通。

### 4.3 网址和粘贴资料

已适配网站走对应解析器；其他网页尝试受控正文提取，失败后允许粘贴文字。用户贴正文即可，不要求先整理格式。

服务端获取网页需要限制大小、超时、重定向和目标地址，阻止访问本机及内网服务。外部内容只作为待提取资料，不能成为系统命令或触发任意工具。保存作者、原网址和来源说明，遵循来源提供的下载与使用方式，不绕过登录或访问控制。

## 5. 人设应分层保存

内部区分三层，普通用户无需每次操作都配置它们：

1. 资料层：来源所述身份、背景、语音等；保留证据和剧情时期。
2. 演绎层：用户或卡作者对表达、性格侧重、平行设定的选择。
3. 活动层：本次衣服、角色分工、临时关系及事件。

现有活动快照继续使用固定角色版本。导入新资料或更新公共角色，不回写既有活动；用户在新活动中选择使用最新版，或者显式比较并更新本场快照。

重要字段附来源状态：资料摘取、作者设定、用户修改、AI 补充、待确认。模型推测不标成官方事实。多来源冲突保留两个候选，用户决定，不能用检索排名代替判断。

同角色多个版本优先表达为“原作向 / 我的改编 / 某剧情时期”等命名方案，底层复用角色修订；有稳定来源 ID 的重复导入进行提示，只提供新增方案或比较更新，不静默合并同名角色。

## 6. 与生图和活动的衔接

从人设外貌和参考图生成视觉描述，继承来源信息。说话语气不作为外貌的兜底文本；头像只是一份视觉参考，不能当成全部外貌证据。

“默认外貌”保存在角色库，“生日会礼服”保存在本场活动。图像提示词继续通过已有配方系统组合，并能跳回对应层修改。不要重建另一套生图服务或复制媒体资产。

群聊、朋友圈、图像提示词分别编译适用的人设片段，控制上下文长度；没有实现世界书完整规则时不将世界书全文无条件塞进每条请求。

## 7. 实施拆分与工作量

复用当前角色表、版本、公共模型服务、Artifact 及活动快照；新增导入暂存记录和字段来源映射。先画清映射表再改数据库，不先删除已有字段。

| 阶段 | 交付 | 相对规模 |
| --- | --- | --- |
| C1 简化编辑 | 添加角色入口、简洁/详细模式、保存并使用、已有角色兼容、固定场景试演 | 中 |
| C2 卡片与资料导入 | PNG/V2 JSON、V3 基础识别、粘贴文字、原始载荷保存、映射预览与未支持字段说明 | 中 |
| C3 第一批在线来源 | Bangumi 候选身份查询 + 原神指定页面解析试点；站点失败、限流、缓存和粘贴兜底 | 中至大，取决于实际可访问性 |
| C4 来源与版本增强 | 逐字段来源、冲突比较、同角色方案、选择性更新活动快照 | 中 |
| C5 后续可选 | Chub 链接适配、更多站内搜索、完整世界书触发、CHARX 导入、批量角色包 | 单独评估 |

推荐先交付 C1+C2，再用真实原神活动选择 C3 的优先来源。上述为相对估算，不是已验证的工期承诺。第一版用户无需安装或运行 SillyTavern。

## 8. 验收清单

- 新建一个只有名字和描述的角色，保存并加入活动，不要求打开详细设定。
- 简洁编辑修改语气后，原有关系、外貌细项和来源仍保留；详细模式切回简洁模式不丢数据。
- 没有模型配置时仍可导入卡片和手工编辑；仅 AI 整理和试演需要模型。
- 导入真实 V2 JSON 和带数据 PNG；头像正确、作者信息保留、数据丢失项有说明。
- 导入普通 PNG、损坏元数据、重复卡片、较大文件，均有明确结果且不污染已有角色。
- 卡中的作者备注、场景、系统提示及未知扩展不会悄悄覆盖活动生成协议。
- 检索同名角色能先选作品和身份；站点不可访问时允许粘贴资料，不编造网页来源。
- 改写候选先展示差异；取消后不改原角色；测试对话不写入正式活动。
- 更新公共角色后，旧活动的人设快照与生图来源仍然可以解释和回溯。
- 390px 手机和桌面上完成找角色、导入确认、编辑、试演与保存使用流程。

本轮仅形成规划文档，没有修改业务代码或执行外部站点导入。
