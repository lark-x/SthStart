# AI 调用链追踪与镜头生图改造：实施交接

确认日期：2026-09-24。执行范围为本文件 T1–T5；用户已确认：全站 AI、配置工作流且镜头允许覆盖、完整长期保留日志、独立日志页、人工核对后采纳图片、不做自动视觉判图，以及本项目管理的邻舍统一走托管服务。

## 现状、目标与边界

- `apps/service/src/activities/comfy-runner.ts` 的镜头生图直接构造固定节点图并请求 ComfyUI；`apps/service/src/activities/routes.ts` 的 `generate-beat-media` 因而绕开 `generation_tasks` 与版本化工作流。`app/features/activities/components/scene-beat-editor.tsx` 直接选引擎/checkpoint、等待结果并立即写回镜头。角色资料只转成提示词文字，`characterConsistent` 不能代表参考图/LoRA 已生效。
- 现有 `generation_tasks` 存有工作流和请求快照，但 `generation_events` 会被清理，且部分旧图片任务可被删除；它们不能单独承担长期审计。活动文本共用 `callLlm`，角色另有直连 LLM，公共 `/v1/chat/completions` 支持流式代理，邻舍托管时从公共服务进入。本项目管理的邻舍目前仅注入公共 LLM 开关，图片/向量未统一强制托管。
- 目标是每次实际 AI 推理请求能在全站日志页按业务事件追踪，并使镜头从来源、编译、选型、实际提交、产物到人工采纳贯通。日志不保证语义正确；不加视觉判图、自动重试、LoRA 训练或新前端框架。独立启动且未经过本项目的外部邻舍进程不在可观测范围内。
- 当前工作树有大量原有未提交改动，包括上述镜头文件、服务路由、数据库和 contracts。它们属于用户，逐文件核对并原位增量修改，不重置、不清理、不覆盖无关内容。方案文件本身由主进程创建，不算 Luna 的业务代码成果。

## T1 — 契约、数据库与只读日志 API

先在 `packages/contracts` 定义 TypeBox 契约并导出，再实现服务 API，最后接入前端；不能在前后端各自定义同名临时类型。业务主库 `apps/service/src/database.ts` 从现有最高迁移版本连续新增迁移，不触碰叙事库。新增长期保存的 `ai_call_records` 与 `ai_call_events`，以及 T3 的 `activity_beat_render_candidates`。关键记录字段至少包括：`id/trace_id/parent_id/retry_of`、来源应用/功能/业务事件及对象 ID、调用类型、请求与结束时间、状态、服务/引擎、实际模型清单、工作流 ID/版本、上游任务 ID、有效参数、正负提示词、脱敏后的实际请求快照和文本响应、用量、错误、产物 ID/哈希、所关联合成任务 ID。事件表存时间、有序阶段和脱敏事件详情；不得设 7 天/条数自动清理。以独立快照保留审计，外键删除任务或产物后记录仍存在且展示“产物已不可用”。镜头候选记录关联 activity/stage/scene/beat、源内容指纹、draftVersion、generation task/call、产物和采纳时间；多次生成保留多候选。

管理员接口：`GET /api/v1/admin/ai-calls`（游标分页，应用/事件/状态/模型/工作流/时间/关键字及业务对象筛选）、`GET /api/v1/admin/ai-calls/:id`（完整详情与事件）。只读接口绝不暴露鉴权头/密钥。列表用摘要，不返回巨大快照；详情返回完整脱敏文本和 Comfy 提交图。历史未记录调用不回填假数据，旧镜头产物显示“无历史调用详情”。现有运行日志页面与保留策略不改变。

记录规则：先写 `requested`，每次上游模型推理一条；预检未提交用 `not_dispatched`，实际提交后顺序记录 `resolved/submitted/accepted/running/succeeded/failed/abandoned` 等阶段。多阶段作业逐次建记录并用 trace/parent 关联；重试建新记录并标 `retry_of`；健康探测/轮询只记为相关过程，不另计 AI 调用。递归脱敏 headers、令牌字段、URL 凭据、已知密钥值和多模态 data URL；保存完整文本提示词/响应而不存图片二进制/base64。流式响应边转发边增量留存正文与中断标记，不为了日志先缓冲完整流；不得静默截断文本。JSON 导出与高级检索不是必做。

验收：重启、清理旧 `generation_events`，甚至删除允许删除的旧生成任务后，新审计详情仍可读；未授权访问拒绝；提供含密钥、data URL、扩展参数的脱敏测试。执行真实库迁移前运行 `npm run db:backup`，后运行 `db:check` 和 `db:integrity`，不可执行时保留阻碍证据，不用 reset。

## T2 — 覆盖全部经本项目转发的 AI 推理

- 在 `apps/service/src/generation/execution.ts` 的统一任务生命周期记录图片/视频等生成，包括活动素材、创作、角色、公共生成、配置试运行和旧图片适配；快照以实际渲染后提交内容为准，保存模型节点/输入模型名、版本化工作流、种子、上游 `prompt_id`、产物与失败。避免从仅有的请求参数猜实际模型；一个图内多模型记录清单。
- 为 `activities/text-jobs.ts` 的 `callLlm` 增加可传递的审计上下文并覆盖活动各阶段、规划、知识、研究、主题调用；`characters.ts` 的直连编辑/视觉提取/试演走同一记录机制。调用者标明业务事件，不能全部显示为泛化的“LLM”。每次真正发给供应商的消息/模型/参数入库；供应商文本输出和 usage 若存在则入库。
- 对 `public-routes.ts` 的聊天代理记录覆盖实际路由后的模型。流式 SSE 维持逐块透传及背压，完整成功、上游失败、用户断开、超时都落准确状态；对向量 `/embed` 及会触发推理的搜索入口记录经本服务发出的请求和响应，不把向量 CRUD 当推理。邻舍托管的 LLM/图片/向量请求在对应入口可查。
- 日志写入失败不得伪装为已审计的成功调用；若不能创建起始记录，不发上游请求并返回明确的本地审计错误，避免“实际调用发生却全无痕迹”。后续落库失败保留可诊断错误并不重发上游任务。

验收：模拟的生成、活动多阶段文本、角色多模态、邻舍聊天流及向量推理各有独立记录；一次作业多次上游请求数量对应；失败/断流也可查，敏感数据不出现。只测相关模块，不默认跑全仓库。

## T3 — 镜头工作流、预览与候选

继续用当前活动草稿中的权威 top-level scene/beat，兼容已有 legacy 读取规则；以 `SceneBeat.characterId` 映射活动 `ActorSnapshot`，取快照人设/外观/服装与来源版本，避免按重名 `display_name` 猜资料。提示词按角色、动作、地点/时间、氛围、用户补充及负向词形成结构化来源段，再绑定到工作流实际 prompt 输入。若角色参考资产存在且选定工作流声明相应输入能力，允许明确选择并交给现有 artifact 绑定机制；不支持时只传文字，UI 明示“未使用参考图/LoRA”，不称“角色锁定”。视频镜头保持既有不支持提示，不误作图片请求。

新增管理员接口：`POST /api/v1/admin/activities/:id/beat-renders/preview` 返回来源摘要、有效正/负提示词、实际工作流/版本/引擎/模型及可配置字段、引用能力、警告与 `planHash`，不发模型请求也不写调用记录；`POST .../beat-renders` 带镜头定位、所选配置、参数、`planHash`、幂等键，成功 `202 {candidateId,taskId,callId}`；`GET .../beat-renders?beatId=` 返回候选与进度；`POST .../beat-renders/:candidateId/adopt` 返回更新后的草稿版本或 409 冲突。提交时重新编译并比对与源镜头/角色及选型绑定的指纹，过期用 409 要求重预览。默认沿用活动图片用途绑定及默认预设；可覆盖为活动可用的已发布、输出图片且有正向提示词绑定的兼容工作流。单独选 checkpoint 仅当工作流 editor config 允许，预设锁定时只读展示实际模型；参数按现有配置校验。不得另造固定 3–9 节点图。

通过现有 `createGenerationTask` 异步执行，候选与 task/call 同事务或等效可靠机制建立关联；生成成功只更新候选，不改草稿。采纳时服务端重读当前草稿，确认原 scene/beat 仍在且生成所依据的相关镜头/角色内容未变，以现有草稿 CAS 原子写 `mediaUrl/mediaType`；无关编辑可保留，相关冲突 409 且候选仍可重看。刷新后候选可恢复。旧 `generate-beat-media` 保留旧响应形状的兼容适配，但必须走同一配置与审计管线，不能继续直接提交固定图；其等待超时不得自动重复提交。

验收：mock Comfy 捕获的 graph、提示词、model、seed 等与日志完全一致；生成后原图未被替换，采纳才替换；删除/改动源镜头拒绝旧候选，日志仍可查；重复提交幂等；配置缺失/不兼容时不向上游发包。禁止假称角色参考已生效。

## T4 — 页面与业务入口

新建独立 `/settings/ai-logs` 常规页面并在全站导航设置区给唯一入口，不塞进运行日志。列表显示时间、来源应用、业务事件、类型、状态、模型、工作流、耗时；过滤和游标分页；详情时间线从来源到实际提交及产物，提供完整脱敏请求/响应查看和返回活动/角色等业务页面的链接。明确本项目托管边界与旧记录缺失原因。空、加载、无结果、错误、长文本与窄屏状态均可用。

镜头工坊中把选型与提示词预览集中于现有唯一生成入口；结果区域展示候选图片、状态、参数摘要、调用日志链接、“采纳/再生成”。既有画面在预览候选时保持不变。请求封装与 React Query 使用共享契约；符合 `app/AGENTS.md` 的列高度隔离、独立滚动、语义 token 和不重复按钮。日志页正常文档流使用 AppShell，镜头页保持全屏工作台。

验收：桌面/窄屏截图显示日志页与镜头工坊，无溢出/遮挡；刷新页面候选与筛选状态合理，日志深链可打开相应调用。

## T5 — 邻舍托管与兼容

在本项目管理的邻舍启动路径注入并锁定公共 LLM、图片和向量托管开关；启动/配置检查相应应用令牌与用途绑定，缺失时给可操作的缺项错误，不回退直连。包括服务运行时和项目自己的邻舍启动脚本；不修改邻舍 submodule 的独立运行默认行为，不更新 submodule 指针。已有“公共 LLM”设置若与强制托管冲突，应在本项目 UI 中解释/调整，不保留会静默关闭审计的开关。独立外部邻舍启动不承诺可观测。

验收：项目管理启动的邻舍经公共网关调用 LLM/图片/向量并留记录；缺配置不能偷偷直连；`npm run test:linshe-contract` 和相关运行时靶向测试通过。

## 顺序、最小验证与交接

依赖顺序：T1 契约/迁移 → T2 采集 → T3 镜头管线/候选 → T4 UI → T5 托管回归；可在不重叠的模块内穿插靶向测试。验证至少包含新日志/镜头服务测试、涉及既有接口的回归测试、`npm run test:contracts`、`npm run typecheck`、迁移前备份与迁移后完整性检查，以及 `node scripts/take_screenshot.mjs` 后实际查看桌面和窄屏截图；真实 ComfyUI 可用时补一次烟雾测试，不可用则注明仅 mock 通过。不要用全量 E2E 替代靶向验证，不做无关清理。

风险与回退：迁移只增表/索引，先备份；发生问题先禁用新入口和托管启动，保留审计记录与候选，不 reset 数据库。无法兼容旧管理员接口、必须改邻舍独立运行、需要新增框架/大依赖或需删除原数据时，停止受影响任务并向用户确认；其他独立任务可继续。允许 Luna 自行决定局部命名/组件拆分及等价代码组织，但不能改变上述用户可见行为、日志留存与安全边界。交付按 T1–T5 列完成度、实际修改文件、测试及截图、方案偏差与剩余风险。主进程之后只做一轮只读验收并暂停。
