# 前端第二轮视觉复审：从组件统一到页面精修

## 1. 审查范围与结论

本次实际查看了当前运行网站的首页、新建活动、角色资料库、创作中心、公共服务页面，使用约 1920px 宽的桌面浏览器，当前为暖杏护眼主题。对照工作区代码及 `2026-09-12-frontend-stage-b-delivery.md`。未修改前端、配置或业务数据，也没有完成本轮手机及默认主题复查。

已有用户标签页和新打开页面曾显示不同导航版本，因此最终结论以新打开的审查标签页为主，未刷新或覆盖用户正在填写的表单。

**结论：本轮确实完成了基础组件工作，但页面精修尚未完成。**阶段 B 记录也明确说明阶段 C 逐页迁移和阶段 D 旧样式清理没有展开。当前的不协调主要来自页面构图、信息优先级和新旧样式混用，继续只调整共享按钮不会解决全部问题。

不要重新执行已完成的导航、弹层和状态基础设施改造。下一轮应以代表页面的实际截图为验收对象。

## 2. 最优先的六项改进

### V01：护眼主题的表面层次太接近

**看到的现象：**页面背景、卡片、输入框都落在相近的黄灰色里，文字与边框也偏灰。看起来像所有元素铺在同一张纸上，界面密度虽高，但不容易快速分辨哪些可编辑、哪些只是说明。

**调整：**

- 保留暖底色，面板使用更浅的暖白，输入区域再略亮一级。
- 仅对输入控件使用清楚的边界，普通内容区优先用间距和标题组织。
- 正文与标题采用明确深色，说明色用于真正次要内容；不要整体加深全部边框。
- AI 正常状态面板不大面积铺橙色。改为普通面板＋小图标/细强调标记，橙色主要留给生成动作和选中项。
- 对比度需实际测量。本次“偏灰”是视觉判断，不代表已经证实不符合某项标准。

**验收：**不开启任何高亮或焦点，也能分清背景、内容面板和输入框；正常 AI 区不会看起来像一条大警告。

### V02：圆角统一存在实际偏差

**证据：**新打开的新建活动页面中，活动标题、类型、日期和地点输入框的 computed border-radius 均为 `14px`，高度为 `36px`。阶段 B 记录则描述为“8px 圆角”。当前 theme 的 `--radius-lg` 为 14px，组件使用 `rounded-lg`，需要核对最终 token 对应关系。

同时，活动设置、阶段面板、首页卡片、角色卡片等仍有旧的不对称角，和新的胶囊感输入控件混用。

**调整：**

- 给业务控件明确语义半径，不依赖对 Tailwind 默认值的记忆：control=8px、panel=12px、dialog=16px。
- 共享组件引用这些确定的 token；验收 computed style，而非仅检查 class 字符串。
- 胶囊形只用于标签/状态，不用于普通表单与全部工具按钮。
- 不对称折角从业务面板退出；保留品牌装饰必须有明确区域，不能页面到处出现。
- 新 token 要考虑现有工具类的消费者，避免改变一个通用变量后无意把其他标签或弹窗都改形状。

**优先级：高。**这是可以直接修复的实现偏差，而不仅是审美偏好。

### V03：页面仍然“每个区域都装一个盒子”

**看到的现象：**新建活动页面包含模板框、基本信息框、角色框、模型状态框、AI 框、阶段总框、每阶段子框及输入边框。各层都在表达“我是独立的重要区块”，视觉噪声较重。

**调整：**

- 形成两个大工作区：左侧“活动设置”，右侧“企划与阶段”。
- 模板作为设置面板顶部的一行选择，不单独占一张约百像素高的卡片。
- 模型状态并入 AI 面板标题行，刷新和配置作为次级小操作。
- 阶段列表使用细分隔线和折叠行；只展开正在编辑的阶段。
- 组内使用 12–16px 间距，组间 24px；不要每一层都加背景和阴影。
- 保持输入焦点、错误和可编辑边界清楚，不通过完全去掉边框制造另一种模糊。

**验收：**首屏视觉上主要是两个工作区，用户能快速识别设置、生成、阶段，而不是先识别十几层边框。

### V04：主操作不够突出，辅助操作占了太多注意力

**看到的现象：**活动“生成企划”目前是小型描边按钮，AI 区整块橙色比按钮更抢眼；角色库未选择任何角色时，仍常驻“已选0位、选择本页、取消选择、批量整理”；创作中心在当前截图高度下需要下滑才能完整到达生成按钮。

**调整：**

- 活动 AI 区只用一个实色“生成企划”主按钮，其余配置/刷新/技术信息降为次级。
- 用户未进入批量选择时，只留“批量管理”入口；进入后再显示选择与整理动作，并保留显式退出方式。
- 创作中心将反向提示词、步数、种子放入默认折叠的高级参数，首屏保留提示词、画幅及生成动作。
- 创建活动仍区分手动创建和使用企划创建，但用状态解释可用性；不出现两个同等强调、含义相近的按钮抢焦点。

**验收：**每个任务区域一眼可识别主动作；辅助按钮不比内容标题更突出。

### V05：首页构图失衡

**看到的现象：**左侧最近工作内容较少却占较大区域；右侧活动卡独占第一行，下方双列排列后最后剩下一张叙事卡。最宽的活动卡内部反而留白很多。每张卡都是“英文标签＋衬线标题＋长说明＋橙按钮”，重复感明显。

**建议采用的下一版：首页分成一条紧凑欢迎栏和两块主区。**

1. 顶部：问候/简短说明，与服务状态对齐；移除大段英文装饰。
2. 主左区约 32%：最近工作，用行式条目。无最近活动时一行提示即可，不为一个空分组保留大块高度。
3. 主右区约 68%：六个应用统一尺寸的 2列×3行网格，不让第一张跨整行。
4. 卡片统一 44–48px 图标/小型品牌图形，不用每张都带很深的竖向装饰色块。
5. 描述限制两行。普通“进入”使用整卡标题链接或轻量箭头，避免六个实色按钮同时争夺焦点。
6. 快捷创建收成一行或放在对应应用卡内，不重复另一套很大的入口网格。

不要为了填空白添加虚构最近项目或新统计。内容少时自然收缩，整页可以留白，但留白应围绕清楚的构图。

### V06：页面宽度与内容类型不匹配

**看到的现象：**活动和角色页接近全宽；公共服务仍是居中的较窄容器，内部只有一张模型卡，右侧搜索和新建按钮离卡片很远。单纯把公共服务扩大到1920px会让这个问题更明显。

**调整：**

- 保持全站相同页头对齐和边距，但根据任务选择内容布局。
- 公共服务模型改成配置列表行：名称/模型、能力、凭据、使用方、操作横向排列。当前只有一个模型时仍像一个完整管理界面，不是一张漂在角落里的卡。
- 搜索与新建放在列表标题同一条工具栏，并靠近主要内容；不要在过宽空区域两端遥相呼应。
- 公共服务路由分类可展示绑定列表，保留分类，不把所有配置再塞回同一屏。
- 阅读正文继续限制行宽。内容密度与页面宽度不是同一件事，不要求所有页面都填满。

## 3. 页面级补充建议

### 3.1 角色库：从“记录表”变成“可浏览的角色库”

本次看到六列卡片，数量已经足够，下一轮不要继续加列数。重点是卡片的信息组织。

- 筛选区压成默认一行：约320–400px搜索框＋作品/标签/分组＋收藏＋更多；已选条件显示第二行，无条件时不占高度。
- 将“管理作品与别名”移到更多管理入口，离开卡片浏览视线。
- 卡片内作品“原神”出现两次：顶部一次、标签区又一次。只保留一个位置。
- “未标注演绎”不应在每张卡常驻成为主信息；有实际演绎差异时再显示，普通卡用“草稿/已发布”小状态。
- 角色名改为稳定的16px/600无衬线，摘要两行，标签最多两到三项＋“+N”。
- 大量首字占位头像让卡片高度重复。无头像时采用统一的紧凑首字占位，辅以少量稳定的低饱和色；不擅自抓图或生成头像。
- 已有真实头像时优先突出头像，但不要为追求美观自动拉取外部媒体。

**目标：**卡片顶部从当前约370px提前到约250px以内（以本次约1920×850桌面视口为参考，具体以页面字体和工具栏实际换行为准），将空间还给角色。

### 3.2 创作中心：修正空态和表单的主次

- 当前媒体库和任务列表都为空，没必要分别占两张大型空白面板。
- 无结果时媒体库空态保持约160–220px，不强制与左表单等高；只显示一条清楚的下一步。
- 右侧可以保留“媒体库/生成任务”页内切换，避免空状态重复堆叠；有任务时显示真实任务进度。
- 管理工作流链接应该和“当前模式待配置”挨在一起，不藏在媒体库底部。
- “Artifact 2.0”“媒体不会复制到邻舍数据库”等技术说明移到详情帮助，不占创作区主描述。
- 缩小英文装饰标题，提高真正的“提示词”“媒体库”标题辨识度。

### 3.3 活动创建：减少用户同时面对的空字段

- 把模板合并到基本信息顶部；规则/导演约束默认折叠。
- 阶段用“序号＋名称＋一句摘要”的紧凑列表，展开当前项，不默认把每个空阶段完整表单铺开。
- 左边角色区提前露出，避免全屏只看到空文本框却看不到活动参与者。
- 右边按“生成要求 → 生成按钮 → 企划结果 → 阶段编辑”的稳定顺序；技术会话详情继续折叠。
- 吸底创建栏减小垂直厚度并预留底部空间，内容不得被遮挡。

## 4. 下一轮建议实施顺序

### 第一步：修正实际渲染偏差

统一并实测control/panel/dialog圆角；调整暖色主题背景、表面和输入层次；清理这些目标页面上的旧折角与厚重阴影。不要先重做路由、弹层或后端。

### 第二步：只精修三张代表页面

1. 新建活动：合并模板和模型状态，阶段收叠，强化生成按钮。
2. 角色库：压缩筛选与批量工具，去重复元信息，统一卡片头部。
3. 首页：六卡规则网格、最近工作行式内容、降低重复橙按钮。

每页同时检查护眼和默认主题，拿真实浏览器截图确认，再推广到其他页面。不要一次性改十个页面后才发现基础比例不合适。

### 第三步：创作中心与公共服务

创作中心解决空态重复和生成入口下沉；公共服务采用适合配置数据的列表行。复用第二步已确认的视觉语言。

### 第四步：后续覆盖范围

再查看日历、角色编辑、笔记、叙事和控制中心。本轮没有实际完整检查这些页面，不将前一份计划中的静态风险冒充新的视觉复现结果。

## 5. 验收方法

- 视口：1920×1080、1440×900、1280×720、390×844。
- 主题：默认和暖杏两种；本轮只实际查看了暖杏，大范围调整前要补默认主题验证。
- 使用同样内容比较前后截图：空活动、24位角色第一页、空媒体库、一个模型配置、少量最近工作。
- 检查 computed style：输入圆角确为8px，面板12px，弹窗16px，不只检查CSS class名称。
- 首屏重点：角色第一排提前；活动AI生成可见；创作中心生成按钮或配置阻塞入口可见。
- 页面任务分组明确，不能为减少边框牺牲输入识别、焦点和错误态。
- 保留模型配置、草稿、角色快照、批量选择、任务和媒体逻辑；不因视觉调整重建业务状态。
- 已有用户标签页可能仍加载旧JS/CSS。验收打开新标签或在确认没有未保存内容后刷新，记录实际版本，避免混用截图。

## 6. 对本轮结果的评价

本轮已经让组件、导航和反馈机制更可维护，但这些变化不会自动让页面构图更好。最需要补的是：**让每张页面有清楚的主角，减少无意义的框和说明，用适合内容数量的布局，而不是把所有区域扩大或压紧。**

下一轮以“页面截图明显改善且操作更容易找到”为完成标准，而不是以“新增了多少共享组件”或“移除了多少硬编码”作为主要成果。
