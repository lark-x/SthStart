# 角色筛选、生日日历与 AI 活动企划

日期：2026-09-11。适用范围：SthStart 公共角色库、活动工作室与门户；不修改邻舍（upstream/linshe）。

## 已实现

### 角色筛选

- 角色库与活动选人继续共用 CharacterFilters、CharacterPagination 与 useCharacterBrowser。
- 搜索、作品别名与查询共用同一套规范化（首尾空白、英文大小写）；同类多选 OR、不同类别 AND、标签可切换全部匹配的既有语义不变。
- 全部生效条件（含“更多筛选”里的作品类型、创作类型、外观、演绎、来源、待整理、生日等）都会显示为可移除标签；清空筛选会一并清除查询条件。
- 作品、标签、分组下拉支持搜索、Escape 关闭与点击外部关闭，并区分“暂无可选项”和“没有匹配的选项”。
- 角色库用 URL 参数 cf 保存筛选条件与页码：页面改为服务端读取 searchParams 后注入首屏，从角色详情返回即可恢复，不产生挂载后的二次水合抖动。活动选人的筛选状态独立保存在页面会话中。
- 筛选变化统一回到第一页；数据减少导致页码越界时 CharacterPagination 自动回到最后一个有效页；关键词仍处于防抖窗口时显示更新状态。
- 新增“生日状态”与“生日月份”筛选，候选月份来自生日查询投影。

### 生日与日历

- 角色草稿新增可选结构化生日字段：状态（已确认／待确认／未填写）、历法（公历／农历／未知）、月日、原始文字、来源与识别依据。
- 识别只接受明确来源：本系统字段 → 导入卡显式生日字段（含扩展命名空间）→ 人设文本中带“生日／Birthday”标签的条目。不由年龄、剧情日期或他人信息推断，不调用模型猜生日。
- 农历、同年月日冲突、书写顺序不明确（如 08/08）与模糊描述一律进入待确认并保留原文；2 月 30 日、13 月 1 日不是有效日期。
- 角色编辑页新增生日编辑器：可确认月日、保留原始文字、明确清空。明确清空会记录 source=manual，之后不再从正文自动补回。
- 导入（含批量导入与旧 persona 迁移）、手动编辑、AI 生成、外观候选应用等所有会改写草稿的路径都会同步刷新生日投影；服务启动时按草稿重建一次投影，保证筛选与日历一致。
- 新增 /apps/calendar 月视图：周一为每周第一天，支持上月／下月／回到今天、日期详情、作品／标签／分组／收藏／事件类型筛选；格子最多显示 3 项并提示“还有 N 项”。
- 同一天多位寿星分别列出（以角色 ID 区分，头像与作品辅助辨识），可用复选框选择一位或多位，直接进入新建活动页并预填日期与寿星。
- 生日每年循环显示；2 月 29 日只在闰年出现，平年不自动平移。活动日期使用 YYYY-MM-DD，不做时区换算；未排期活动不进入日历，归档活动与归档角色默认排除。
- 门户快捷通道、应用切换器、角色库页头与活动工作室页头都提供日历入口。

### 活动模板与创建

- 门户与服务端共用同一份模板定义（生日、日常聚会、节日庆祝、出游、空白），未把默认内容复制到多个页面。
- 生日模板包含“准备邀请 → 到场互动 → 庆祝祝福 → 合照回顾”，多人合办时为每位寿星生成单独的祝福必达事件。
- 新建活动页提交完整 ContentDocument，修复了此前只提交阶段标题、导致阶段指令与结束条件丢失的问题。
- 模板切换前先列出会改变的内容（类型、主题、地点、规则、阶段），用户确认后才替换，并保留已选参与者。
- 支持从角色库添加参与者，也可添加只在本场活动出现的自定义参与者；生日模板可勾选本场寿星。
- 活动工作台的设定页新增活动日期字段，并提示日期随草稿保存后才同步到日历。

### 创建前 AI 企划

- 新增独立企划会话，生成过程不创建正式活动，刷新后可继续同一会话。
- 会话冻结角色人设：发布版固定使用该确切版本，草稿记录当时的修订号与人设哈希；创建正式活动时逐一复核，草稿发生变化或人设被替换会返回 409 并要求重新读取。
- 提交的文档必须与会话冻结的快照一致：参与角色数量、显示名、来源角色与人设哈希都会被校验，客户端不能冒充服务端人设。
- 模型输出使用共享契约 ActivityPlanningOutput（活动概述、角色分工、完整阶段），只允许覆盖主题与阶段；日期与寿星名单由用户设定，模型不能改写。
- 至少两个阶段、角色 ID 必须来自冻结输入、clientId 必须唯一且不重复；寿星若未出现在任何阶段，采用时会被补进最后一个阶段并追加祝福必达事件。
- 结果按概述、角色分工与阶段卡片展示，支持编辑基础信息与阶段文本、“应用到表单”、重新生成、查看折叠的原始 JSON，以及使用该企划创建活动。
- 创建活动使用幂等键，重复提交返回同一活动；会话的活动创建与状态更新在同一事务内完成。

### 活动内 AI 生成

- 共用上下文构建器（activities/context.ts）：身份、背景、现状、性格、动机、信念、喜欢／不喜欢／害怕、边界、语气、表达习惯、口头禅、有限数量的对话示例、活动职责、角色关系与真正位于目标阶段之前的事实。角色投影里保留的原始草稿作为字段回退来源。
- 提示词统一加入输入数据守卫，明确角色资料与用户要求都属创作输入，不能改变输出格式、引用范围或校验规则；供应商 extraBody 不再能覆盖 model / messages 等核心字段。
- 新增快捷文案入口：生成邀请、生日祝福、朋友圈文案、配图描述。它们复用阶段输出的结构，因此共用同一条校验与采用链路，但采用时是追加写入，不会清空该阶段已有内容；配图入口只生成描述，不触发图像生成。
- 快捷入口必须明确目标阶段；局部重写必须明确选中记录，两者都在服务端与界面双重校验。
- 修复局部重写：以前只传阶段、候选也无处采用。现在按记录 ID 生成，采用时只替换选中消息／动态的文本，记录被删除后候选失效并返回 409。
- 修复任务重试：任务保存原始请求快照（模式、范围、补充要求、输入文档），重试按原样恢复；没有快照的旧任务明确提示无法原样重试，不会用当前草稿冒充。
- 取消会通过 AbortSignal 尝试终止上游请求，迟到结果不会产生可采用候选。
- 修复企划采用：锁定阶段改为按稳定阶段 ID 保护（模型未回传 ID 时才退回顺序匹配），同名或重排都不会误覆盖。
- 采用流程在单个事务内完成草稿更新、内容版本提交与候选标记；替换阶段内容时同步清理该帖子的评论与点赞，避免悬空引用；追加文案只把当前与后续阶段标记为需要复核。
- 整场生成按阶段顺序展示候选，支持“按阶段顺序采用全部”，使用服务端返回的 headVersion 递增，避免中途版本冲突。
- 阶段规划提示词补充了活动日期、寿星、角色关系与完整人设，避免只取性格或简介。

## 数据与接口

迁移 19 birthday-calendar-and-planning（服务启动按既有迁移机制升级，无需重置数据库）：

- character_birthdays 生日查询投影（角色 ID、状态、历法、月日、原文、来源），可随时由角色草稿重建。
- activities.scheduled_date 与索引，activity_actor_characters 活动参与者投影。
- activity_jobs.request_json 原始请求快照。
- activity_planning_sessions、activity_planning_jobs、activity_planning_candidates 企划会话、任务与候选。

新增接口（门户沿用 /api/admin/* 代理）：

- GET /api/v1/admin/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD&filter=<JSON>
- POST|GET|PUT|DELETE /api/v1/admin/activity-planning-sessions[/:id]
- POST /api/v1/admin/activity-planning-sessions/:id/jobs、GET .../jobs/:jobId、POST .../jobs/:jobId/cancel|retry
- POST /api/v1/admin/activity-planning-sessions/:id/create-activity

契约新增：CharacterBirthday、生日筛选与 facets.birthdayMonths、活动 scheduledDate / templateId / birthdayActorIds / overview、ActivityPlanning* 类型、ACTIVITY_TEMPLATES 与 buildActivityDocument。ActivityJob 增加 replayable，活动文本任务的 mode 扩展为 invite｜wish｜moment｜shot。

## 已知限制

- 未实现农历换算、提醒推送、活动时间冲突检查、自定义模板编辑器与角色人设的 AI 改写。
- 企划会话不自动过期，只能显式丢弃；生成失败会保留表单与上一份可用候选，但没有自动的 JSON 修复重试。
- 活动日历精度为“按天”，活动只参与一次，不区分同一活动内的多个时间段。
- 快捷文案入口只针对已有阶段追加内容，不支持跨阶段批量生成。
- 自定义参与者（无角色库来源）可以创建活动，但不能用于生成企划，界面会给出明确提示。
