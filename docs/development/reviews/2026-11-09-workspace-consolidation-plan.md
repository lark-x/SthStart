# Web 工作区收敛与内容可用性实施计划

状态：实施、逐项浏览器验收及正式部署已完成；详见同目录2026-11-09-workspace-consolidation-acceptance.md与内容可用性报告。负责人：主代理；最多三个授权子智能体并行。
基线：`82dbebe`，现有 B 布局；以当前源码、浏览器和正式数据只读检查为准。

## 目标与约束

完成已经核实的布局缺陷、统一基础层和工作台交互，然后查明无法加载的页面与内容并修复或给出逐类可验证解释。保留暖夜及其余既有配色、B 独立工作面，不引入绿色主色。桌面优先，手机兼容核心浏览与简单编辑。邻舍内部不重构，只检查入口及可用性。不得以通过少数截图测试代替全范围验收。

不新增业务数据模型或付费生成需求，不删除缺失媒体对应的正文、角色、历史来源等有价值记录。可自动清除明确无引用的临时垃圾；存在业务引用、来源未知或不可恢复内容时保留记录并解释。正式数据只读调查；恢复已有文件须先核对来源、身份和备份。

## 第四阶段：无法加载内容调查与处理

1. 建立正式环境路由、关键API、缩略图/媒体、角色图片、笔记附件、制作结果与外部服务清单。记录HTTP、错误码、业务引用、文件存在性、来源与检查时间，报告不泄露凭据。
2. 分类：前端或接口故障；数据库有记录但本地文件缺失；外部链接失效；服务未配置/离线；历史任务失败/中断；暂无数据；权限问题。不能把空数据等同故障。
3. 前端故障和失效加载状态修复；缺失资源给出明确占位、原因和恢复路径，避免无限转圈/破图。可在原有备份找到文件时核对后恢复，不能伪造图片或冒充重建原件。
4. 对无法安全清理的引用记录保留并解释；只删除确认无业务引用的临时残留。每项处理前后有清单；若无需删除，以证据说明原因满足用户的解释要求。
5. 缺失文件不等于数据库损坏，检查实际容器挂载与路径映射，不能依据旧的缺失数量下结论。
