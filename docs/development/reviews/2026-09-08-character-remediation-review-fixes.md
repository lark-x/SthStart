# 角色库整改复查与修复

日期：2026-09-08。验收口径：个人自用，优先保证主流程、数据保存和活动兼容，不按原计划的全部企业级检查项阻塞交付。

## 完成情况

当前已具备核心使用链路：简洁/详细人设编辑、Character Tavern 搜索、本地 PNG/JSON 和已支持的网址导入、预览后确认、原卡归档、角色发布版本、试演、参考图上传、识图候选、模型配置以及活动参考图转入。

结论是“核心功能已实现，经本轮修复后可继续实际使用”，不是原详细计划逐项 100% 完成。源码存在、协议模拟通过和真实模型效果已验证是不同状态。

本轮接手时上述实现尚未提交；本次提交同时包含待提交实现和复查修复。没有改造邻舍内部，也没有增加云部署。

## 修复的实际问题

| 问题 | 修复 |
| --- | --- |
| 修改导入预览后直接确认，会提交旧候选 | 确认按钮先保存屏幕上的候选，再提交返回的新版本和哈希；取消冗余的“保存预览修改”操作 |
| 相同文件/网址取消后重试，可能取得已经取消的会话 | 每次新的导入使用独立请求键；同一次确认仍保留幂等处理 |
| 预览没有展示原卡封面；搜索入口藏在编辑页 | 增加受控封面预览，搜索结果显示缩略图，角色库首页提供搜索/导入入口 |
| 搜索关键词改变后可能混用旧分页，并提前显示“没有结果” | 结果与已执行的关键词绑定，旧请求取消，修改关键词清空旧分页 |
| 弹窗在输入时重置焦点，小屏确认按钮可能超出视口 | 焦点初始化仅在打开时执行，回调通过引用更新；限制整体高度并滚动正文 |
| 稳定辨识特征的表单值是对象数组，接口需要字符串数组 | 补齐双向转换，简洁/详细模式保存保持一致 |
| 更新现有角色会把卡片未提供的背景、喜好和外貌细项清空 | 更新仅覆盖有来源映射或在预览中明确修改的字段，保留其他设定 |
| 用户改过的候选仍标记为卡作者原文，文件 hash 不是原字节 hash | 记录用户修改及新值 hash，原卡按实际字节计算 SHA-256；修正部分来源字段路径 |
| 文件 MIME 未识别时或 JPEG/WebP 暂存为 .bin，封面无法应用 | 先识别真实格式再选择暂存扩展名；为图片导入单独放宽编码后请求大小限制 |
| 角色发布成功但前端契约校验失败 | 将来源列表包装为契约接受的对象，并加入真实响应 schema 检查 |
| 给已有活动添加角色时 persona 是空对象 | 选人窗口从服务端取得完整指定版本快照；新建和已有活动均可使用 |
| 旧角色版本读取当前头像，活动包又缺少头像资产键 | 发布冻结头像 ID 并保留媒体引用；提交活动内容时将头像纳入活动资产 |
| 发布后的角色允许转入不属于当时版本的新参考图 | 校验参考图是否在该发布版本中；明确选择草稿仍可用新增参考图 |
| 图片提示同时包含备选服装、本场服装，并重复拼接服装 | 选择单一造型；活动外貌块只包含外貌，服装由单独来源块负责 |
| 未声明身份参考能力的普通工作流也可被标成“人物参考” | 未声明时按普通起始图处理，不支持的参考用途明确拒绝 |
| 旧字符串外貌和较长示例对话被归一化丢弃/截短 | 保留字符串外貌及完整对话块的合理长度 |
| 识图候选可能清空未观察到的字段，并遗漏输入证据 | 空观察值不覆盖原设定，服装候选追加；记录图片 hash、实际模型和提示词 |
| 应用识图结果、生成头像或再次导入可能越过未保存编辑 | 先保存必要草稿、处理失败，应用候选时保留请求期间其他编辑；导入后重新载入最新草稿和参考图 |

另外补充了 PNG 压缩文本的解压上限、导入更新事务内版本复核和失败时共享原文件的保护。这些是局部可靠性修复，没有扩展账号系统、审核流程或复杂任务平台。

## 可以继续使用，但尚未完全实现的计划细节

以下是后续增强，不作为此次个人项目提交的阻塞条件：

1. **更完善的重复导入对比界面**：已有来源归档、版本控制和保留字段的更新方式，但没有完整的作者版本对比/逐字段选择合并界面。
2. **所有 AI 操作统一为可编辑差异候选**：识图有选字段确认，旧的整份 AI 草稿生成仍是整体更新方式。使用已有角色时可先发布版本；后续适合补齐“比较后采用”。
3. **更多来源与普通网页抓取**：当前在线卡来源为 Character Tavern；网址导入针对已支持的卡链接，其他资料可粘贴文本。不是全网角色搜索引擎。
4. **完整命名造型与参考图管理**：当前以服装列表选择默认造型，能选参考用途；尚不是完整的多造型编辑、裁剪和多图控制系统。
5. **完整来源资料归档包与高级视觉控制**：现有活动媒体/提示词溯源导出继续使用，原卡可独立下载；尚未把所有外部原卡和逐字段证据整合成完整活动资料包。多角色身份控制、独立云图像供应商需要按实际需求另接。
6. **真实效果观察**：建议实际使用时做一次“搜索导入 → 改外貌 → 文生图/图生图 → 修改服装再生成”的短演练即可，不要求补跑原计划全部 24 项人工检查。
