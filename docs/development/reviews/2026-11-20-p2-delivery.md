## 2. 契约与迁移

### 2.1 契约（`packages/contracts`）

- 新增 `covers.ts`：`CoverEntityTypeSchema`（`story-project` / `story-world` / `activity`）、`SetEntityCoverSchema`（`artifactId: string | null`，**null 为显式移除，字段不可省略**）、`EntityCoverSchema`、`CoverUploadResponseSchema`，以及 `COVER_IMAGE_CONTENT_TYPES`（PNG / JPEG / WebP / GIF / AVIF）与 `COVER_IMAGE_MAX_BYTES`（12 MiB，与创作中心上传一致）。
- `StoryProjectSchema`、`ActivitySchema`（`index.ts` 与 `activities.ts` 两处）、`StoryWorldSchema` 新增可选 `coverArtifactId: string | null`。只存中心媒体（artifacts）ID，不存 URL；前端用 `coverImageUrl()` 拼媒体库代理地址。
- `StoryWorldSchema` 的封面是实体元数据，不属于 `WorldDefinition`。新增 `STORY_WORLD_METADATA_KEYS`，服务端 `definitionOf`、`source-updates` 与前端 `definitionFromWorld` 统一用它剔除，保存世界时封面不会混进 definition。
- `RecentWorkResponseSchema` 条目新增可选 `imageArtifactId`：作品 / 项目 / 制作取封面，角色取头像（无头像取立绘），笔记为 null。

### 2.2 服务端（`apps/service`）

- 新增 `covers.ts`：
  - `POST /api/v1/admin/covers/uploads`：沿用 `streamUploadArtifact`，归属新的中心媒体应用 `entity-covers`（媒体库显示为「作品封面」，存储策略 keep）；非图片 415，超过 12 MiB 413。
  - `GET / PUT /api/v1/admin/covers/:entityType/:entityId`：校验实体存在（404）、媒体存在（404）、文件就绪（422）、类型为图片（422）、大小（422）。设置在同一事务内替换 `artifact_references`（`ref_type='entity-cover'`、`ref_id='<type>:<id>'`），因此被引用的封面媒体不能被普通删除；清除封面只删引用，媒体文件保留在媒体库。
- 三个 store 的读取映射带出 `coverArtifactId`；`sw_worlds.data_json` 写入前去掉封面（`persistedWorld`），封面只存在列里。
- `workspace/recent` 联合查询带出 `imageArtifactId`。

### 2.3 数据库迁移 68 `entity-covers`

- `story_projects`、`sw_worlds`、`activities` 各加可空列 `cover_artifact_id TEXT REFERENCES artifacts(id) ON DELETE SET NULL`。只加列，不改已有数据，旧版本代码读取时忽略该列。
- 三个 `AFTER DELETE` 触发器：实体删除时清掉对应封面引用，避免媒体库残留指向已删除实体的引用。
- 验证（只用临时数据库，未触碰 `data/` 与正式库）：
  - `database.test.ts` 新增用例：迁到 67 → 写入三类旧数据 → 迁到最新，逐列比对旧值不变、封面为 null、触发器存在、`integrity_check` 为 ok、`foreign_key_check` 为空；
  - 另有 3 个既有升级测试（v47 活动、v54 项目、v58 世界）原本整行比较，已改为显式期望新列为 null，其余字段原样保留。

### 2.4 正式库何时迁移与备份步骤

正式库会在**下次部署或重启服务**时自动执行迁移 68（服务启动即迁移）。迁移前按 `db-migration-backup` 执行：

```bash
npm run db:check          # 只读：确认当前版本为 67
npm run db:backup         # 一致快照 + media-manifest.json
npm run db:integrity      # 只读：PRAGMA integrity_check
# 部署 / 重启服务，迁移 68 自动执行
npm run db:check          # 确认版本为 68
npm run db:integrity
```

需要连媒体一起保底时改用 `node --import tsx scripts/portable-backup.ts backup` 并 `verify`。迁移只加可空列与触发器，回退时用备份恢复即可，不需要反向迁移。

## 3. 前端

- `app/components/ui/entity-art-model.ts`（纯模型）+ `entity-art.tsx`：FNV-1a 哈希派生纹样族（弧线 / 条带 / 点阵 / 波纹）、角度、中心、疏密与色相；颜色全部来自 `[data-tone]`；支持 `avatar` 1:1、`portrait` 3:4、`cover` 16:10。`EntityImage` 统一面板圆角、1px 发丝边、懒加载、加载中同尺寸 Skeleton，缺图或加载失败回落到 `EntityArt`。样式在 `app/styles/entity-art.css`。
- `app/features/covers/`：`api.ts`（上传、读取、设置、`coverImageUrl`、本地预校验）、`query-keys.ts`、`components/cover-field.tsx`。`CoverField` 用共享 `Dialog` / `Input` / `Button` / `EmptyState`，没有新的野生弹窗；写入后由所属模块的 `onChanged` 失效自己的查询，原有查询键不变。
- 接入位置：创作项目详情（`DetailLayout` 的 `media` 槽）、作品首页导语条、制作项目「活动全局设置 → 基本资料」。
- `DetailLayout` 新增 `navigation`、`status` 透传；`ReaderLayout` 新增 `embedded`（只约束 44rem 阅读栏宽度，不套页面容器）。`.reader-prose`：衬线、`max(16px, --text-reading)`、行高 1.8、段距 0.6em、最大 40em。实测故事阅读正文 16px / 28.8px / Newsreader，桌面宽 640px（40em），手机铺满栏宽。
- 阅读视图（`world-reader`、`world-image-reader`、`world-event-detail`、`badges`、`world-branch-comparison`）：小于 12px 的字号与任意像素值清零，`font-bold` 改 `font-semibold`，去掉内联衬线样式。
- 画布：去掉所有 `var(--x, #hex)` 回退值；原始 rgba 改为 token 混色；节点内人物圆点放大到 20px 以容纳 12px 字；白字改 `text-fg-on-accent`。运行日志控制台新增 `--console-*` token（`theme.css`），修复暗色主题下 `bg-ink` 变浅导致文字不可读的问题。
- 去掉 3 处 `✓` / `○` 字符图标（改为文字）。
