# SthStart 前端设计重置计划

日期：2026-11-02
目标：把上一轮“换 Token、修响应式”的工作升级为真正的页面构图与交互层级重构。

## 0. 参考原则再核对

参考站把设计分成两层。第一层是工程约束：组件只负责结构和行为，颜色、圆角、阴影由语义 Token 提供；`variant`、`tone`、`size` 是独立维度；只提供必要 API；原生表单元素保留浏览器行为；焦点、加载、减少动效和对比度属于组件默认能力；Props 有完整类型。第二层是视觉取舍：以近黑、近白和灰阶为主，彩色只表达主操作、成功、警告和危险；层级优先用文字灰阶、页面/内容两层表面、1px 细线，最后才用很淡的阴影；控件约 6px、容器约 12px，圆角保持小而统一；UI 字重最高 600；触屏输入字号至少 16px。

这些原则对当前项目最重要的启示不是“再换一组主题色”，而是：

1. Token 是约束工具，不是重构成果。只改变颜色、圆角和阴影，页面仍然保留原来的卡片墙、动作密度和阅读路径，用户自然看不出变化。
2. 视觉层级必须由页面构图承担。先决定谁是内容主表面、哪些动作常驻、哪些信息同行或分组，再让 Token 统一这些选择。
3. 中性色主导意味着强调色稀缺。一个区域出现多个彩色标签、图标和按钮时，主操作就不再突出。
4. 工程原则最终要落到交互。原生语义、焦点恢复、IME 互锁、类型约束和减少动效，与版式重构同等重要。

因此本轮验收必须看到 DOM 重排后的结果：列表去卡片化、工作台内容优先、低频操作渐进暴露。仅有主题变量、圆角或间距变化，判定为未完成。

## 1. 判断标准

本轮不以“测试通过”作为设计完成标准。必须同时满足：

- 同一页面在重构前后有可见的构图差异，而不只是颜色、圆角或阴影变化。
- 每个页面区域只有一个主操作；次要操作进入菜单或上下文浮层。
- 列表不再为每一行套独立卡片；主要层级依靠留白、字号、位置和分隔线。
- 一个视口内只使用一个强调色语义，强调色只用于主操作、选中态和必要状态。
- 最多两层主要表面：纸张底色、内容表面；浮层单独作为临时层。
- UI 字重不超过 600；触屏可输入控件字号至少 16px；控件与容器圆角保持 6px / 12px 的同心关系。
- 工作台顶栏保持 48–52px；业务操作密度明显下降。
- 桌面、平板、手机无横向溢出；键盘、焦点、IME、减少动效不回退。
- 类型检查、门户测试、生产构建通过，并以实际截图人工复核。

## 2. 设计契约

DouUI 的“简洁克制、Token 驱动、无障碍、类型完善”转译为以下工程约束：

1. **信息层级先于容器**：标题、说明、内容和操作通过字号、间距、对齐形成层级；禁止用边框和阴影代替层级。
2. **单主动作**：页面顶栏或卡片操作区只保留一个实心主操作；其余操作使用文本按钮、图标按钮或溢出菜单。
3. **内容优先**：列表行使用分隔线和留白；只有独立对象、浮层或需要强调的模块才使用卡片。
4. **单强调色**：`accent` 只表示主操作、当前选择和必要状态，不承担普通图标、标签和装饰着色。
5. **统一节奏**：间距使用 4/8px 步进；UI 标题使用无衬线；长文正文才使用衬线。
6. **语义 Token**：surface、text、border、action、status 分别定义；组件不新增散落色值。
7. **原生交互**：原生 button/input/select，焦点可见，CJK 输入法互锁，Escape 恢复焦点。
8. **渐进暴露**：搜索常驻；高级筛选、批量和低频操作按需展开。

## 4. 页面样板

先完成并复核三个样板，再向其他页面推广：

1. 首页：一个明确主入口、紧凑应用分组、近期内容以行列表呈现。
2. 剧情工作台：正文成为视觉中心；顶栏只保留返回、标题、一个主操作和“更多”；资料树降低对比度。
3. 活动工作台：分镜按连续流呈现，不再每条套独立边框；角色、对白、动作、画面按固定节奏排列；导演面板在窄桌面默认收起。

## 5. 验证矩阵

- 视口：1920×1080、1440×900、1024×768、390×844。
- 页面：首页、剧情列表/详情、活动列表/详情、角色列表、图像工坊、创作笔记、叙事档案、日历、全部设置页。
- 视觉指标：可见主操作数、主要表面层数、强调色用途、列表卡片数量、顶栏高度、横向溢出。
- 交互：主题菜单、命令面板、手机导航、侧栏折叠、长文滚动、草稿保存、IME、减少动效。
- 工程：`npx tsc --noEmit`、`npm run test:portal`、`npm run build:portal`、定向 ESLint。

## 6. 模型调度规则

- 用户指定的 Gemini、GLM-5.3-Flash、magpie-wb-ds 分别承担独立页面样板。
- 实际路由：Gemini = `google-antigravity/gemini-3.8-flash`；GLM = `magpie/zcode-GLM-5.3-Flash`；magpie-wb-ds = `magpie/workbuddy-ai-deepseek-v4.1-flash`。
- 同一时刻最多三个子智能体并发；完成后关闭，释放并发额度。
- 模型名称不可用时记录接口实际错误，不静默冒充或改写模型身份。
- 主代理承担阻塞关键路径的设计契约、共享原语、冲突处理与最终验收。
