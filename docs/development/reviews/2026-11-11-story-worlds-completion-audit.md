## 3. 已有真实证据如何解释

### 3.1 文本：短时原创生活已验证，不能外推全天原作

旧六人样本累计 44 调用、16 事件、57 记忆，重开进程只补 4 调用，是预算与持久步骤恢复证据；内容却有修理自家工作台灯反复等许可、复述“不要求回应/同行”、未知性别代词漂移等问题，不能用于证明自然生活合格。

改善提示词后的六人两轮样本实际 completedTick=120，40 调用、15 事件、78 记忆、1 地点。已读实际 perspectives：送信及扶灯各有 2 视角，群体交谈/暂别各 6 视角；之后继续修灯、整理书、茶摊和盆栽，乔安开始素描。人物有具体行动与对白，较旧样本有进步；仍可见一些谨慎限定与重复清点式日常。两小时原创样本不能证明跨日作息、长途旅行、角色成长或原作语气。

### 隐私、输入和可扩展性的实际边界

个人 context 当前仅携带本人 actor/state、经来源链允许的 facts/memories/beliefs、同地点可见人物姓名外观；不携带全局来源原文、事件正文或地点 description。隐私保障因此较强，也限制了常识/环境细节可用性。猜测/误解的防泄密使用事实精确链与规范化文本包含检查，无法识别一切同义暗泄；AI 审查与人工样本仍有必要，不能将有限反例测试表述为全面语义安全证明。

角色库输入实际读取已发布 CharacterVersion，actorFromCharacterVersion 从该版本映射背景/语气/外观，测试特意让未发布 draft 与已发布版本不同并断言采用旧已发布内容。默认 referenceArtifactIds=[]，不会因为选择角色就自动继承全部参考资源。资料库来源目前只导入已有条目 excerpt，UI 明示完整原文需补入；笔记/叙事档案能转快照。因此“引用来源”已实现，但不能据此宣称每个原作人物均拥有完整准确资料。

12 人/1,000 事件 runtime 测试明确断言首轮读 1,000 行、下一轮只加 12 行，个人 memory 限 20、某角色 facts=84，两步 76 个假模型调用、总耗时<15s；模型裁定历史窗口<400。这证明该固定样本的增量 SQL 读取与输入裁剪，**不证明真实模型时延**，也不消除缓存数组 clone/sort、每人事实过滤与 commitStep 全历史校验的增长开销。通知另有 20,000 已确认步骤的 EXPLAIN QUERY PLAN 断言，使用 migration56 部分索引并每批最多 32 个结果，重启回调有持久 lease/ack，已避免每秒读全表 committed payload。

费用提示目前是固定“当前没有可用的价格配置”，没有价格读取/实际估算链。可证明未虚报费用、调用额是硬限制；不能宣称已经验证价格齐全时自动算费。
