# 话题素材库与活动点子：审查与修复记录

日期：2026-09-14

对应方案：[话题素材库与活动点子开发方案](../plans/TOPIC_LIBRARY_AND_ACTIVITY_IDEAS_IMPLEMENTATION_PLAN.md)。本次审查范围是这份方案，不是此前的活动企划升级。

## 结论

原实现已有主要模块和入口，但部分功能只配置了界面或字段，实际执行和数据衔接没有完成。本轮直接修复后，「后台定时搜集 → 素材筛选 → 生成点子 → 采用到企划 → 创建活动并保留来源」已通过代码与接口回归，达到个人使用的基本交付条件。

没有连接真实 MCP 或外部模型，没有进行人工浏览器验收。因此不以测试通过等同于真实热点检索质量、模型创意质量或所有 MCP 服务兼容性均已确认。

## 已修复的问题

### 搜集与来源准确性

- 配置的原文读取工具没有调用：补上按工具 schema 构造参数、使用搜索返回的文档定位进行读取。
- 通用检索帮助函数只返回两条结果：话题搜集改为处理完整的有限结果集，避免第三条起被无声丢弃。
- 搜集没有实际限定近期内容：关键词加入最近七天的日期范围，过滤已知过期发布时间；未知发布时间仍保持未知。
- 更新时间被当作发布时间、非法日期被归一成有效日期：不再使用 updatedAt 冒充发布时刻，并校验日期范围。
- 整轮 180 秒预算未约束在途请求：MCP 请求与整理模型请求共享整轮截止时间；达到工具预算会标明部分完成。
- 允许运行已移出允许列表的工具：执行时重新确认允许工具，自动搜集设置也检查来源及工具有效性。
- 所有来源失败仍标为部分完成：现在明确为失败，有内容保留下来的部分失败才按部分完成处理。
- 没有有效引用的模型话题被挂上前三条来源：现在拒绝无效引用，不虚构来源归属。
- 无正文时生成完整解释：保留“信息不足”说明，不把模型补写当作来源内容。

### 去重与数据保留

- 按标题前 16 个字符归并导致不同事件被吞并：取消前缀归并，自动匹配限完整标题、相同作品和近期记录；模型可在明确同一事件时引用已有话题 ID。
- 原始候选按 URL 加标题去重：改为标准化 URL，相同链接改标题也不会重复。
- URL 规范化删除可能定位内容的参数及片段：只清理明确跟踪参数，保留其他参数及 hash。
- 无 URL 的多个 MCP 文档互相覆盖：使用来源与文档定位建立内部标识，对页面仍显示文档定位而非伪造网页链接。
- 新增数量上限阻止后续已有话题补充来源：新增限额只限制新话题，合并仍可继续。
- 失败整理的原始候选、配置没有完整复用：重试沿用原任务配置，有原始候选时不重新搜索。
- 30 天清理只存在方法而未调度：在启动和调度检查中执行，不删除素材、点子及活动快照。

### 点子与活动衔接

- 不选择可选主角就无法采用点子：允许先建立未选择人物的企划草稿，随后在向导里选择；详细生成仍要求至少一位参与者。
- 同一点子重复点击创建多个会话：复用已建立的对应会话；指定不存在的会话会明确报错。
- 在已有活动内生成点子时未带主角和要求：选择器接收已有主角、活动类型及要求。
- 重复采用或更换点子不断叠加冲突要求：替换之前自动附加的灵感段落，同时保留原有用户要求。
- 推荐人物仅存在提示词里，无法进入待补人设：接入已有可选候选流程，移除后不会自动重新加入。
- 来源链接和原文未冻结：点子生成时保存来源快照，采用时保存点子、推荐人物、初步阶段及来源；正式活动读取对应生成依据。
- 追加到第 12 个之后的新点子被截掉：取消静默截断，保留已有候选，并把历史点子带入后续生成提示。
- 历史批次追加依赖当前素材勾选：追加改用该批次自己的冻结素材。
- 不同请求被返回同一个正在运行的批次：明确提示等待，避免把另一场活动的点子误当成本次结果。
- 活动中没有“灵感来源”展示：增加可展开的素材摘要、来源链接和摘录。

### 页面表现

- 修复“不限时间”仍实际查最近 30 天、收藏视图时间控件与实际结果不一致。
- 两处选择入口复用作品多选和跨页选择逻辑；切换页面仍能看到已选标题并移除素材。
- 补齐向导选择器的类型和时间筛选。
- 搜集完成后主动刷新素材和下次执行时间，避免任务很快完成时漏刷。
- 增加最近成功时间及中文任务状态，运行中禁用重复生成按钮。
- 采用成功后关闭确认弹窗；点子工作区内显示接口错误。

## 使用边界

- 搜集需要后端持续运行；电脑关机期间不会执行，恢复后补采近期内容。
- 资料源必须本身能查询近期网页或社区信息。代码不能让纯剧情库凭空提供新梗；特殊 MCP 返回格式仍可能需要适配。
- 发布时间缺失不等于近期发布。页面保留未知状态，需结合来源内容判断。
- 同一事件的语义归并、多份点子的实际差异和原作设定准确性仍依赖真实模型，适合在预览时人工确认。
- 本轮采用内存数据库与可控 MCP/模型响应验证，没有修改个人实际素材数据，也没有提交或推送 GitHub。
