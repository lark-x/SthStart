## 2. UI token 守门（`check:ui`）

- 新增 `scripts/ui/check-tokens.mjs`，扫描 `app/shell`、`app/workspaces`、`app/features`、`app/apps`、`app/settings` 下的 `.ts` / `.tsx`，跳过测试文件和以 `//`、`*` 开头的注释行。
- 检查 6 类问题：原生色板、6 位 hex、小于 12px 的字号、超过 600 的字重、间距 / 尺寸 / 圆角的任意 px 值、字符图标与表情符号。
- 采用棘轮：`scripts/ui/baseline.json` 按文件、按类别记录存量，只允许减少；基线里没有的新文件必须为 0。超标时列出文件、行号和匹配内容。
- 读不了的文件单独报错，退出码 2，不按 0 处计。`--update` 只能在数量下降后收紧基线；有任何一项超标时拒绝执行。
- 新增 npm 脚本：`check:ui`、`test:ui-check`。`ci:core` 改为 `check:architecture → check:ui → typecheck → …`。
- `sthstart-ui-system` §1 / §6 和 `project-verifier` 已把 `check:ui` 改成"已落地"，并写明运行方式。

首次建立的基线（626 个文件，其中 116 个有存量）：

| 类别 | 数量 |
| --- | --- |
| Tailwind 原生色板类 | 563 |
| 6 位 hex 颜色 | 156 |
| 小于 12px 的字号 | 205 |
| 超过 600 的字重 | 67 |
| 任意像素值（间距、尺寸、圆角） | 86 |
| 字符图标或表情符号 | 7 |

和计划 §2.2 的粗扫数字有出入，原因有三：扫描范围多了 `app/apps`、`app/settings`；注释行不计；任意像素值只算间距、尺寸和圆角，`text-[13px]`、`leading-[…]` 不算。计划里的 `mcp-source-manager.tsx` 当时读不了，只是 Quick 沙箱的权限限制，Node 可以正常读取，本次已计入。

## 3. 无障碍扫描（axe）

- 以 devDependency 安装 `@axe-core/playwright` 4.14.0。
- 新增 `tests/e2e/a11y-routes.spec.ts`：沿用路由矩阵的造数据方式和隔离上下文，在 1440 宽下用 WCAG 2.1 A/AA 规则扫描 22 个主路由，暖白与暖夜各跑一遍。serious / critical 必须为 0。没有关闭任何规则或排除任何区域，`KNOWN_ISSUES` 为空。
- 首轮发现 serious / critical 共 11 处，均已修复：

| 规则 | 位置 | 处理 |
| --- | --- | --- |
| `label-content-name-mismatch` | 共享分页的"每页条数"按钮（8 个列表路由）：可见文字「每页 20 条」不在读屏名称里 | 读屏名称改为「每页 20 条，更改每页条数」；同步更新分页单测和 `pagination.spec.ts` |
| `label-content-name-mismatch` | 角色库「更多筛选」按钮，读屏名称是「筛选与排序」 | 去掉 `aria-label`，读屏名称就是可见文字，已启用条件数仍由 `aria-describedby` 说明；6 个 e2e 文件里的定位同步改名 |
| `label-content-name-mismatch` | 首页四个模块卡：读屏名称只有标题，统计和简介是可见文字 | 标题、简介在 DOM 中排前，CSS 用 `order: -1` 把头部（图标与统计）放回最上，视觉不变；去掉 `aria-labelledby` / `aria-describedby`，读屏名称仍以模块名开头 |
| `label-content-name-mismatch` | 日历日期格：读屏名称「2026-11-01，0 项事件」不含可见的日期数字和事件标题 | 读屏名称先复述格内可见文字（日期、前 3 个事件、溢出提示），再补完整日期和事件数，例如「13 苏禾生日，2026-11-13，共 3 项事件」；新增 `data-date` 供测试定位；同步更新 `calendar.spec.ts`、`mantine-world-calendar.spec.ts` |
| `button-name`（critical） | 日历月初月末的补位格是没有文字的禁用按钮 | 改为 `aria-hidden` 的 `div`，外观不变（见 `after/light-paper-1440-calendar.png`） |

- 复扫结果：两套主题都是 0 处 serious / critical。
- 已知限制：手机宽度下日期格只显示日期和圆点，读屏名称里多出事件标题，axe 的 label-in-name 规则在窄屏可能仍会提示。本轮只扫 1440 宽。

- `tests/e2e/visual.spec.ts` 新增 15 个用例：

  - 首页暖夜一张（暖白已有）。
  
  连同原有 7 张，共 22 张 win32 基线。
- 页面原型用例回放 `tests/e2e/visual-fixtures/*.har` 里录好的 `/api/admin/*` 响应，页面时钟固定在录制时刻；录制前清掉请求头和 Cookie，不把测试会话写进仓库。接口变化后，先用 `STHSTART_VISUAL_RECORD=1` 重录，再更新截图（`frontend-visual-qa` 已写明步骤）。

- 稳定性：把基线和会持续写库的 axe 用例一起跑，24 项通过，截图不受共享测试库变化影响。
- **darwin 基线待补**：需要在 macOS 上运行 `npx playwright test tests/e2e/visual.spec.ts --update-snapshots`。
