# 前端升级后的接口与保存流程调整

## 修复范围

- 角色批量标签变化也推进 `draft_revision`；仅修改收藏、分组等不被档案保存覆盖的组织字段时维持原行为。
- 角色编辑器保留编辑基准与草稿快照。刷新头像或详情不重置未保存输入，保存期间新增修改也不被保存响应覆盖。冲突时可先在本机会话保留完整 JSON 草稿，再载入最新版；备份可下载。
- 笔记 PUT 增加共享 `NoteWriteRequestSchema`。新客户端发送 `expectedRevision`，也接受旧完整载荷携带的 `revision`；0 表示仅创建。更新已有笔记且缺少版本号返回 428，版本不符或原笔记已删除返回 409。检查、写入、资源关联和知识标记更新在同一事务内完成。
- 笔记内容完全相同且未请求修改知识元数据时，允许重复请求确认已完成的写入，不再次递增版本号。原有知识元数据的缺省保留及显式 null 清空规则保持。
- 笔记冲突进入独立本地状态，自动和手动重试都不会覆盖远端。继续编辑仍保存在本机。用户可保留独立副本后采用远端版本；笔记托管图片先复制到本机，避免原笔记删除后副本失去图片。复制失败时不替换原草稿。
- 已有笔记的离线正文同步不写回旧知识对象，知识元数据继续通过专门接口保存。
- 增加 `GET /api/v1/admin/workspace/recent?limit=10`，使用共享响应契约，仅返回活动、笔记和角色的 ID、标题、种类与更新时间。统一按更新时间排序，过滤已归档内容，limit 范围 1–50；沿用管理接口鉴权。
- 首页合并轻量摘要与本机待同步/冲突笔记，排除本机待删除笔记，读取失败时保留缓存并提供重试。
- 画风选项与原始描述分开保存，仅在准备提示词时组合。取消画风、切换默认和草稿恢复均保持一致；手动最终提示词期间暂停画风按钮，避免改写手动内容。

没有数据库结构变更或数据迁移。旧版客户端更新已有笔记时必须携带读取响应中的 `revision`，否则会收到明确的 428，避免无条件覆盖。
