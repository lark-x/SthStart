# 活动工作区流程精简

## 问题依据

对照用户提供的活动页截图，主要问题不是功能缺失，而是三个生成入口同时出现、阶段信息重复、无任务时仍显示零计数，以及过早显示 `not_configured` 等无法直接操作的技术提示。版本、模板与导出操作占据与主任务相同的视觉层级。

## 已实现

- 首屏变为一个明确的“下一步”区域，按当前草稿提示完善设定、生成内容、检查候选、可选配图或预览。
- 删除重复的阶段总览卡片，不再把已有手写草稿误报为没有内容。
- 无待处理内容时不显示提示按钮；历史处理仍可从“更多操作”进入。
- 生图尚未配置不再阻碍写内容；配图阶段提供中文说明、配置入口以及跳过配图的选项。
- 版本回溯、导出、预设及手动保存版本归入“更多操作”。
- 进入素材、回放或导出之前，先保存最新草稿；与当前版本不同时自动准备新版本，无变化时复用原版本。
- 生成窗口默认只需选择整场或单个阶段、填写可选要求。邀请、祝福、局部重写、重新规划仍保留在折叠选项中。
- 阶段范围默认全选未锁定阶段，只有调整范围时才展开；已有阶段时不默认要求重新规划。
- 当前阶段补写使用明确的阶段 ID；整场入口与阶段补写入口的作用分开。
- 设定页默认展示活动基本信息、参与者和阶段安排。创作偏好及模板归入可选高级区域，阶段按需展开。
- 移除空记录的零计数，缩短空白区域；手机上的四个模式入口保持一行，子分类不再被截断。

## 未删除的能力

手工编辑、角色本场设定、阶段保护、全部生成模式、候选逐条比较与采用、变更复核、回放、导出和模板管理继续保留。没有新增数据库结构、前端框架或后台配置平台。

## 验证

- `npm run typecheck`：通过。
- `npm run build`：通过。
- `npm run test:portal`：13/13，通过。
- 活动、变更复核和精简流程专项页面回归：10/10，通过，无跳过。
- 在独立 E2E 数据库验证：编辑后进入回放会使用新内容，重复进入不再创建版本。
- 候选部分采用后刷新恢复、套用配置预览、版本回溯、导出入口、实际媒体预览等保留能力均有回归覆盖。
- 查看了 1440px 桌面与 390px 手机的最终页面截图，检查主次层级、入口可见性和横向溢出。
- `git diff --check`：通过，只有 Windows 换行转换提示。

页面测试使用独立服务端口及测试库，未调用真实 AI 生成服务或消费模型额度。为通过现有工程编译，补装了锁文件中已声明但本机缺失的依赖；未改依赖版本或锁文件。
