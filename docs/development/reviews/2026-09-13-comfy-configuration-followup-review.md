# ComfyUI 配置工作台开发复核

日期：2026-09-13

## 结论

对照 `docs/development/plans/COMFYUI_CONFIGURATION_WORKSPACE_DEVELOPMENT_PLAN.md`，当前实现已具备主要业务链路，不需要推倒重做。但原实现存在自动保存、运行结果刷新、参数校验和版本引用方面的真实问题，不能仅凭页面齐全判定开发完成。

本轮直接修复已确认的问题，保留现有框架、数据库迁移和直连/Worker 架构。没有修改实际 ComfyUI 安装、下载模型、部署服务或操作生产数据。现有未提交修改均保留。

建议状态：**核心功能进入联调验收，尚非完整计划的最终验收通过。** 不用缺乏依据的百分比代替功能验收。

## 本轮修复

### 1. 草稿自动保存和冲突恢复

- 修复第一次单独编辑时，定时保存读取旧状态而不执行的问题。
- 串行保存；保存期间继续输入不会被旧响应标记为已保存，新内容继续写入。
- 切换工作流前先完成当前保存；失败或冲突时不切换。
- 忽略过期草稿加载响应，清理保存定时器。
- 修复 HTTP 409 被通用 API 层抛出后，冲突处理分支无法进入的问题。
- 采用服务器草稿时同步 revision，下一次编辑可以正常保存。
- 保存、失败和冲突状态不再被统一的“未保存”覆盖；浏览器离开时对未保存内容给出原生提醒。
- 保存版本使用完成保存后的草稿快照，避免捕获旧编辑内容。

涉及：`workflow-workspace.tsx`、`generation/api.ts`。

### 2. 试运行参数和状态

- 请求只发送用户显式编辑的常用参数，避免旧模型、旧默认值、固定字段反向覆盖新版本。
- 移除重复的种子输入；布尔字段使用布尔控件。
- 默认值显示随草稿更新；移除已从草稿删除的参数/媒体槽位覆盖值。
- 选中任务即使已从运行中变为成功/失败，仍读取最终详情。
- 重新打开运行中的历史记录可继续轮询；没有活动任务时停止轮询；避免轮询自身重叠。
- 相同请求在响应不确定后的重试复用幂等键；收到明确创建结果后下次操作使用新键。

涉及：`test-run-panel.tsx`。

### 3. 参数、模型和预设服务端校验

- 按 ComfyUI `input.required` / `input.optional` 与组合枚举结构读取元数据。
- `type: string` 配合 `enum` 同样校验，不再仅对 `type: enum` 生效。
- 校验步长及整数安全范围，包含浮点步长误差容忍。
- 严格合并通道检查工作流默认值，不只是校验本次输入。
- 模型允许列表在共享严格合并通道生效，不只在试运行路由检查。
- 模型成套锁定/禁止单独切换时，拒绝本次请求替换成另一模型；允许重复携带相同模型值。
- 更新预设时检查连接类型；更换版本时，即使未提交 values 也重新校验保留值。
- 禁用默认预设与解除默认引用放入同一事务。

涉及：`generation/configuration.ts`、`generation/configuration-store.ts`。

### 4. 工作流和预设版本一致性

- 从历史试运行另存预设传递真实 workflowVersion，不猜测为最新版本。
- 预设参数编辑器按选定版本展示字段；另存时排除固定字段、种子和该版本未声明的输入。
- 同一工作流重复执行“另存预设”可重新打开编辑器。
- 恢复配置包时不注入自动分析的新默认值、不替换原自定义绑定。
- 配置包字段不再经过原生导入候选键过滤；界面明确说明包内预设尚未自动恢复。
- 原生导入中手动勾选未知字段时创建对应 schema 和绑定；取消 LoRA 相关字段后移除失效槽位引用。

涉及：`preset-panel.tsx`、`generation-settings.tsx`、`workflow-import-dialog.tsx`。

### 5. 布局和编译

- 工作台外层改用已有宽页面容器，不再受普通设置页窄宽度限制。
- 三栏依据工作区实际可用宽度，而不是单纯依据浏览器宽度。
- 非三栏时使用抽屉，不同时挂载隐藏的常驻试运行面板。
- 遵循项目 Sites 规范，沿用既有布局原语和设计变量，未引入新框架或视觉体系。
- 对活动生成校验中的两处 TypeScript 收窄问题做最小修正，保留原有归一化逻辑。

## 尚未关闭的验收项

这些是剩余工作，不包含在“已修复”中，也不应在计划里勾成完成。

### P1：真实 Windows ComfyUI 联调

在用户实际运行的 ComfyUI 上验证：连接、节点清单、模型相对路径、切换两个允许模型、文生图、上传参考图并图生图、产物获取、重启后历史查询。确认工作流所需自定义节点已安装。

验收证据必须包含实际任务 ID、工作流版本、seed、模型路径及图片产物。仅用模拟 HTTP 测试不能替代。

### P1：模型库存一致性

当前共享严格通道已检查配置允许列表，但实时库存仍主要依赖发现缓存/局部路由检查。需要统一“库存不可读取”和“成功读取但确实为空”的语义，并按连接与模型类别检查；缓存过期时刷新再确认，不将空数组直接当成通过。

还应对所有调用入口分别证明 V2 严格校验生效；现有内部/兼容入口保留宽松模式，不能宣称所有调用都强制严格校验。

### P2：导出包中预设恢复

目前明确只恢复工作流草稿。若继续完成原计划，建议在导入确认中增加“同时恢复预设”，重绑定目标连接与新工作流版本，默认不开放用途，失败事务回滚。不能直接沿用来源机器的连接 ID 或默认用途关系。

### P2：复杂输入与草稿恢复边界

- 创作中心图片表单仍主要围绕单张参考图；多图片槽位和自定义槽位要与契约逐项验收。
- 服务端已保存草稿可以恢复；网络失败期间的未保存输入还没有本地持久化备份。浏览器离开提醒不等于站内导航、崩溃恢复保证。
- 跨页面重新打开后“相同内容不重复发布”的判断目前主要依赖页面内缓存，应进一步与已发布版本做稳定内容比较。

## 后续建议

继续完善当前实现，不另建一套配置平台。优先完成真实 ComfyUI 联调和库存校验，再补配置包预设恢复与极端草稿恢复；无需为此引入新的前端框架、Windows 模型管理服务或模型下载平台。
