# 活动企划升级审查与修复

日期：2026-09-14

## 范围与结论

本次审查的是「活动意图 → MCP 研究人物与地点 → 候选选择 → 多方案对比 → 补齐人设 → 创建活动」升级，不涉及话题素材库、定时搜集热点的后续计划，也没有改动邻舍。

结论：主要模块已经实现，原实现存在数处影响实际闭环的问题。本轮修复后，代码与接口回归达到个人使用的基本交付条件；真实 MCP 服务、真实模型输出质量，以及浏览器中的实际操作体验尚未在本轮联调验证，因此不以“全部功能百分之百验收”描述。

## 本轮修复的主要问题

1. **通用 MCP 请求不符合工具定义**：原先统一发送 query/keyword/q，且把搜索关键词当作原文 ID。现在保留完整 inputSchema，按实际字段构造并校验参数，读取使用搜索返回的条目 ID。陌生必填字段才由模型补充，并再次校验。
2. **MCP 超时信号复用**：原实现给整个客户端实例绑定一次倒计时，后续调用可能一开始就超时。改为逐请求设置超时，同时保留研究任务的总体时间预算。
3. **资料引用失真**：不再把前几条证据统一分配给所有人物和地点。候选只保留模型明确引用且实际存在的 evidenceId；没有有效引用时标记为创作建议。
4. **作品与人设匹配不准确**：研究作品从主角人设获取，虚空终端转换 gi/hsr/bh3；跨作品问题携带各自作品。匹配本地角色时结合所属作品、名称和别名，避免宽泛匹配被当成唯一匹配。
5. **用户约束仅靠提示词**：实际校验必选人物的分工和阶段参与、锁定主要地点、必选地点以及排除地点；校验失败的方案不进入可采用结果。
6. **取消、重试和部分成功衔接缺失**：取消后迟到响应不能覆盖状态或继续写入方案；成功方案逐份保存。重试沿用原始角色、研究依据、约束和方案数量，页面增加原样重试入口。
7. **表单更新破坏角色引用**：同一人物保留会话 actor ID，角色快照引用同步更新；先验证再事务保存，非法角色不会留下半更新的表单。
8. **选中方案受到其他方案阻塞**：确认页只展示所选方案使用的待补人设，创建时允许移除未采用方案的建议人物；仍校验保留人物的冻结人设与阶段引用。
9. **跳过检索仍使用旧资料**：清除关联的研究修订、候选选择及旧研究人物，使跳过检索的选择实际生效。
10. **历史依据随后续编辑变化**：研究修订保存结果快照，每份方案独立保存生成时的依据；后续修改选择或重试不会把旧方案的来源替换成新资料。
11. **页面刷新与局部重生成不完整**：恢复进行中的任务轮询，恢复最近任务状态；局部重生成包含所选方案正文，确认的编辑草稿在当前浏览器保留。

## 使用边界与后续建议

- 本轮接口测试使用可控的 MCP 和模型响应，没有访问用户真实资料源，也没有人工浏览器验收。下一步适合使用一个真实主角、一个真实资料源，完整试一次研究到创建。
- 通用接入使用 HTTP Streamable MCP。某个服务若使用特殊返回结构、纯文字条目或特殊读取参数，仍可能需要小型适配器；这不等于所有 MCP 都可零配置接入。
- 有引用不等于模型判断一定正确。人物关系、剧情时间线和创意质量仍适合在候选/方案预览时人工确认；多方案差异化也需要结合真实模型效果观察。
- 简版人设基于已保存资料和用户确认，未覆盖的性格、经历、外观不强行填满。移除人物后，阶段中的自然语言描述仍需用户检查，不自动改写故事文本。
- 编辑草稿恢复限当前浏览器；服务端保存原始方案与生成历史。跨设备同步手工编辑稿可以后续再做，不作为个人使用的首版阻塞项。
- 取消阻止继续采用响应与写入结果，不保证远端模型服务立即停止计费。

本轮保留了接手时的未提交实现及其他计划文档，没有创建提交或推送 GitHub。
