# 来源与执行范围

来源：聊天「全面重构前端设计」最后实施计划，2026-11-10。该聊天末次暂不执行；当前聊天的活动目标已重新授权完整实施。以下保留计划原文，实施证据另记。

**SthStart「故事世界」扩展计划**

把现有创作能力扩展成一个**可以持续演化、分支推演，并以图文阅读的角色世界**：角色根据自己的背景、目标、经历和掌握的信息行动；同一个事件可以影响多个人，也可以进入不同故事。

首版按已确认的方向建设：**共享世界、6–12 名主要角色、少量地点、有额度的后台模拟、导演视角、人物交织的时间长卷**。同时支持尊重原作与改编分支，并显示明确标签。

**一、产品结构与核心体验**

整个模块采用以下层级，避免继续增加意义重复的功能入口：

| 层级 | 管理什么 | 与现有模块的关系 |
|---|---|---|
| 故事世界 | 世界背景、原作资料、地点、人物身份、时间规则 | 引用角色库和资料库 |
| 世界分支 | 起点、原作约束、独立经历、当前时间和模拟状态 | 同一世界可有多个不同走向 |
| 人物与故事线 | 人物生活轨迹，以及围绕一个主题形成的故事 | 多条故事共享同一分支的事件 |
| 事件与场景 | 谁在何时何地做了什么、造成什么影响 | 作为正文、人物记忆和配图的共同依据 |
| 创作项目 | 从世界经历中整理出的章节、场景和制作版本 | 沿用现有写作与制作模块 |

新增一个“故事世界”入口。角色库继续维护可复用的人物基础资料，资料库维护来源，创作项目负责整理成作品。世界中的经历不会直接覆盖全局角色卡。

完整使用流程：

1. 创建世界，选择资料来源、角色、地点和故事起点。
2. 创建分支，选择“原作留白”“原作改编”或“平行世界”，设置创作方向与禁止改动的设定。
3. 设定本次推进范围和调用额度，启动后台模拟。
4. 在故事流中观察人物的独立行动、相遇和后续影响；也可以切换到连续阅读。
5. 作为导演插入事件、调整未来目标，或从历史节点创建另一条分支。
6. 把喜欢的故事整理进现有创作项目，继续编辑、配图和制作。

“原作留白”也明确属于同人创作。资料另外标注“原作有据／作者设定／AI 创作／待核实”，避免把创作内容误认为官方剧情。

**二、故事流与图文阅读**

主视图采用你选定的**人物交织时间长卷**：

- 时间从左向右展开，人物拥有稳定的轨迹和身份标记。
- 多人在同一场景相遇时，轨迹汇入共享事件；离开后分别延续。
- 缩小时看一天内的活动和交叉点，放大后查看事件、对白和配图。
- 不同故事引用同一事件，不复制出相互矛盾的版本。
- 默认只展示选中分支；分支比较使用并排视图，避免所有分支混成一团。
- 无事发生的时段可以折叠，但保留实际时间与间隔标记。布局位置不允许直接改变事件时间。

桌面工作台划分为三个区域：左侧是人物、故事线和时间筛选；中央是时间长卷；右侧在选中事件时打开详情。运行状态、剩余额度和暂停入口放在紧凑顶栏。沿用现有皮肤、主题色、选中态和分栏规范。

提供三种相互联动的查看方式：

| 查看方式 | 主要用途 |
|---|---|
| 故事流 | 看人物在什么时候相遇、哪些故事产生交叉 |
| 故事阅读 | 按一条故事或一个人物连续阅读，也可切换另一人的视角 |
| 图像叙事 | 按关键画面浏览事件过程，配上简短说明并可展开正文 |

配图围绕**场景建立、关键行动、结果变化**组织。每幅图必须对应具体事件和人物状态；关键事件可拆成连续数幅画面，使读者即使不展开正文，也能大致理解发生了什么。

人物外观、服饰、地点和重要道具使用固定的参考配置。支持参考图或 LoRA 的生成路径复用现有能力；不支持的路径明确提示一致性限制。未生成、排队、失败和待重做都有独立状态，图片延迟不阻塞故事阅读。

移动端优先支持阅读、人物筛选、查看事件及暂停运行，复杂编排与分支比较以桌面端为主。

**三、AI 如何持续推进，同时保持故事可信**

采用“角色提出行动 → 环境裁定 → 记录事件 → 更新个人记忆 → 整理成故事”的循环。

- **角色基础与当前状态分开。** 背景、性格、说话方式来自角色版本和资料；地点、目标、情绪、关系变化、已知信息随分支推进。
- **角色只接收自己能知道的信息。** 角色行动请求按人物单独构造上下文，过滤其他分支、未来事件和未获知的秘密。世界裁定可以看到全局，人物不能。
- **记忆可以有偏差。** 区分亲历、听说、猜测和误解；每条记忆保留来源事件和获知时间。由此产生误会、信息差和迟来的理解。
- **日常允许平静。** 作息、工作和旅行用计划推进，重要互动再详细生成；不强迫每个时间段发生冲突，也不为每个路人调用模型。
- **支持角色库之外的人物。** 可手动加入原创人物，AI 也可按需创建有持续身份的配角。配角默认留在当前世界；成为主要角色或加入全局角色库由用户选择。
- **关系变化必须有依据。** 保存导致变化的事件，避免一次普通交谈后关系突然跳变。
- **正文围绕已发生的事件展开。** 写作步骤可以补充表达和对白，但新增会影响后续的事实必须经过事件校验，不能通过正文偷偷改变世界。

“导演干预”分两类：对未来增加目标、约束或外部事件；对过去做不同选择则创建分支。已发生的历史保留，首版支持分支创建和比较，不做自动合并。

每个分支有独立的事件记录、角色状态和记忆。从历史节点分支时，只继承该节点之前的内容。更新原作资料或角色版本时显示影响范围，由用户选择是否纳入，已有故事不会静默改写。

后台运行由服务端负责，关闭网页后仍可继续。实现以下运行边界：

- 一个分支同时只有一个推进任务；事件和人物状态在同一事务中保存。
- 每轮保存进度、模型调用记录及结果，服务重启后从已完成步骤恢复。
- 对结果不明的外部调用先核对状态，不能直接重复提交。
- 时间先后、角色位置、必要前提和锁定设定由程序校验；人物动机与原作一致性由 AI 辅助审查。
- 输出不合法时允许一次修正；仍失败则暂停该运行，保留已完成内容并显示原因。
- 人物日常、记忆摘要和已有正文可缓存复用，避免每轮重新读取整个世界。

启动一次运行，即允许 AI 在该分支和额度内自动积累事件，无须逐条接受。整理进正式创作项目时，沿用现有版本与提案机制，保护用户已经编辑的正文。

**四、复用方案与必要的技术扩展**

已经核对现有代码、相关仓库说明和许可证。以下是复用决策；这些外部实现尚未在本项目中运行验证。

| 实现 | 用途与决定 |
|---|---|
| [React Flow](https://github.com/xyflow/xyflow)，MIT | 直接用于故事流的缩放、选择、自定义节点和连线；编写符合时间与人物语义的布局，不另造画布交互底层 |
| [AI Town](https://github.com/a16z-infra/ai-town)，MIT | 参考并适配记忆按相关性、重要性、近期性排序，以及交谈后形成个人记忆的实现；记录使用的提交与许可证。其 Convex 数据库不整体引入 |
| [Concordia](https://github.com/google-deepmind/concordia)，Apache-2.0 | 采用“角色提出意图、环境裁定结果”的模拟思路；首版继续使用现有 TypeScript 服务，不增加 Python 模拟服务 |
| [iStoryline](https://istoryline.github.io/) | 参考人物聚合、减少交叉和保持轨迹稳定的可视化研究；其旧运行环境和求解器不作为项目依赖 |
| SthStart 现有能力 | 复用角色快照、虚空终端检索与导入、公共模型配置、AI 调用日志、生成任务、媒体资产、正文版本和制作模块 |

新增业务集中为一个 `story-worlds` 模块，继续使用现有 Fastify、SQLite、TypeBox 和 React Query。新增模型包含世界、分支、人物状态、事件、记忆、故事线、运行记录和配图计划；分支与模拟属于新增业务，不强塞进现有章节正文。

接口与兼容安排：

- 提供世界与分支管理、历史节点分支、人物与来源管理、运行启动／暂停／恢复、时间范围事件查询、故事阅读、配图和采纳进项目的接口。
- 写操作沿用版本校验；启动任务、保存模拟步骤和生成图片支持幂等。
- 时间使用世界内部的相对时间与显示标签，允许“某事件之后的第三天”，不编造原作没有给出的公历日期。
- 查询均限定世界、分支和时间范围，按游标分页；故事流按可见时间窗口加载，旧事件自动聚合。
- 原作来源保存引用及内容快照。运行期间使用固定版本，检索不可用时仍可基于已有资料推进，并显示资料缺口。
- 旧项目无需迁移到故事世界才能继续使用；项目可以绑定一个分支，引用其故事线与事件。采纳为章节时保留来源和版本。
- 模型调用复用现有公共模型配置，人物行动、环境裁定和叙事整理可使用同一模型，也可分别绑定；新增用途不硬绑定某一家模型。

**生图并发作为公共调度能力统一修改：**

- 增加跨连接、跨模块的生成类型分组；同类任务共享名额。
- 默认 **ComfyUI = 1、GPT Image = 1、图片总并发 = 2**。
- 故事世界、自由生成及其他使用公共生成服务的模块共同遵守限制；不同 API 地址或多个连接不能绕过同类限流。
- 在事务中领取名额，提交中和执行中均计入占用。超时但上游可能仍在执行的任务保持待核对状态，不能直接释放后继续提交。
- 每个图片任务生成一幅图；连续分镜拆成独立任务，避免通过批量参数绕过限制。
- 同类按队列调度；完成、失败和确认取消后释放名额。启动与恢复时先核对已有任务，再派发新任务。
- 复用通用生成接口接入 ComfyUI 与 GPT Image，避免照搬现有制作模块中针对特定 ComfyUI 工作流的限制。

**五、实施顺序、默认值与验收**

按四个阶段完成一个可使用的首版：

1. **世界与分支基础**：共享契约、数据库增量迁移、来源快照、人物身份、事件记录、分支和历史恢复；同时完善公共生图并发限制。
2. **持续模拟**：人物计划、记忆、环境裁定、后台运行、额度、暂停恢复、导演干预和冲突提示。
3. **故事工作台**：人物时间长卷、事件详情、多视角阅读、分支比较，以及接入现有创作项目。
4. **图像叙事与完整验收**：关键画面规划、参考配置、两类生图接入、连续图文阅读、性能优化和部署。

首版默认值如下，均在运行设置中可调整：

- 6–12 名主要角色，建议先用 3–5 个地点。
- 每次运行最多推进 24 小时故事时间，或消耗 120 次文本调用，先达到者暂停；失败后的修正调用也计入额度。
- 每次最多提交 12 幅配图，失败请求也计入已提交额度；额度不足时保留待配图节点。
- 开始前显示采用的模型、时间范围和额度。调用量是硬限制；只有配置了价格才能显示费用估算。
- 图片默认按故事节点生成，正文继续推进；视频留作后续扩展，沿用已有制作入口。

验收覆盖真实工作流程：

- 多名角色分别行动，在共享事件交叉后继续各自故事；切换视角仍引用同一事件。
- 未在场人物不会提前获知秘密；之后通过交流获知时能追溯来源。
- 同一节点创建原作留白与改编分支，后续事件、人物记忆和配图相互隔离，标签清晰。
- 关闭网页、重启服务、暂停、额度耗尽和请求超时不会重复提交已完成步骤或丢失事件。
- 混合提交故事配图与自由生成任务，实际验证 **ComfyUI ≤ 1、GPT Image ≤ 1、总并发 ≤ 2**。
- 正文和配图展示一致的角色、地点、行动及结果；人工检查连续画面能否说明事件，不能仅凭任务成功判定通过。
- 以 12 名主要角色、1,000 条事件检查时间窗口加载、筛选和画布交互；桌面完成编排，移动端完成阅读与暂停。
- 使用隔离数据库完成契约、模拟、分支、队列和浏览器测试，再以有限额度验证真实文本模型及两类生图路径。
- 完成备份、迁移检查与部署到 `localhost:9320`，检查健康状态和新功能，并回归现有角色、资料、写作与生成流程。

最终验收以“角色是否持续生活、交叉故事是否自洽、历史是否可追溯、图文是否能读懂”为标准。自动检查可以验证结构和约束，人物是否贴合原作、故事是否自然仍需要实际阅读与图像检查。
