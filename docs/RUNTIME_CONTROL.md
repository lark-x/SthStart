# 运行控制与日志服务

## 边界

公共服务是正式本地运行时唯一的邻舍进程托管者。它只会停止自己启动的进程；如果检测到端口已经由 EXE 或开发脚本占用，状态显示为“外部启动”，不会尝试结束该进程。

邻舍数据仍由邻舍维护。SthStart 保存启动器设置和选定的共用创作设置，通过邻舍现有 `/api/config` 接口应用，不直接修改邻舍数据库。

## 日志策略

- 默认 `info`，可设置全局级别并按服务覆盖。
- 运行生命周期和托管进程异常退出始终记录。
- 内存最多 2,000 条，磁盘默认保留 7 天或 200 MB。
- 单文件达到 10 MB 后滚动；写入队列拥塞时优先丢弃 Info/Debug/Trace，并累计丢弃数。
- 详细诊断与敏感正文诊断最长开启 30 分钟。
- 提示词、对话和模型响应默认不采集；诊断导出始终再次脱敏。

应用需要在令牌中取得 `logs` 能力后才能调用：

```http
POST /api/v1/logs
Authorization: Bearer <app token>
Content-Type: application/json

{"serviceId":"worker","level":"info","message":"task completed","sensitive":false}
```

应用只能以自己的身份写入日志。跨应用查询、日志策略和诊断导出均为管理员接口，只能由 Portal 的服务端代理调用。

## 配置迁移

控制中心只读取 `launcher_config.json` 生成预览；确认后把支持的字段写入 SthStart 数据库，此后不再双向同步。邻舍在线时还可导入 ComfyUI、工作流、功能、记忆与模型档案的非敏感部分。旧 API Key 不会通过邻舍接口迁移，需要在公共模型配置中重新填写。
