# 创作工作区与模块职责

SthStart 以角色与故事创作为中心。创作项目保存作者的正式内容和采用关系，资料库、角色库与媒体库提供可复用来源。工具可以独立使用，已有业务与数据继续保留。

| 入口 | 主要职责 | 与项目的连接 |
| --- | --- | --- |
| 工作台 | 继续最近工作，查看日程，快速新建 | 最近工作包含正文修改后的项目和制作版本 |
| 创作项目 | 正文、设定、登场角色、参考资料、制作和媒体 | 项目总览 /apps/projects/:id；正式内容在已有 Story 编辑器 |
| 资料库 | 笔记、灵感、搜集任务、待整理、来源连接 | 加入项目保存来源快照；点击“采用为设定”才生成正式设定 |
| 角色库 | 可复用角色档案、关系、外貌与发布版本 | 采用真实角色 ID 和已发布版本；项目调整独立保存 |
| 媒体库 | 跨业务图片、视频、音频和文件 | 加入项目建立 artifact 引用并防止保留策略误清理 |
| 自由生成 | 独立画面与视频实验 | 结果可从媒体库加入项目；项目制作在制作工作区执行 |
| 创作日历 | 生日与日程 | 继续使用原有企划入口 |
| 设置 | 模型连接、生成方案、运行诊断、调用记录、备份 | DSH 的独立连接与凭据边界保持真实 |

## 四个不同概念

- **来源作品**：原神等既有作品及其原作文本，是背景来源。
- **创作项目**：作者正在写的故事，拥有自己的正式设定与章节。
- **制作版本**：选取某些已保存章节修订后创建的制作工作区，用于镜头、对白、图像、配音等。后续改写正文不自动改动冻结来源。
- **导出成品**：在制作工作区生成的漫画、配音视频等输出。创建制作版本本身不等于已生成或导出成品。

## 典型流程

1. 新建创作项目，填写大纲与章节。
2. 从资料库或项目内资料选择器加入来源。从角色库采用已发布角色版本。
3. 在项目“参考资料”中核对内容及性质；需要写入正式设定时选择“采用为设定”，随后按创作意图修改。
4. 从“制作”选择章节创建制作版本，进入制作台。生成、审批预算和导出仍使用原有明确操作。
5. 在媒体库查看文件与原业务来源，按需加入其他项目作为引用。

## 数据与来源规则

复用 story_projects、story_documents、story_characters 和现有修订。迁移 54 只新增 project_links 与索引，不搬移或重写已有内容。

资料引用保存当时的标题、正文摘要、版本、内容哈希、性质、作者类型和引用用途。单条正文超过 12000 字符会标为节选。读取项目时检查本地来源，分别提示未变化、已更新或不可用；来源更新不自动覆盖快照或正式设定。原作、社区解读、个人设定和未确认内容不混为同一种事实。

“采用为设定”在一个事务中创建正式世界设定、修订和采用关系。重复执行返回同一正式条目。已采用的引用保留出处；普通引用可解除，解除不删除原笔记、媒体或制作。

角色采用时复制选定发布版本的正文，并保存 sourceCharacterId / sourceVersion。项目总览显示库中的新版本提示。原先没有来源的历史角色不按姓名自动冒认来源。

制作关系优先从 publication_drafts.project_id 读取。旧独立互动制作可手动关联；已从其他项目章节创建的制作不能通过关联改变来源项目。

媒体使用管理员专用列表和文件接口。底层应用隔离继续生效；加入项目只登记引用，不更改其他应用的读取权限。实体缺失显示不可用，不伪造恢复文件。

## 兼容入口

旧 /apps/story、/apps/activities、/apps/notebook、/apps/inspiration、/apps/narrative 保持可达，并可从命令面板查找。对话感想使用 /apps/story?type=reflection，继续进入原感想编辑器。邻舍保留独立子模块与数据边界。
