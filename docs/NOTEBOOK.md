# 创作笔记

创作笔记是 SthStart 内的第二个本地应用，入口为 `/apps/notebook`。第一版刻意保持精简，只实现对创作有直接帮助的能力。

## 已实现

- 六类记录：日记、灵感、随记、剧情素材、角色设定、世界资料。
- 块式编辑：文本、手机或电脑本地图片、外部链接。
- 标签、收藏、全文模糊搜索和类型筛选。
- 草稿、资料、剧情候选三个阶段。
- 角色人设与世界故事快捷书架。
- 文本、链接与图片先保存到浏览器 IndexedDB，约 300ms 内完成本机自动保存。
- 后台合并同步，同一篇笔记只保留最新待同步版本，不因 Cloudflare 延迟阻塞输入和切页。
- 新笔记使用客户端 UUID 幂等创建；同步状态区分本机已保存、正在同步、已同步、离线待同步和同步失败。
- 图片先显示本机预览，联网后以二进制流上传，不再转换为 Base64 JSON。
- 响应式布局与移动端底部插入栏。
- 同步完成后由 SQLite 和 `data/artifacts/notebook` 持久化；未同步草稿和图片暂存在当前浏览器。

## 本地优先与同步边界

- 待同步图片单张最大 8MB，当前浏览器内的待同步图片总量最大 100MB。
- 图片成功上传后会立即清理对应的本机 Blob；服务器确认后的笔记保留为最近使用缓存。
- 断网、关闭页面或切换应用不会丢失已经显示“本机已保存”的内容；恢复网络、窗口聚焦或重新打开应用后自动重试。
- 首次成功打开新版笔记后会安装本机离线应用壳；之后断网重新打开已访问的笔记路由时，编辑器可从 IndexedDB 恢复草稿。首次访问前完全断网仍无法安装应用壳。
- 手机和电脑同时编辑同一篇笔记时采用最后抵达服务器的保存覆盖。`revision` 用于避免较旧响应覆盖当前设备上更新的草稿，不提供多人协同合并。
- 浏览器站点数据被手动清除时，尚未同步的草稿和图片无法恢复；重要内容仍应等待“已同步”状态并纳入数据库备份。

## 为剧本编辑器预留的出口

`story-candidate` 是第一条数据边界：笔记被标记为“剧情候选”后，未来的剧本编辑器可以读取这些素材，但不会直接修改原笔记。后续建议按以下顺序增加：

1. 笔记之间的显式关联，例如“角色出现在世界事件中”。
2. 版本历史与误删恢复，移动编辑时尤其有用。
3. 一键复制为剧情素材快照，保留来源笔记 ID。
4. Markdown/JSON 导出，避免创作内容被某个编辑器锁定。
5. 在资料数量明显增加后，再加入反向链接和关系图；当前阶段不需要。

暂时不建议加入复杂富文本排版、表格、任务管理、协同评论和插件系统。这些功能会让手机编辑变重，却不会直接帮助日记、灵感与剧情素材的流转。
