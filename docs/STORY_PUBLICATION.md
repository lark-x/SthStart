真实主库已在另轮恢复至迁移50；业务库、叙事库完整性检查通过。原生 DSH 的 Step 模型已通过独立制作 MCP 提交六镜头方案，9320 的 Docker Service 已实际完成六张 Anima 图片、六句 `stepaudio-2.5-tts` 配音、61.34秒视频和发布ZIP。以下较早隔离验收的数字/环境限制保留为历史记录，不能作为当前部署状态。

**功能链路可用，成片视觉质量尚未通过。** 部分画面仍有上下留边，晶体特写主体过小，砂糖书写镜头的动作不符；本轮没有自动重绘，统一音色也不等于已完成角色声音设计。完整证据、问题和下一步见 `docs/development/logs/story-publication-production-acceptance-2026-10-04.md`。

剧情工作室中保存章节 → “制作作品”选择章节版本 → 制作台的“AI 协作”把制作任务交给 DSH 或其他 MCP Harness → “核对方案与额度” → 自动串行生图与逐句配音 → 审阅 → 下载发布 ZIP、视频、封面。上传平台仍由你操作。

旧活动继续使用原工作台；新作品不会改变正式剧情、旧镜头画面或旧漫画。一般先做 6 个镜头、60–90 秒小样，再扩到 12 个镜头。不做连续角色动画或图生视频。

## DSH 配对

1. 旧剧情桥接保持原配对方式。
2. 在制作台“AI 协作”生成**独立制作凭据**。它只能读本剧情项目的制作来源、编辑独立方案、执行人工批准的额度；不能接受正式剧情提案或自行批准制作。
3. 在本机 PowerShell 执行（项目 ID 替换成页面提供值）：

```powershell
.\scripts\story-dsh\start.ps1 -ProjectId <project-id> -PortalUrl http://127.0.0.1:9320 -PairPublication
```

交互输入凭据，启动器会使用当前 Windows 用户 DPAPI 加密，保存于 `%LOCALAPPDATA%\SthStart\StoryBridge\<project-id>.publication.cred`。以后不用重复 `-PairPublication`。凭据不出现在命令行、URL、模型聊天或 patch 中。生成新凭据立即使旧凭据失效，撤销后运行中的 MCP 也失去权限。切换剧情项目先退出当前 DSH 实例。

只有带有独立制作凭据的手动启动器会添加第二个 MCP。已有控制中心启动与旧 Story MCP 不自动扩大权限，也不会偷偷创建制作凭据。此流程在 Windows 用户级保证文件加密，不承诺操作系统沙箱。

## 其他 Harness

使用标准 stdio MCP，命令 `node --import tsx/esm apps/service/src/publication/mcp-server.ts`（正式构建可使用相应 dist 路径）。通过安全的进程环境注入：`STHSTART_STORY_PROJECT_ID`、`STHSTART_STORY_PORTAL_URL`、`STHSTART_PUBLICATION_BRIDGE_TOKEN`。不要把真实 Token 写进仓库文件或传给模型。

提供22个工具，保留原八工具，并补充作品/运行发现、候选图与音频历史、媒体预览、配置查询、校验/预检、局部修改、选音频、单句重试和独立导出。完整清单、接入与示例见 [Harness MCP 使用指南](HARNESS_MCP.md)。正文每次最多20,000字符，通过nextOffset继续读取。草稿先提交，管理员在网页确认后才有approval ID；查询到历史批准不代表它对当前内容仍有效。状态与额度以服务记录为准，未知结果不自动重投。

## 配音

“制作方案”中单独配置 OpenAI-compatible `/audio/speech` 服务，API 根地址例如 `https://provider.example/v1`；模型、声音 ID、声音清单由所用提供商决定，聊天模型可用不代表语音可用。

可在配音弹窗“从已配置的语音模型选择”中直接选择公共服务里的 TTS 模型，复用对应连接的加密凭据，无需再填写密钥。配音配置只保存连接 ID 和参数；实际请求前会复查连接与模型启用状态、根地址是否一致，地址变化时停止，绝不向其他地址发送原连接密钥。当前列表按模型 ID 中的 `tts` 识别，公共服务卡片的 `text` 标签不表示已经通过语音测试，不应对 TTS 做聊天能力推理测试。

独立配置仍可使用服务运行环境 `STHSTART_SPEECH_API_KEY`（可在表单指定另一个变量），或系统凭据库账号 `publication-speech:<profile-id>`。数据库不存密钥。Docker 需要显式向容器注入变量；网页保存独立配置不会自动改变容器环境。

每句独立配音，支持 WAV、MP3、M4A 手动替换。时长由 FFprobe 探测；没有配音时仍可生成漫画，视频不能成功导出。改句子只使该句音频失效；图像描述改变只使相应画面失效。修改画面英文提示词需要创作模型重新提交或在绘制设置手动编辑，服务不会根据中文描述自动改写。

### StepAudio 配置示例

在“制作方案 → 配置配音服务”中，`stepaudio-3-tts` 和 `stepaudio-2.5-tts` 分别建立配置，模型字段一次只填一个 ID。

| 字段 | 填写方式 |
| --- | --- |
| API 根地址 | 阶跃普通 API：`https://api.stepfun.com/v1`；Step Plan：`https://api.stepfun.com/step_plan/v1`；转发平台填写平台提供的兼容根地址。不要把 `/audio/speech` 再加到根地址后面，程序会追加。 |
| 模型 | `stepaudio-3-tts` 或 `stepaudio-2.5-tts`，以账户/平台实际支持为准 |
| 默认声音、声音清单 | 填写该模型可用的真实声音 ID，两处须一致；官方2.5示例使用 `cixingnansheng`。3或转发平台须核对它们自己的声音清单，不凭中文显示名猜 ID。 |
| 语速 | 先用 `1.0` |
| 密钥环境变量 | `STHSTART_SPEECH_API_KEY`，或已经安全保存并注入 Service 的专用变量名 |

[官方 TTS 接口](https://platform.stepfun.com/docs/zh/api-reference/audio/create-audio)返回音频二进制，当前项目按 MP3 接收。单次文本最多1000字符；这两个模型会将括号中的内容作为不发音指令，需读出的内容不要放在括号内。`voice_label` 不适用于2.5/3；它们支持 `instruction`，但本项目目前尚未提供独立指令字段、克隆或词级时间戳选项。

先试听一个短句，再运行整段配音。模型名称不意味着密钥、额度或根地址已配置；聊天平台提供 Step 文本模型也不意味着它提供 TTS。不要将模型密钥明文发给模型、放进 URL 或写入仓库。

2026-10-04 已使用用户的 Step Plan 连接实际验证 `stepaudio-2.5-tts`、`cixingnansheng`、语速1：六句272字符成功，导出63.77秒1080×1920视频。本次仅是隔离测试项目，未修改正式剧情或部署；`stepaudio-3-tts`、角色多音色和情绪控制没有实际测试。画面质量问题仍见真实验收报告。

## 显存、导出与恢复

默认 768×1024 关键帧、ComfyUI 串行、不自动 Hires；全局、角色、镜头 LoRA 按现有链合并。无参考图或 LoRA 时角色一致性仍依赖文本，不承诺每次一致。视频编码使用 CPU FFmpeg、2 线程，不占 ComfyUI 推理显存。

服务需要 FFmpeg/FFprobe；本地 Noto Sans SC 字体随项目分发，`@napi-rs/canvas` 需安装对应平台原生依赖。Docker 构建时用 `--build-arg INSTALL_FFMPEG=true`，普通文件同步部署不足以安装新增原生依赖。较早隔离实施没有改变容器；后续恢复与部署已补齐运行依赖，真实生产导出成功。

发布 ZIP 含漫画 PNG、封面、文案与 manifest；选视频时增加 MP4、SRT。竖屏图卡 1080×1440、视频 1080×1920，横屏 1920×1080。对白过长会拒绝导出而不是缩成不可读字体。视频最长5分钟，建议拆分长章节。

服务重启不会重复提交已关联生成任务。配音提交结果未知则保留 unknown 与已用额度；停止制作不保证上游立即取消或费用返还。本地编辑遇到后台画面更新时保留文本，显示冲突并等待手动恢复。

较早隔离验证时真实主库曾有完整性异常，后续已恢复、迁移和核验；详情见数据库恢复报告。今后仍需先核对实际库与媒体，使用项目一致快照工具备份，不能强行迁移异常库或裸拷贝活跃 `.db`。`db:backup` 备份数据库和媒体清单，不包含媒体二进制。

## 制作台工作流选择

未明确选预设、工作流或参考图时，新发布模式优先使用已启用的「邻舍对齐 · Base」预设，不修改旧活动的默认绑定。完整英文画面提示词由 Harness 写入；服务只追加已配置画风/策略及 LoRA 触发词，不二次调用文本优化模型。

制作台要求正向提示词直接绑定 `CLIPTextEncode.text`；内部再次固定拼词的旧流程会被拒绝并指出替代预设，不会暗改已发布工作流。最终模型、正负提示词和参数以「核对方案与额度」及调用日志为准。角色参考图和 LoRA 没有提供时，不承诺角色/动作必然正确。
